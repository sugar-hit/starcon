# Starcon MiniMax 开发流水线

本文件是自动开发的唯一执行协议。先读根 `AGENTS.md`，再读本文件；
`PIPELINE_CRON_PROMPT.md` 仅作入口。项目根目录用 `git rev-parse --show-toplevel`
确定，不写死个人电脑路径。历史会话记录是取证材料，不覆盖本协议。

## 目标与边界

衡量**通过验收的行为 / 模型用量 / 机器时间**，不以提交数、代码行数或标记完成数论产出。
保留现有代码，按证据局部修复；不以模型名称判断质量，不因一次失败全部重写。

本地运行参数仍来自 `.dev-agent/PIPELINE.local.md`（不入库）：并发、调度间隔、
静默时间、温度和容器阈值、用量预算。缺文件或缺参数时只做只读检查并报告缺项；
不得猜值、执行文件内 shell/eval、自动恢复暂停的定时任务或自行提高并发。
本 PR 不更改任何定时任务、生产环境、secrets、权限或付费服务。

## 任务队列：先收口，再开工

1. 每轮先看 `git status`、`lane.mjs status`、台账、最近失败的检查和开放 PR。
   用 `node tools/module-progress/sync.mjs --check` 检查派生计数；只有数字确有变化才同步写回。
2. 优先级：失败回归/安全隔离问题 → 已开工任务 → 解锁上游 → 新功能。
   检索 main、集成分支、在途分支中的表/API/页面和测试证据，避免重复实现。
3. 一个任务一个可验收行为。任务卡必须含模块 ID、基线 SHA、用户行为、输入/输出、
   排除范围、上游实际文件、主责服务、预期改动路径、验收用例、风险及迁移版本。
   大模块拆成可独立验证的任务；尚未完成整个模块时台账保持「进行中」。
4. 先做 10 分钟依赖检查。缺表、缺服务、需求不明确或已有等价实现时返回 BLOCKED
   和证据；不造第二套实现，不硬塞到错误服务。阻塞项不在下一轮无条件重试。
5. 并行仅用于无依赖且无共享写入热点的任务：独立 worktree、分支、迁移号和文件所有者。
   不同 L3 仍可能共享 `api-proxy.ts`、导航、OpenAPI 或数据库表；调度前检查路径所有权。
   同一热点一次一个 writer，其他任务排队。生成契约按后端 spec 重生成，不靠求并保证语义。

## 调度与资源

- 沿用 `lane.mjs` 的依赖/主责服务选择，不在 prompt 中再建一套选择算法。
- 运行前读本地静默窗口、温度、load 趋势、Docker/Testcontainers 存活数和模型剩余额度。
  命中本地阈值即零派发；没有额度 API 时记录「未知」，不谎报可用量。
- 先检查调度闸再 `gate acquire`；持闸期间重新读状态、预分配迁移号并登记 worker。
  `finally` 释放自己取得的闸。不要强制清理其他调度者的闸。
- `plan --lanes N` 的 N 是**本轮派发预算**，不是额外无限名额：调用前计算
  `N = max(0, 本地并发上限 - running - ready - conflict)`；优先处理待验收/冲突。
  调度器仍可能返回超时车道，派发前逐条核对总预算。预览需先 init，使用 `--dry-run`。
- 心跳超时只表示需要调查；先确认旧 worker 已停止，再重派，防止双 writer。
  worker 每 25 分钟续心跳；派发后登记真实 session ID。不要靠定时反复重读完整仓库等待结果。
- 依赖锁不变就复用本 worktree 的安装和 pnpm store；新 worktree 安装使用 frozen lockfile。
  不共享可写 node_modules、数据库或测试输出目录。
- 每轮记录任务 ID、基线/头 SHA、开始/结束、阻塞原因、修复次数、检查耗时；
  能取到的模型用量才记录。连续 3 轮无验收产出时停派并报告瓶颈，不靠加并发解决。

## 分层验证

worker 在自己 worktree 里反复跑最小相关测试；批次集成后一次全量。
仅改文档的 worker 做格式/链接检查，不启动数据库；PR CI 仍保留全套检查。
所有命令从项目根目录执行，下面的目录切换用子 shell 避免串目录。

| 层      | 执行者    | 命令与要求                                                                                                                                                                               |
| ------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L0 静态 | worker    | TS 改动：`pnpm --filter @starcon/web typecheck`（或实际受影响包）与相关 lint；Java 改动：`(cd backend && ./mvnw -B -ntp -pl services/<service> -am compile spotless:check)`，必须 JDK 21 |
| L1 行为 | worker    | Java：`(cd backend && ./mvnw -B -ntp -pl services/<service> -am test)`；TS：`pnpm exec vitest run <实际相关测试路径>`；共享库变更需扩大到消费者                                          |
| L2 集成 | 调度者/CI | 针对集成后的同一内容快照，执行下面完整检查；契约/UI 变更还需生成差异与浏览器验收                                                                                                         |

L2 从根目录执行（顺序运行，避免本地同时启动多套 PostgreSQL）：

```bash
(cd backend && ./mvnw -B -ntp spotless:check verify)
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm test:codegen
pnpm test:workflow
NEXT_TELEMETRY_DISABLED=1 pnpm build
node tools/module-progress/sync.mjs --check
```

- 以上任何一步失败即停止交付；执行器必须检查每个退出码，不可只用最后一条的结果。
- 本地 L2 已有同一 tree SHA 的通过证据且没有后续内容变化，就复用证据；PR CI 是独立验收。
  不要求每个 worker 再跑一遍全量，也不靠跳过 CI 节省用量。
- CI 中 lint/typecheck/unit 并行，build 和浏览器检查等轻量检查通过后开始；
  Java 格式先于真实 PostgreSQL 测试。pnpm/Maven 下载缓存沿用，Turbo 缓存覆盖完整包输入及共享配置。
  不缓存数据库、测试成功标志或 Maven target；不复用未验证测试结果。
- 迁移必须审阅本批 diff：历史数据回填、NOT NULL/default、CHECK、RLS、旧 INSERT 兼容性、版本撞号。
  grep 只能提示风险，不能证明正确；真实数据库回归才是依据。
- 新 API 要验证真实 proxy 的放行与拒绝、权限、租户隔离；禁止只测自写正则来代替端到端路径。
  CI 的 catalog 浏览器测试只是现有基线，新页面仍需自己的验收用例。

## 失败反馈与 Bugfix

1. 记录第一个失败命令、退出码、对应 SHA、测试名、期望/实际与最小必要日志。
   测试数据必须脱敏；不上传 .env、生产日志、凭据或全量请求。
2. Bugfix 先加能在修复前失败的回归测试，修复后证明通过；再跑受影响模块。
   租户隔离、伪造 header、连接池串租户、金额精度、库存并发/幂等、时区与数据库精度按影响面覆盖。
3. 只重跑失败 job/用例用于定位。没有代码变化且没有基础设施瞬时故障证据，不重复全量重试。
   同一错误两次修复无进展时，提交精简诊断交接给更强模型/人工，不继续扩大改动。
4. L2 红则冻结该批新功能，按实际 diff 和依赖定位；必要时在一次性 worktree 检查前序集成快照。
   交互性故障不满足二分的单调性，不能承诺“四车道两次定位”。修复后重新验证最终快照。
5. 不关闭失败测试、不加吞异常、不手改生成物、不用全表重格式化掩盖问题。

## 落地、PR 与验收

- worker commit 后调用 `land` 只表示**待验收**。报告真实命令/退出码/测试数与 SHA，
  没跑就写未验证；`land` 本身不执行测试，也不意味着已交付。
- 调度者先记录批次基线，再用 `merge-ready` 串行集成少量任务（最多本地并发上限），
  检查共享热点与生成契约语义。不要把数十个分支攒成一次大合并。
- L2 通过后提交必要的会话摘要，通过新分支 PR 交付 main；保持集成分支的现有用途，
  但不直接 push main、不自动合 PR、不改写其他人的历史。不要为写说明 amend 已验证提交。
- 台账「已交付」须有代码路径、测试证据、验收快照/PR；未验证抢救提交不得算交付。
  不批量重写历史台账来虚增进度。
- PR 必须填写模板：范围/排除、依赖、验收行为、迁移/契约、回归、实际验证结果、风险。
  `Quality Gate` 要求所有 CI 层成功，失败、取消、跳过均不视为通过。
  服务器 required checks 需要维护者在仓库设置中启用；仅新增 workflow 不等于已强制保护。
- 每轮只更新一份简短会话记录：验收功能、关键取舍、文件与测试证据、阻塞/下一任务。
  未变状态不重复写日志、不重复全量扫描，不把历史 prompt 再粘贴到每个 worker。
