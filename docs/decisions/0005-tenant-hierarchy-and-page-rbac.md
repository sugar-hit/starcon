# ADR-0005: 子租户层级与页面操作权限

- 日期：2026-09-27
- 状态：Proposed（子租户和角色页面 CRUD 为用户明确要求；父级访问与商品共享默认策略待评审）
- 补充：ADR-0002、ADR-0004；保留每服务数据库内 tenant_id + RLS。

## 设计决策

采用 tenant.parent_tenant_id + tenant_closure 表达多层租户。每个子租户拥有独立业务数据、成员和角色；父子关系不自动产生业务数据访问权。每次业务事务选定一个明确目标租户，通过该租户 membership 和 role_assignment 校验。父级账号经目标租户显式授权进入，汇总查询按目标逐一鉴权，不扩大 RLS 为全部后代。

角色配置基于稳定 page_resource + permission(page,action)，支持页面 CRUD 和领域动作。用户通过成员身份拥有多个角色，数据范围绑定角色分配；操作和范围必须由同一分配满足。前端权限矩阵负责配置和展示，后端命令负责执行鉴权。删除权限不绕过事实不可删除等业务不变量。

共享商品默认显式发布版本并导入子租户独立 SPU/SKU，来源映射可追溯；不共享库存主键、不跨租户建商品外键。商品 product 统一命名 spu，无规格商品也有 SKU。

## 取舍

显式成员授权比父级自动继承需要更多管理配置，但保留清楚的隔离边界和撤权路径。独立导入目录需要处理版本差异，却不会让父级编辑意外改动子租户历史业务。若业务要求自动继承权限或统一集团 SKU，需评审具体授权和所有权策略后调整，不能从层级关系隐含推导。
