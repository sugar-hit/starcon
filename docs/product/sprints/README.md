## 功能交付纪律

1. 每个功能关联 PRD FR/AC，先核对现有实现与依赖，再改源代码。
2. 每个功能包含正常、拒绝、重复与失败恢复测试；数据库功能必须跑真实 PostgreSQL 隔离验证。
3. API 变动从后端重新生成契约；不直接修改生成包。
4. 完成相关测试、lint、typecheck、build，记录证据；UI 功能附截图。通过本地检查不表示远端 CI 已通过。
5. 每次更新当前项与剩余项，写会话日志。不得把“有页面”“有 SQL 草稿”“已修文档”标为功能完成。

## S1-01 范围及后续边界

- 切换前统一确认风险；取消不发请求。
- 发起切换时卸载工作区并阻断旧页面后续业务请求。
- 明确拒绝恢复原身份；网络错误/5xx 读取真实身份；核验不可用则阻断并可重试；401 进入登录。
- 重试核验只读身份，不重发切换。
- 本增量不解决已到达服务端的在途写入、两个标签页同时切换或超时请求晚于身份查询提交的问题。S1-02 需服务端会话版本或等价串行机制及竞态测试，未完成前不得宣称 AC-05 全通过。

## 审阅结论

- IAM：收敛组织写权限为 Owner，普通角色只读；平级部门不宣称部门树；区别本地头像与真实账号资料。
- IAM：对象不存在与对象无权访问统一为不可访问；撤权“下一次请求”以事务提交后的新身份核验为边界，在途请求单列。
- 订单库存：D3 验收不依赖尚未实现的订单界面；补重复池行合计校验、到期竞争、缓冲下限、幂等租户/动作边界和超授权实物隔离。
- 金额数量：补非负/正数、19 位容量、溢出拒绝及基础单位冻结；币种/时长/仓型仍需业务决策。
- V2/V3 是设计资料，Flyway 是执行来源；不直接将 SQL 草稿部署为业务功能。
