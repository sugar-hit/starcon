# 17 组织权限与系统设置系统

> **定位**：谁能看什么、谁能改什么、谁能批什么、编号怎么编、参数怎么配。多租户 SaaS 的安全底座。
> **后端归属**：`identity` 服务（唯一拥有租户、法人、部门、成员、角色、页面资源、权限、审批、审计）。
> **前端入口**：租户组织管理 `/org`；平台运营 `/platform`。文中 `/settings/*` 为目标态信息架构，实施前需通过对应 PRD 确认迁移方案。

## 边界

**做**：租户与子租户、法人主体、部门组织、成员开通、角色与页面权限、数据范围、审批流、系统参数与编号规则、字典、审计日志、操作日志。

**不做**：不做业务数据的读写（只提供权限判定）、不管理业务主数据（属 03）、不管理店铺（属 02）。

**关键约束**（[ADR-0005](../../decisions/0005-tenant-hierarchy-and-page-rbac.md) 明确）：
- **子租户是独立数据边界，父子关系不自动授予业务访问**
- 租户 ID 来自已认证用户的成员关系，**不信任 `X-Tenant-Id` 头**
- 页面 CRUD 权限由**目标租户**的角色配置
- **操作权限与数据范围必须在同一个角色分配中同时满足**
- 每张业务表 `tenant_id NOT NULL` + RLS，登录用户查询自己的租户列表属于**显式窄权限路径**

## 功能职责（L2）

| **17.7 平台运营** | starcon **自身**的套餐计费与平台配置，**不是租户可见的 ERP 功能**，仅平台管理员访问 | platform |

## 详细设计

### 17.1.1.1 租户列表

- **职责**：展示用户所属的租户及其基本状态（名称、标识、状态、角色、最后登录），支持切换租户上下文；租户管理员可管理本租户基本信息。
- **输入**：当前用户身份；租户列表查询（**仅返回有成员关系的租户**）。
- **输出**：可切换租户列表 + 当前上下文标识。
- **关系**：上游 = 17.2.2.1 成员关系；下游 = 全系统租户上下文。**这是唯一允许的跨租户列表查询路径**，且只返回用户自己的成员关系租户（实体目录 §4 明确窄权限路径）。

### 17.1.1.2 子租户

- **职责**：管理租户层级：创建子租户、设定父子关系、查看层级树与祖先索引；**父子默认隔离业务数据**。
- **输入**：子租户创建；层级调整；`tenant_closure` 维护。
- **输出**：租户树 + 层级事件记录。
- **关系**：上游 = 17.1.1.1；下游 = 17.1.1.3 层级授权。**父子关系仅表示结构，不自动赋权**——集团看子公司数据必须显式授权。

### 17.1.1.3 层级授权

- **职责**：父租户访问子租户数据的显式授权：授权范围（哪些子租户、哪些数据域、只读还是可写）、授权有效期、撤销。
- **输入**：授权配置；访问请求。
- **输出**：授权记录 + 访问判定结果；审计日志。
- **关系**：上游 = 17.1.1.2；下游 = 全系统数据过滤。**授权判定在服务端完成**，前端菜单隐藏不构成权限控制。

### 17.1.2.1 法人档案

- **职责**：管理法人主体：法定名称、注册国家、登记号、本位币、地址、税务登记（关联 16）、启用状态。法人是**货权、收付款与记账主体**，不等于租户。
- **输入**：法人增删改；状态变更；税务信息关联。
- **输出**：法人档案。
- **关系**：上游 = 17.1.1.1；下游 = 7 库存（货权）、12 财务（记账）、2 店铺（绑定法人）。**法人与租户是一对多**，一个租户可含多个法人——这是"店铺收入记到哪个主体"的基础。

### 17.1.2.2 本位币与账簿

- **职责**：为法人配置会计账簿与本位币（关联 12 财务），设置记账规则（数量精度、金额舍入、期间设置）。
- **输入**：账簿配置；本位币选择。
- **输出**：账簿配置记录。
- **关系**：上游 = 17.1.2.1；下游 = 12.5 会计科目与期间。**本位币归法人，租户默认币种只是展示默认**（实体目录 §5），两者不能混。

### 17.2.1.1 部门树

- **职责**：维护部门层级：部门编码、名称、负责人、所属法人、上下级关系，支持拖拽调整与防环校验。
- **输入**：部门增删改；层级调整。
- **输出**：部门树 + 成员分布。
- **关系**：上游 = 17.1.2.1；下游 = 17.2.2.1 成员、17.3.2.2 数据范围。**部门是组织维度，与法人（法律主体维度）分离**——不能用一个组织节点混装两者。

### 17.2.1.2 部门负责人

- **职责**：指定部门负责人，设置管理范围与审批权限，支持代管与临时授权。
- **输入**：负责人设置；授权范围。
- **输出**：负责人记录；审批链引用。
- **关系**：上游 = 17.2.1.1；下游 = 17.4 审批流。**负责人可为空**，没有负责人的部门需要在审批流中指定兜底人。

### 17.2.2.1 成员管理

- **职责**：管理租户成员：用户信息、所属部门（可多部门）、角色分配（可多个带范围的角色）、状态（正常/停用）、关联负责人范围。
- **输入**：成员新增/编辑；角色分配；部门关联；停用操作。
- **输出**：成员档案 + 权限汇总视图。
- **关系**：上游 = 17.3.2.1；下游 = 全系统权限判定。**成员可属多个部门、可持多个角色**，实际权限是所有角色分配的并集。

### 17.2.2.2 成员开通与入职

- **职责**：为新成员创建本地账号或关联已有全局账号，建立目标租户成员关系，并设置初始部门与角色。邮件邀请、接受令牌和自助激活属于后续独立 PRD，不作为当前可用能力。
- **输入**：管理员录入的账号信息或已有用户标识；目标租户；初始部门与角色。
- **输出**：账号创建/关联结果 + 成员记录 + 初始角色分配；不在页面或日志返回完整初始凭据。
- **关系**：上游 = 17.2.2.1；下游 = 17.3.2.1 角色分配。未来引入邮件邀请时必须补充令牌摘要存储、有效期、单次使用、防枚举和撤销规则。

### 17.2.2.3 离职与停用

- **职责**：处理成员离职：停用成员（非删除用户）、转移在职单据与审批责任、回收待办与任务、保留历史操作记录。
- **输入**：离职操作；责任转移指定。
- **输出**：成员状态变更 + 责任转移记录。
- **关系**：上游 = 17.2.2.1；下游 = 17.4.2.2 审批、1 工作台待办。**停用而非删除**：离职员工的操作记录是审计追溯的依据。

### 17.3.1.1 角色管理

- **职责**：管理角色：角色编码、名称、描述、系统预置标记、成员数统计；支持复制角色作为自定义角色的起点。
- **输入**：角色增删改；复制操作。
- **输出**：角色档案。
- **关系**：上游 = 17.2.2.1；下游 = 17.3.1.2 权限矩阵。**系统预置角色不可删除**（权限被依赖），可复制为自定义角色。

### 17.3.1.2 页面权限矩阵

- **职责**：配置角色的页面 CRUD 与扩展动作权限：按 L3 子功能（页面资源表）勾选查看/新增/编辑/删除/导出/审批/特殊动作，按系统分组展示，实时显示影响成员数。
- **输入**：权限勾选；`page_resource` 与 `permission` 记录。
- **输出**：角色权限矩阵（可导出）；受影响成员预览。
- **关系**：上游 = 17.3.1.1；下游 = 全部系统的服务端鉴权。**权限控制必须在服务端执行**，前端菜单显隐只是体验优化（ADR-0005）。

### 17.3.2.1 角色分配

- **职责**：给成员分配角色：选择角色、设定生效时间、设定作用范围（法人/店铺/仓库/部门）、多个角色并存时的合并规则说明。
- **输入**：角色分配操作；范围设定。
- **输出**：角色分配记录 + 有效权限预览（合并后）。
- **关系**：上游 = 17.3.1.1；下游 = 17.3.2.2、17.2.2.1。**分配时必须同时设定范围**——没有范围的角色等于全量权限，实践中极易误配。

### 17.3.2.2 数据范围

- **职责**：配置角色分配的作用范围：按法人、店铺、仓库、部门分别限定，多个分配的范围取并集，支持"全部"与指定集合两种模式。
- **输入**：范围配置；范围对象集合。
- **输出**：范围记录；有效数据可见集预览。
- **关系**：上游 = 17.3.2.1；下游 = 全系统列表查询过滤。**操作与数据范围必须在同一分配中同时满足**：有"删除订单"操作权但范围限定在仓库 A，就不能删除仓库 B 的订单。

### 17.3.3.1 越权检测

- **职责**：检测与审计越权尝试：访问无权限资源、伪造租户标识、跨范围访问、异常高频访问，输出审计事件并可告警。
- **输入**：鉴权失败事件；`audit_event`；访问模式异常检测。
- **输出**：越权审计记录 + 风险告警。
- **关系**：上游 = 全系统鉴权层；下游 = 1 工作台告警、16.5.2 安全审计。**伪造 tenant header 无效**是集成测试必须证明的三条之一（AGENTS.md 多租户章节）。

### 17.4.1.1 审批流定义

- **职责**：定义审批流程：适用单据类型、审批节点（角色/岗位/指定人）、审批方式（串行/并行/条件分支）、金额阈值分支、超时升级规则。
- **输入**：流程定义；节点配置；条件规则。
- **输出**：审批流定义记录。
- **关系**：上游 = 17.3.1.1 角色；下游 = 17.4.2.1。**审批流按单据类型注册**，未注册的变更类操作默认可直接执行——需要显式定义才有管控。

### 17.4.1.2 审批规则

- **职责**：配置审批触发规则：金额区间、跨法人、跨部门、新供应商、高风险商品等条件触发不同流程，支持免审配置（小额免审）。
- **输入**：触发条件配置；免审规则。
- **输出**：规则集；生效策略。
- **关系**：上游 = 17.4.1.1；下游 = 各业务系统的提交动作。**免审要设上限金额**，否则"小额免审"会被用来绕过大额管控。

### 17.4.2.1 待我审批

- **职责**：展示当前用户的待审批列表：单据类型、金额、申请人、停留时长、当前节点，支持批量审批与转交。
- **输入**：`approval_instance` 投影；用户身份与角色。
- **输出**：待审批列表；审批动作。
- **关系**：上游 = 各业务系统提交；下游 = 1 工作台待办。**审批动作在 17 执行**，工作台只做跳转，避免两处审批逻辑不一致。

### 17.4.2.2 审批记录

- **职责**：记录与查询审批全链路：发起、流转节点、各节点意见与时间、转交、驳回、撤回，最终结果；支持导出用于审计。
- **输入**：审批实例数据。
- **输出**：审批链路记录；统计报表。
- **关系**：上游 = 17.4.2.1；下游 = 各业务系统（审批结果驱动后续动作）。**审批记录不可修改**，驳回后重新发起要生成新实例并关联原实例。

### 17.5.1.1 业务参数

- **职责**：配置全局与分场景业务参数：审单策略默认值、库存策略默认值、售后政策（期限/必退情形）、成本口径默认值、编号前缀、时区与币种展示默认值。
- **输入**：参数配置；生效范围（全局/按法人/按店铺）。
- **输出**：参数生效值；变更历史。
- **关系**：上游 = 全部业务系统；下游 = 9 审单、11 售后、7 库存。**参数必须有默认值与生效范围**，改参数不改历史单据已冻结的行为。

### 17.5.1.2 编号规则

- **职责**：配置业务单据编号规则：前缀 + 日期 + 序号 + 后缀，序号按实体/日期重置，支持多级嵌套与预览生成效果。
- **输入**：规则定义；预览参数。
- **输出**：编号规则；生成的编号预览。
- **关系**：上游 = 17.5.1.1；下游 = 全部单据创建（订单、采购、出库、售后等）。**编号是业务单据的可读标识**，不是外键；规则冲突要在配置时校验。

### 17.5.2.1 数据字典

- **职责**：维护业务字典：状态枚举、原因码、分类标签、单位类型等，支持租户级自定义扩展与停用，不允许修改已被历史数据引用的编码。
- **输入**：字典项增删改；停用操作。
- **输出**：字典项 + 引用统计。
- **关系**：上游 = 17.5.1.1；下游 = 各业务系统下拉选项。**字典项被引用后只能停用不能删除**，否则历史单据会显示空白。

### 17.5.3.1 审计日志

- **职责**：记录关键操作的不可篡改审计：操作人、时间、动作、资源、授权上下文、脱敏的变更前后值；支持按资源/操作人/时间检索与导出。
- **输入**：各系统产生的 `audit_event`；查询条件。
- **输出**：审计记录列表 + 变更详情。
- **关系**：上游 = 全部业务系统；下游 = 审计与合规检查。**审计不记录密码与完整客户地址**；变更详情必须脱敏（实体目录 §4）。

### 17.5.3.2 操作日志

- **职责**：记录系统操作日志用于运维排障：登录、API 调用摘要、任务执行、错误堆栈，支持按用户/时间/请求 ID 关联链路。
- **输入**：系统运行事件；查询条件。
- **输出**：操作日志 + 链路关联视图。
- **关系**：上游 = 系统各层；下游 = 运维排障。**操作日志与审计日志用途不同**：前者排障（含技术细节，可短期留存），后者合规（脱敏，长期留存），不可互相替代。

### 17.6.1.1 账簿与本位币

- **职责**：在法人下管理**多本账簿**并指定各账簿的本位币（如"业务账 CNY"与"海外账 USD"并存），支持按账簿区分业务流水与法定账；账簿决定本位币、科目体系与报表口径，跨账簿不混记。
- **输入**：账簿定义（名称、本位币、类型（业务账/法定账）、启用状态、科目体系来源）；默认账簿设置。
- **输出**：账簿档案 + 本位币；单据与凭证的归属账簿；报表按账簿出。
- **关系**：上游 = 17.1.2.1 法人；下游 = 12.5.1.1 会计科目、12.5.2.1 凭证、12.1.1 应收应付。**跨境常见一个主体同时用人民币和美元记账**（多币种平台结算+国内采购），单账簿假设会导致本位币与实际不符；多账簿不改变"单一事实账"原则，同一笔业务事实只在归属账簿记一次。

### 17.7.1.1 套餐与权益

- **职责**：starcon **自身**的 SaaS 商业化：套餐定义与权益项（店铺数、SKU 数、订单量、用户数、API 调用量、AI 用量）、订阅状态、试用与到期处理、超限策略。**仅平台管理员可见，租户不可访问**——避免与租户自身的采购/应付业务混淆。
- **输入**：套餐配置；订阅与续费事件；权益校验结果。
- **输出**：订阅状态；权益用量视图；超限降级/阻断策略。
- **关系**：上游 = 平台运营；下游 = 各系统功能开关（超限降级）。**与 ERP 客户的销售收入完全无关**（实体目录 §8 已说明"独立于 ERP 客户的销售收入，暂不实施"），实现时需与业务库物理隔离。

### 17.7.1.2 用量统计

- **职责**：统计各租户资源用量（店铺、SKU、月订单、存储、API、AI）用于计费与容量规划，口径须与套餐定义严格一致。
- **输入**：各系统用量埋点；统计周期。
- **输出**：用量报表 + 趋势 + 计费依据。
- **关系**：上游 = 全部系统埋点；下游 = 17.7.1.1 计费。**口径不一致会直接引发计费争议**。

### 17.7.2.1 平台参数与开关

- **职责**：平台级功能开关与参数（灰度放量、按租户禁用某模块、限流阈值、公告），用于平台侧运营而非租户配置。
- **输入**：开关与参数配置；灰度策略。
- **输出**：全局配置；功能可用性判定。
- **关系**：上游 = 平台运营；下游 = 全系统功能门控。**平台开关与租户参数（17.5.1）分层**，平台开关不可被租户覆盖。

### 17.7.2.2 平台运维视图

- **职责**：平台管理员视角的跨租户运维视图：租户在线状态、错误率、任务积压、容量与成本，**严格隔离租户业务数据**，不展示单租户的客户/订单/PII 明细。
- **输入**：系统指标与运维事件。
- **输出**：平台健康看板；告警。
- **关系**：上游 = 全部服务运维指标；下游 = 平台告警。**跨租户视图只看技术指标不看业务数据**，是 SaaS 多租户隔离的红线。
