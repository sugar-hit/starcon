# 15 客户与客服系统

> **定位**：买家侧的入口。站内信、邮件、评价、消息触达，以及跨店铺的买家档案。
> **后端归属**：`channel` 服务负责平台消息同步与发送；`support` 服务负责工单、模板与通知投递；买家主档在 `catalog`（`party` `customer_profile`）。
> **前端入口**：`/crm`

## 边界

**做**：站内信与邮件收发、消息模板、评价管理与回复、Request a Review、客户档案与标签、客户接触记录、客服工单与知识库、消息触达（关怀邮件、催付、催评）。

**不做**：不替代工单系统处理售后（11 负责售后单据）、不存储完整 PII 到普通日志。

**关键约束**：
- **不同店铺的买家不按邮箱自动合并**（实体目录 §3.5），合并需显式操作并留痕
- 买家联系方式属敏感数据，**不进普通日志、不进导出默认字段**
- 平台消息发送走官方接口，频率受限
- 消息模板与合规话术需版本化，平台政策变化时能定位

## 详细设计

### 15.1.1.1 消息收件箱

- **职责**：集中展示各店铺的平台站内信与买家消息：店铺、买家、主题、正文、附件、平台时间、收发方向、已读状态、关联订单，支持按店铺/类型/优先级/未读筛选与批量处理。
- **输入**：平台消息同步（webhook + 拉取）；用户筛选条件；数据范围（店铺维度）。
- **输出**：消息列表 + 详情视图 + 关联订单上下文。
- **关系**：上游 = 2 渠道与店铺（同步）；下游 = 15.1.1.2 回复、11 售后（转售后）、15.4 工单。**消息必须关联到买家与订单**，否则客服看到消息还要去猜是哪一单。

### 15.1.1.2 消息发送

- **职责**：回复买家消息：调用模板、手工编辑、附件支持、发送记录、失败重试；支持批量相同回复（同类问题）。
- **输入**：回复内容（模板或手工）；目标消息；附件；`idempotency_key`。
- **输出**：发送记录 + 平台回执 + 失败原因。
- **关系**：上游 = 15.1.1.1、15.4.2 知识库；下游 = 平台消息接口。**发送失败要保留原消息状态**，不能让客服以为已回复。

### 15.1.1.3 消息分类

- **职责**：对消息自动分类（售前咨询、物流查询、退货退款、投诉、平台合规、垃圾信息），驱动自动回复与优先级，支持人工纠正以改进分类。
- **输入**：消息内容；分类规则（关键词 + 平台类型 + 历史纠正数据）。
- **输出**：分类标签 + 优先级 + 是否可自动回复。
- **关系**：上游 = 15.1.1.1；下游 = 15.5.1 自动回复、1.3 预警。**人工纠正要回流为训练样本**，否则分类准确率永远上不去。

### 15.1.2.1 邮件收发

- **职责**：管理买家邮件（Amazon Buyer-Seller Messaging、eBay 邮件等）：收发、附件、模板、与站内信的双向同步或标记为同源。
- **输入**：邮件同步；发送请求。
- **输出**：邮件列表与详情 + 发送记录。
- **关系**：上游 = 2 同步；下游 = 15.1.1.2 发送。**部分平台要求邮件与站内信在同一会话处理**，分开展示会导致重复回复买家。

### 15.1.2.2 邮件规则

- **职责**：配置邮件自动处理规则：按发件人/关键词/工单标签自动分配、自动回复、静默规则（重要沟通不可静默）。
- **输入**：规则配置；15.1.1.3 分类结果。
- **输出**：规则命中记录；自动分配结果。
- **关系**：上游 = 15.1.1.3；下游 = 15.4.1.1 工单分配。**关键沟通静默会造成平台违规**，规则需强制留痕。

### 15.2.1.1 评价列表

- **职责**：汇总各店铺评价：星级、内容、变体、图片、平台时间、关联订单、是否已回复、店铺评分汇总，支持筛选（星级、含图/含视频、未回复、时间范围）与导出。
- **输入**：评价同步；筛选条件。
- **输出**：评价列表 + 评分统计。
- **关系**：上游 = 2 同步；下游 = 15.2.1.2 回复、15.2.2.1 索评。**评分趋势比单条评价更重要**：连续下滑要先查是产品问题还是履约问题。

### 15.2.1.2 评价回复

- **职责**：回复评价（公开回复 + 部分平台的卖家评论追加），支持模板、多语言、批量回复同类评价。
- **输入**：回复内容；目标评价。
- **输出**：回复记录 + 平台回执。
- **关系**：上游 = 15.2.1.1；下游 = 平台接口。**差评回复是转化机会也是合规风险**，模板必须符合平台措辞规范。

### 15.2.1.3 差评处理

- **职责**：差评专项处理：标记原因（产品/物流/服务/误判）、判定是否申诉（部分平台支持）、联系买家解决后请求修改、跟踪解决率。
- **输入**：差评内容；处理动作；买家沟通记录。
- **输出**：处理记录 + 申诉任务 + 解决状态。
- **关系**：上游 = 15.2.1.1；下游 = 15.1.1.2 联系买家、11 售后（解决问题）。**解决差评的正确路径是先解决买家问题再请求修改**，直接申诉容易被驳回且消耗申诉配额。

### 15.2.2.1 Request a Review

- **职责**：按规则向已签收订单的买家发起索评（平台允许范围内），控制频次避免打扰，支持按店铺/时间/物流状态批量执行。
- **输入**：索评规则（时点、范围、频次上限）；已签收订单集合。
- **输出**：索评任务 + 发送记录 + 评价回收统计。
- **关系**：上游 = 10.3.2.2 签收；下游 = 15.2.1.1 评价。**索评频次必须受限**，过度索评会被买家投诉甚至平台处罚。

### 15.2.2.2 索评规则

- **职责**：配置索评策略：按店铺、按物流方式（自发货/平台仓）设置不同延后时间，避开节假日，支持 A/B 测试不同话术。
- **输入**：规则配置；话术模板。
- **输出**：生效策略 + 效果对比。
- **关系**：上游 = 15.2.2.1；下游 = 15.1.1.2 发送。

### 15.3.1.1 客户列表

- **职责**：客户列表：客户标识（按店铺）、来源店铺、首末购买时间、订单数、累计消费、退款率、客单价、标签、联系方式（脱敏）、风险标记。
- **输入**：筛选条件（店铺、标签、价值分层、风险）；用户数据范围。
- **输出**：客户列表 + 分层统计。
- **关系**：上游 = 9 订单、15.3.1.3 合并结果；下游 = 15.3.1.2 详情。**列表默认脱敏显示联系方式**，需要显式授权才完整展示。

### 15.3.1.2 客户详情

- **职责**：客户全档案：基本信息、跨店铺身份关系、订单历史、售后历史、消息历史、评价、标签、接触记录、风险与价值分层。
- **输入**：`customer_id`；聚合各域数据。
- **输出**：详情视图 + 时间线（订单/消息/售后合并时间线）。
- **关系**：上游 = 15.3.1.1；下游 = 9 订单、11 售后、15.1 消息。**统一时间线是客服理解客户的唯一高效方式**——跨系统翻找会显著拖慢响应。

### 15.3.1.3 跨店合并

- **职责**：把同一自然人在不同店铺的身份合并到一个逻辑客户，支持按邮箱/电话/姓名+地址/平台买家标识匹配，给出置信度并需人工确认，保留合并前映射可拆分。
- **输入**：候选匹配（自动建议）；人工确认；拆分请求。
- **输出**：合并后的逻辑客户 + 映射关系 + 操作记录。
- **关系**：上游 = 15.3.1.1；下游 = 15.3.1.2、13 分析（客户价值跨店汇总）。**自动合并风险高**（同名不同人、同人不同邮箱），因此只给建议不自动执行，且必须可拆分。

### 15.3.2.1 客户标签

- **职责**：维护客户标签体系（VIP、复购、退货率高、高客单、风险、渠道来源等），支持自动规则打标（按订单行为）与手工打标，用于筛选与营销。
- **输入**：标签定义；自动打标规则；手工操作。
- **输出**：标签记录 + 标签分布统计。
- **关系**：上游 = 9 订单、11 售后；下游 = 15.3.1.1 筛选、14.4 促销定向、15.5.2 关怀邮件。**"退货率高"标签要谨慎使用**，避免对正常买家产生歧视性动作。

### 15.3.2.2 接触记录

- **职责**：记录与客户的所有接触（客服通话、消息、邮件、营销触达、售后沟通），可由各模块自动写入，支持时间线检索。
- **输入**：各模块接触事件；手工补录。
- **输出**：接触时间线。
- **关系**：上游 = 15.1、11 售后、15.5.2；下游 = 15.3.1.2。**接触记录是自动化的豁免依据**——曾明确表示"不要再联系我"的客户，营销触达需排除。

### 15.4.1.1 工单列表

- **职责**：客服工单列表：类型、优先级、状态、SLA 剩余、关联买家与订单、分配客服、转派与升级。
- **输入**：工单创建（自动/人工）；筛选条件。
- **输出**：工单列表 + SLA 预警。
- **关系**：上游 = 15.1.1.3、11.4.2.1；下游 = 15.4.1.2 处理。**SLA 计时需按营业时间而非自然时间**，否则夜间积压会造成误判。

### 15.4.1.2 工单处理

- **职责**：处理工单：回复、备注、状态流转、关联订单与售后单、解决确认、满意度回收、SLA 暂停/恢复。
- **输入**：处理动作；关联单据；满意度评分。
- **输出**：工单状态 + 处理记录 + 关联单据更新。
- **关系**：上游 = 15.4.1.1；下游 = 11 售后（升级）、9 订单。**工单关闭不等于问题解决**，需确认实际结果（退款到账、换货发出）才计为解决。

### 15.4.2.1 知识库

- **职责**：维护客服知识库：常见问题标准答法、平台政策说明、产品使用指导、退换货规则，按店铺/类目/语言组织，支持版本与生效日期。
- **输入**：知识条目编辑；版本管理。
- **输出**：知识库内容 + 引用记录。
- **关系**：上游 = 3.4.2.2 文案资产；下游 = 15.1.1.2 发送、15.5.1 自动回复。**知识条目必须标注适用平台与生效时间**，平台政策变更时才能快速定位过期内容。

### 15.5.1.1 自动回复

- **职责**：配置消息自动回复：按触发条件（收到消息分类、关键词、无人工介入超时）自动发送回复，支持节假日无人值守、分级自动回复（先自动引导再转人工）。
- **输入**：自动回复规则；模板内容；触发条件。
- **输出**：自动回复记录 + 转人工标记。
- **关系**：上游 = 15.1.1.3、15.4.2；下游 = 15.1.1.2 发送。**自动回复必须可一键关闭并留出人工接管**，很多平台对纯自动回复有明确限制。

### 15.5.2.1 关怀与催办

- **职责**：主动触达买家：发货通知、物流提醒、催付（未付款订单）、催评、售后进度通知、关怀邮件（节假日/生日），按规则定时发送并遵守频次上限与退订要求。
- **输入**：触达规则；目标买家集合；退订名单。
- **输出**：触达发送记录 + 打开/点击统计 + 退订记录。
- **关系**：上游 = 9 订单、10 物流、15.3.2.2 接触记录；下游 = 15.1.1.2 发送、12 财务（催付加速回款）。**催付有合规边界**：部分平台限制催付话术与频次，规则需按平台配置，过度催付会被投诉。
