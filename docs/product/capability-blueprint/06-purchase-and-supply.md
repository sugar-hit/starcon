# 06 采购与供应系统

> **定位**：把"要卖什么"翻译成"要进什么货"，并盯到货真正入仓。跨境卖家的库存事故，八成出在这一环。
> **后端归属**：`trade` 服务拥有采购单据；供应商档案在 `catalog`（`party` `supplier_offer`）；收货执行在 `warehouse`；应付与付款在 `finance`。
> **前端入口**：`/purchase` `/supply`

## 边界

**做**：供应商与货源管理、缺货与补货建议、采购计划与申请、采购单与跟单、委外加工、来料质检、采购侧对账发起。

**不做**：不写库存（08 收货执行）、不确认应付（12 财务）、不做付款。

**关键约束**：
- 采购收货是**分批、可有差异**的，不能假设"到齐了才入账"
- 采购成本影响利润与库存计价，**必须记录币种、汇率快照、单位换算**
- 采购单生成后修改要留痕（改了价格/数量会影响后续核算）
- 补货建议必须纳入**在途量**（已采购未到 + 头程在途），否则会重复补货造成积压

## 功能职责（L2）

| 功能 | 职责 | 主责服务 |
|---|---|---|
| **6.1 供应商与货源** | 维护供应商档案与评级，管理 1688/档口货源池、同款货源推荐与资质；解决"从谁那进货、可不可信" | catalog + trade |
| **6.2 采购需求** | 由销量、可用量与在途量推导出缺货风险与补货建议，汇总为采购计划与申请；解决"该进多少货" | trade |
| **6.3 采购执行** | 管理采购单的创建、审批与跟单到货；解决"货按承诺在正确时间正确数量到达" | trade |
| **6.4 加工与质检** | 处理委外加工（BOM 冻结下发）与来料质检、不良品处置；是精品与高退货类目的必需能力 | trade + warehouse |
| **6.5 采购结算** | 采购侧发起供应商对账并输出采购分析；对账由采购发起、财务付款执行，职责分离 | trade → finance |
| **6.6 产品开发与打样** | 管理新品立项、打样与试产转量产；品牌化客户的产品源头，铺货型客户可整体不启用 | trade + catalog |

## 详细设计

### 6.1.1.1 供应商列表

- **职责**：维护供应商档案清单：编码、名称、联系方式、合作状态、供货 SKU 数、采购金额累计、准时交付率、质量合格率，支持筛选与导出。
- **输入**：查询条件（状态、类目、合作等级）；用户数据范围。
- **输出**：供应商列表 + 关键指标；点击进入详情。
- **关系**：上游 = 3.6.1.2 角色档案；下游 = 6.1.1.2 详情、6.3 采购单、6.5 对账。**供应商数据主数据在 03**，本模块呈现采购视角的视图与运营动作，避免同一实体两处可编辑。

### 6.1.1.2 供应商详情

- **职责**：单供应商全景：基础信息、账期与开票信息、供货 SKU 与报价、采购历史与金额、交期与质量表现、联系人、附件资质。
- **输入**：`supplier_id`；采购历史聚合；报价列表（03）。
- **输出**：详情视图 + 操作入口（新建采购单、发起对账、更新报价）。
- **关系**：上游 = 6.1.1.1；下游 = 6.3.1.2、6.5.1、3.6.2 报价。**账期与开票信息是付款审批的输入**，缺失时 12 财务无法自动生成付款申请。

### 6.1.1.3 供应商评级

- **职责**：按周期（默认月度）自动统计供应商表现：交期达成率、质量合格率、响应时长、价格竞争力、售后配合度，综合打分并支持人工调整权重。
- **输入**：收货事件时间与质检结果；采购单沟通记录；权重配置。
- **输出**：评级结果与排名；评级变动历史；影响采购建议的默认供应商优先级。
- **关系**：上游 = 6.4.2 质检、6.3.2.1 跟单；下游 = 3.6.2 报价优先级、6.2.1.2 补货建议（优先选高分供应商）。**评级必须由客观数据算出**，人工加权分需单独标记，否则会变成纯主观打分。

### 6.1.2.1 档口与货源池

- **职责**：管理 1688/义乌购等货源渠道的店铺档口，抓取与同步在售货源（标题、起订量、价格区间、规格、图片），支持收藏、比价、建立与内部 SKU 的货源关联。
- **输入**：档口 URL 或插件采集；货源同步任务；收藏操作。
- **输出**：货源条目 + 档口列表；价格与起订量信息。
- **关系**：上游 = 外部货源平台；下游 = 3.6.2 报价、6.3.1.2 采购单（带入货源价）。**货源数据是外部快照，会变**，采购下单时必须以实际下单金额为准，货源快照仅作参考。

### 6.1.2.2 同款货源推荐

- **职责**：当某 SKU 缺货或质量不达标时，推荐可替代的同款/相似货源：同款不同供应商、历史采购过该货的供应商、价格对比。
- **输入**：SKU 编码与图片；历史采购记录；货源库匹配结果。
- **输出**：候选货源列表（供应商、价格、交期、历史质量评分）+ 一键生成采购申请。
- **关系**：上游 = 6.1.2.1、6.1.1.3 评级、6.3 采购历史；下游 = 6.2.2.1 采购申请。**同款判定要给置信度**，图片相似不等于同款，误判会导致采购到错误商品。

### 6.1.2.3 供应商资质

- **职责**：登记与跟踪供应商资质：营业执照、质检报告、认证证书（CE/ROHS/ISO 等）、授权书，明确有效期与即将过期提醒。品牌授权需关联 03 品牌。
- **输入**：资质文件上传；有效期；审核状态。
- **输出**：资质档案 + 过期提醒。
- **关系**：上游 = 3.3.2 品牌；下游 = 16 合规（认证缺失预警）、8 收货（质检依据）。**资质过期必须阻断相关商品的刊登与发货**，不能只做提醒。

### 6.2.1.1 缺货与断货风险

- **职责**：识别即将断货的 SKU：按日均销量、可用库存、在途量、备货周期计算"预计断货日"，按紧急度排序输出。
- **输入**：销售速度（13 投影）；可用库存与预占（07 投影）；采购在途（06 自身）；头程在途（10）；采购备货周期（供应商交期+生产周期）。
- **输出**：断货风险清单（SKU、可用量、日均销、可支撑天数、预计断货日、缺口量、涉及店铺）。
- **关系**：上游 = 07 库存、13 销量、10 在途；下游 = 6.2.1.2 补货建议。**必须扣除预占和在途**，只看现有库存会严重高估健康度。

### 6.2.1.2 补货建议

- **职责**：计算建议补货量：目标库存覆盖天数 × 日均销量 −（可用 + 在途），并结合 MOQ、箱规、采购起订额做取整修正，给出建议供应商与到货时间。
- **输入**：销量预测（含近期增长率）；覆盖天数目标（可按 SKU/分类配置）；MOQ 与箱规（3.6.2）；在途量。
- **输出**：补货建议（建议量、取整说明、预计到货日、预计费用）；支持接受/调整/忽略。
- **关系**：上游 = 6.2.1.1、3.6.2 报价、10 头程时效；下游 = 6.2.2.1 采购申请。**建议必须展示计算过程**（销量怎么来的、扣了哪些在途），用户不信任的预测不会被采纳。

### 6.2.1.3 采购计划

- **职责**：按周期（月/季）、按店铺大促节奏、按仓库制定采购计划，把补货建议汇总成计划行，支持调整、锁定、导出给采购员。
- **输入**：补货建议集合；计划周期；大促日历；锁库策略。
- **输出**：采购计划（计划行：SKU、数量、目标仓、期望到货日、优先级）。
- **关系**：上游 = 6.2.1.2；下游 = 6.2.2.1 采购申请。**大促备货与日常补货要分开**：大促计划的备货量大、周期长，混在一起会让日常补货失焦。

### 6.2.2.1 采购申请

- **职责**：把计划行/补货建议转成采购申请，走审批，确认供应商与数量后转采购单。
- **输入**：计划行或建议；供应商选择；数量与交期调整；审批提交。
- **输出**：采购申请单（草稿/待审/已批/已转单/已驳回）；审批记录。
- **关系**：上游 = 6.2.1.2/6.2.1.3；下游 = 6.3.1.2 采购单、17 审批。**申请是内部决策单据，采购单是对供应商的正式承诺**，两者分离便于审批留痕与事后追溯。

### 6.2.2.2 需求合并与批量

- **职责**：把多个 SKU 的需求合并成一张采购单（同一供应商），支持批量生成、批量修改数量与供应商、批量打印。
- **输入**：多行需求；供应商选择（相同供应商才能合并）。
- **输出**：合并后的采购单草稿；未合并行说明原因。
- **关系**：上游 = 6.2.2.1；下游 = 6.3.1.2。**合并只在同一供应商内进行**，跨供应商合并会导致对账与付款错误。

### 6.3.1.1 采购单列表

- **职责**：采购单主列表：单号、供应商、SKU 行数、总金额、币种、状态、承诺到货日、已收数量/比例、逾期标记，支持多维筛选与导出。
- **输入**：筛选条件（供应商、状态、日期区间、是否逾期、目标仓）；用户数据范围。
- **输出**：分页列表 + 批量操作（催单、关闭、导出）。
- **关系**：上游 = 6.2.2.1；下游 = 6.3.1.2 详情、6.3.2 跟踪。**已收比例需实时反映 08 的收货结果**，这是采购员判断是否催货的第一指标。

### 6.3.1.2 采购单创建与编辑

- **职责**：创建/编辑采购单：选择供应商、添加 SKU 行（带出报价与库存快照）、填写数量/采购单位/单价/币种、约定交期与发货地址、备注与附件。支持草稿与提交。
- **输入**：表单数据；`expected_version`；SKU 与供应商报价快照。
- **输出**：采购单（草稿/已提交）；金额与税额计算结果。
- **关系**：上游 = 6.2.2.2、3.6.2 报价；下游 = 6.3.1.3 审批、8 收货、12 应付。**单价、汇率、单位换算在提交时冻结快照**，之后改报价不影响已提交采购单的成本核算。

### 6.3.1.3 采购单审批

- **职责**：按金额阈值与采购员分级审批，支持批量审批、驳回并附意见，审批通过后锁定单据生成应付。
- **输入**：待审批采购单；17 组织的审批规则（金额阈值、层级）。
- **输出**：审批结果 + 审批链路记录；通过后触发 12 生成应付、8 允许收货。
- **关系**：上游 = 17 审批、6.3.1.2；下游 = 12 应付、8 收货。**审批通过的采购单不可直接改数量与单价**——如需变更，走变更单或红冲重下，避免已生成应付与实际收货对不上。

### 6.3.2.1 跟单与交期

- **职责**：记录与供应商的沟通跟进（催单、确认、异常反馈），维护承诺到货日变更历史，统计平均延迟天数。
- **输入**：跟单记录；新的承诺日期与原因。
- **输出**：跟单时间线；交期变更历史；延迟统计。
- **关系**：上游 = 6.3.1.1；下游 = 6.2.1.1（交期变化影响断货预测）、6.1.1.3 评级（准时率）。**交期变更是断货风险的主要输入**，必须回写补货建议。

### 6.3.2.2 到货与逾期

- **职责**：跟踪采购单的到货状态：已发货（在途）、部分到货、全部到货、逾期未到、取消。逾期自动预警并给出处置建议（催货/改供应商/调库存/延期售卖）。
- **输入**：8 仓储的收货事件；跟单记录；物流在途状态（10）。
- **输出**：到货状态 + 逾期预警 + 处置建议。
- **关系**：上游 = 8 仓储作业、10 物流；下游 = 6.2.1.1 断货风险、1 工作台待办。**部分到货必须立即更新已收数量并触发应付部分确认**，否则采购与财务三方数据对不上。

### 6.4.1.1 加工单

- **职责**：发起委外/自有工厂加工：选择成品 SKU 与 BOM 版本、指定组件领用量与加工厂、约定完工数量与交期，跟踪加工进度与入库。
- **输入**：加工需求（成品、数量、组件需求）；BOM 版本；加工厂。
- **输出**：加工单（组件领用记录 + 完工数量）；入库需求通知 8。
- **关系**：上游 = 3.5.2.1 BOM；下游 = 8 组装/加工单、7 库存（组件出库与成品入库同事务）。**加工是"消耗组件产生成品"的库存动作**，必须在 warehouse 本地事务完成，不能由 trade 直接改库存。

### 6.4.1.2 BOM 关联

- **职责**：加工单引用 BOM 版本并冻结展开结果，后续 BOM 修改不影响已下达的加工单。
- **输入**：BOM 版本选择；冻结动作。
- **输出**：冻结的组件清单快照。
- **关系**：上游 = 3.5.2.2 展开；下游 = 6.4.1.1。**冻结与订单冻结组件同理**：加工周期长，BOM 中途改配会导致实物与系统不符。

### 6.4.2.1 质检单

- **职责**：来料/成品质检：抽样比例、检验项（外观、功能、规格、包装、认证标识）、检验结果记录、不合格判定与扣量。
- **输入**：收货事件；质检模板（按类目）；抽样规则；质检结果录入。
- **输出**：质检单（合格量/不合格量/让步接收量）；触发 7 库存的质量状态分流。
- **关系**：上游 = 8 收货、3.7.2 物理安全属性；下游 = 7 库存（待检 bucket）、6.1.1.3 评级。**质检不合格的货不能直接进可售库存**，必须进入待检或残次状态。

### 6.4.2.2 不良品处理

- **职责**：不合格品的处置：退换货补货、返修、让步接收、报废、转为促销品，处置结论联动库存状态与供应商索赔。
- **输入**：质检不合格明细；处置决策；索赔金额。
- **输出**：处置单 + 库存状态变更指令 + 供应商索赔记录。
- **关系**：上游 = 6.4.2.1；下游 = 7 库存（调整）、12 财务（索赔/退款）。**让步接收需要权限与原因**，不能由质检员随手放行。

### 6.5.1.1 采购对账

- **职责**：采购侧发起与供应商的对账：按期间汇总应收数量、单价、金额、代扣代缴费用、索赔，生成对账单发给供应商确认，差异挂起。
- **输入**：期间内的收货记录、质检扣量、索赔；供应商确认回执。
- **输出**：对账单（明细 + 汇总）；差异清单；确认状态。
- **关系**：上游 = 8 收货、6.4.2 质检；下游 = 12 财务（应付核对与付款）。**对账由采购发起、12 财务执行付款**，两侧数据以对账单为交接点，避免采购擅自确认应付。

### 6.5.2.1 采购分析

- **职责**：采购侧报表：采购金额趋势、供应商集中度与贡献、采购价格波动、到货准时率、采购成本占销售额比、按类目/店铺维度的采购效率。
- **输入**：采购单与收货数据；时间范围与维度筛选。
- **输出**：报表图表 + 可导出明细；下钻到具体采购单。
- **关系**：上游 = 6.3、6.4；下游 = 13 利润与经营分析。**采购成本占比是利润健康度的先行指标**，采购毛利异常时能提前发现。

### 6.6.1.1 开发立项

- **职责**：管理新品开发立项：立项编号、品类、目标市场与平台、目标售价与毛利、开发负责人、打样与量产时间计划、状态（评估/立项/开发中/打样/试产/量产/终止）。立项通过后可派生打样单与试产单，并作为 SKU 建档的前置。
- **输入**：立项申请与评审结论；目标定价与成本估算（5.3.1.1）。
- **输出**：开发单（立项记录 + 里程碑计划）；可转 SKU 建档的候选参数。
- **关系**：上游 = 5 定价（目标毛利）、14 广告（市场数据）；下游 = 6.6.1.2、6.6.2.1、3.1.1.1 建档。**立项不是 ERP 传统模块，但是品牌化客户的源头**——把"开发-打样-试产-量产"纳入同一编号体系，才能让开发成本进入 SKU 生命周期。

### 6.6.1.2 打样与样品管理

- **职责**：管理打样与样品：样品申请、样品来源（供应商/自有产）、样品物流、确认结果（通过/修改/放弃）、样品成本；与达人寄样（14.5.1.2）区分打样与营销样品。
- **输入**：打样申请；供应商/工厂；样品信息与图片。
- **输出**：打样单 + 样品台账 + 确认记录；样品成本。
- **关系**：上游 = 6.6.1.1、6.1.2.1 档口；下游 = 6.6.2.1 试产、12 费用（样品成本）。**打样费用是新品开发的真实成本**，需进费用归集，否则新品利润被高估。

### 6.6.2.1 试产单

- **职责**：管理试产：小批量试产（数量、BOM 版本、组件需求、产线/加工厂、质检标准、试产成本与良率），试产结果记录并对比量产目标，输出转量产建议。
- **输入**：试产申请（BOM 版本、目标数量）；质检方案；成本数据。
- **输出**：试产单 + 组件领用需求（→ 7 库存）；良率与成本结果；转量产建议。
- **关系**：上游 = 6.6.1.2、3.5.2.1 BOM；下游 = 6.6.2.2、8.4.1 组装/加工。**试产消耗真实组件库存**，需走 8 加工单而非直接改库存（实体目录 §6）。

### 6.6.2.2 转量产与建档

- **职责**：试产通过后转正式量产：确定量产 BOM、批量采购/生产计划、目标成本、正式 SKU 建档（含编码/条码/属性/报关属性），并把量产参数带入采购与价格模型。
- **输入**：试产结果；量产决策；BOM 定版。
- **输出**：量产计划；正式 SKU（3.1.2.1）；量产 BOM 版本；采购需求（6.2.1.2）。
- **关系**：上游 = 6.6.2.1；下游 = 3 商品主数据、6 采购、5 定价。**转量产是开发与供应链的交接口**，SKU 编码/条码在此时生成，后续全链路引用此编码。
