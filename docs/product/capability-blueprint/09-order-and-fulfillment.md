# 09 订单履约系统

> **定位**：把"买家下单"变成"货发出去且平台认账"。跨平台订单的聚合、审单、拆合单、分仓、发货回传都在这里。
> **后端归属**：`trade` 服务拥有订单与售后单据；订单数据来自 `channel` 同步；库存动作由 `warehouse` 执行。
> **前端入口**：`/orders`

> 评审提示：本文为能力蓝图。代发的货权/资金政策、财务确认与关账规则须在对应 PRD 中确认；未决项见 [业务设计审查](../../backlog/2026-09-30-business-design-review.md)。不能将经营形态直接等同于会计政策。

## 边界

**做**：订单聚合与查询、审单与异常拦截、拆单合单、仓库分配、履约批次编排、发货回传、订单状态与时效、订单变更与取消。

**不做**：不扣库存（07/08 执行）、不处理退货判定（11）、不做平台状态写入（2 回写队列）。

**关键约束**：

- **一订单可多次、多仓履约**，出库单不与订单一一对应
- 订单行冻结**商品、价格、汇率、映射版本、单位换算**快照
- 取消与预占的乱序必须用流程版本 + 取消终态阻断，不能"回滚 HTTP 调用"
- 重复 webhook / 重复事件**只产生一张订单**

## 详细设计

### 9.1.1.1 订单列表

- **职责**：全渠道订单统一列表：订单号、平台店铺、下单时间、买家、SKU 行数、总金额/币种、支付状态、履约状态、发货仓、平台状态，支持多维筛选、导出与批量操作（审单、备注、取消、发催付）。
- **输入**：筛选条件（平台、店铺、时间、状态、金额、买家、SKU、发货仓）；用户数据范围。
- **输出**：分页列表 + 汇总条（订单数/金额/待处理数）；批量操作结果。
- **关系**：上游 = 2 平台同步、9.2 审单；下游 = 9.1.1.2 详情、9.3 履约。**列表状态是多状态的组合展示**（支付状态 × 履约状态 × 售后状态），需要能按任一维度筛选与排序。

### 9.1.1.2 订单详情

- **职责**：订单全景：买家与地址快照、商品行（SKU、规格、单价、数量、税费）、费用构成与分摊、支付与退款记录、履约批次与包裹、物流轨迹、售后关联、平台侧原始报文、状态历史。
- **输入**：`order_id`；聚合子资源（组件展开、费用分摊、包裹、售后）。
- **输出**：分区详情 + 操作入口 + 状态时间线。
- **关系**：上游 = 9.1.1.1；下游 = 9.3 履约、11 售后、12 财务。**详情页是订单的"控制塔"**：客服、采购、财务都从这一个页面理解这笔订单为什么长这样。

### 9.1.1.3 订单变更与取消

- **职责**：处理订单变更与取消：地址修改、数量调整（需平台允许）、取消未发货数量（先确认仓库停止作业并释放占用；已发货数量转售后），并把变更同步回平台。
- **输入**：变更/取消请求；平台可变更规则；当前履约状态。
- **输出**：取消申请/处理中/已确认/拒绝或待核验状态 + 仓库停止作业及释放结果 + 平台回写任务；仅在责任方确认后记录对应数量的取消终态。
- **关系**：上游 = 9.1.1.2；下游 = 7.2.1.3 释放、2.5.1.1 回写、11 售后（已发货转售后）。**已发货订单不能取消只能转售后**，这是硬规则——不能"回滚 HTTP 发货"（实体目录 §6.5）。

### 9.1.2.1 平台订单同步

- **职责**：接收并落库平台订单（webhook 实时 + 轮询补拉），做字段解析、状态归一、金额与税费还原、地址快照，形成统一订单模型。
- **输入**：平台订单事件/接口返回；平台枚举映射（2.1.2.1）；`idempotency_key`（平台订单号 + 来源范围）。
- **输出**：销售订单 + 行 + 费用 + 地址快照 + 组件展开（按映射版本）。
- **关系**：上游 = 2 渠道与店铺；下游 = 9.2 审单、9.3 履约、13 销量。**同一外部订单号在同一来源范围内唯一**，重复事件走 inbox 去重，绝不产生第二张订单。

### 9.1.2.2 手工订单

- **职责**：支持非平台来源订单（独立站线下、B2B、代发、样机单）的录入，含客户选择、商品行、收货地址、费用与支付方式。
- **输入**：表单录入或导入；客户档案（03 party）；价格来源（05 价目）。
- **输出**：手工销售订单（来源=MANUAL）+ 后续同样进入审单履约流程。
- **关系**：上游 = 3.6.1.2 客户档案；下游 = 9.2 审单。**手工单与平台单共用同一条履约链路**，只有来源标记不同，避免两套流程。

### 9.2.1.1 待审队列

- **职责**：展示待审订单，按风险与时效排序，支持批量通过/驳回/挂起，显示每单命中的规则与风险信号。
- **输入**：新订单事件；审单规则配置；风控信号。
- **输出**：待审列表 + 批量审单结果。
- **关系**：上游 = 9.1.2.1、9.2.1.2；下游 = 9.3 履约编排。**审单是发货前的最后人工闸门**，批量通过必须基于明确的规则，而不是默认全过。

### 9.2.1.2 审单规则

- **职责**：配置自动审单规则：按店铺/金额/买家等级/商品/收货国家自动通过或转人工；命中黑名单、地址异常、大额、异常折扣的强制转人工。规则有优先级与生效期。
- **输入**：规则定义（条件、动作、优先级）；测试数据。
- **输出**：规则命中结果（每单命中的规则链）；规则生效记录。
- **关系**：上游 = —；下游 = 9.2.1.1、18 自动化（规则引擎复用）。**规则命中结果要可解释**：客服被买家投诉时能说出"为什么这单被拦了"。

### 9.2.1.3 异常拦截

- **职责**：识别并拦截异常订单：地址不可达/信息不全、黑名单买家、重复下单、异常折扣（低于成本）、疑似欺诈、超出收货国家限制、平台合规风险。
- **输入**：地址校验服务；16 合规与风控信号；5 定价（低于成本线）；订单特征。
- **输出**：拦截清单 + 拦截原因 + 处置建议（取消/转人工/放行）。
- **关系**：上游 = 9.2.1.2；下游 = 16 合规（黑名单）、11 售后（欺诈售后）、2 平台（取消回写）。**拦截不自动取消**，默认转人工——误拦真实订单的代价通常高于人工看一眼。

### 9.2.2.1 地址与支付校验

- **职责**：校验买家地址可投递性（国家/邮编/街道格式）、禁运国家清单、支付状态一致性（平台已付/货到付款/未付款）。
- **输入**：订单地址快照；支付方式与状态；禁运规则配置。
- **输出**：校验结果 + 风险等级。
- **关系**：上游 = 9.1.2.1；下游 = 9.2.1.3、10 物流（渠道可用性）。**货到付款订单的履约风险最高**，需额外风控与保险策略。

### 9.2.2.2 风控校验

- **职责**：多信号风险打分：买家历史（退款率、纠纷率）、设备与 IP 关联（16）、下单频次、金额异常、地址集中度；输出风险分与建议动作。
- **输入**：买家行为画像（15 客户）；16 风控信号；订单聚合特征。
- **输出**：风险评分 + 建议动作（放行/人工/拒发）。
- **关系**：上游 = 15 客户、16 合规；下游 = 9.2.1.3。**风控分数不能单独作为拒绝依据**，需人工复核，避免误伤正常复购客户。

### 9.3.1.1 拆单

- **职责**：把一个订单拆成多个履约单元：按仓库拆、按承运商拆、按发货时效拆（如部分现货先发）、按平台限制拆。
- **输入**：拆单请求或自动拆单规则；可用库存分布。
- **输出**：多个履约请求 + 库存预占指令 + 发货回传按拆分执行。
- **关系**：上游 = 9.2 审单；下游 = 9.3.3.1 履约请求、7 预占。**拆单不产生新的销售订单**，只是履约切分；订单总金额与买家视角不变。

### 9.3.1.2 合单

- **职责**：把同一买家的多笔订单合并成一个包裹发货，降低运费与包材成本；同时识别跨店铺同买家订单（需分别回传平台）。
- **输入**：候选订单集合（同一买家 + 同一收货地址）；合单规则。
- **输出**：合并履约请求 + 各原订单的关联记录。
- **关系**：上游 = 9.1.1.1；下游 = 8.3.3.2 打包、9.4.2.1 回传。**合单后每个平台订单仍要单独回传物流号**，平台不认跨订单的合并。

### 9.3.2.1 分仓规则

- **职责**：配置并执行仓库分配：按库存可用性、运费成本、时效承诺、货权归属、买家地区匹配度选择发货仓；支持优先级与兜底策略。
- **输入**：分仓规则配置；订单收货信息；各仓库存与运费估算。
- **输出**：分配结果（发货仓 + 分配数量）；无法分配的异常挂起。
- **关系**：上游 = 7.1.1.3 可用量、10 运费试算；下游 = 9.3.3.1、8 出库单。**货权与成本要参与分仓决策**：从 A 法人的仓发货意味着收入记在 A 法人，不能只看运费便宜。

### 9.3.2.2 FBA 与自发货选择

- **职责**：在平台仓（FBA/MFN）与自有/第三方仓之间选择履约路径：优先用平台仓（买家体验好）、平台仓缺货时切自发货（需符合平台的多渠道配送要求）、或按成本优先。
- **输入**：各渠道库存；平台多渠道配送权限；成本与时效对比；平台规则。
- **输出**：履约路径决策 + 缺货时切换记录。
- **关系**：上游 = 7.1.3.1 多仓分布、2.1.1.2 能力矩阵；下游 = 9.3.3.1、10 物流。**平台仓缺货自动转自发货是高价值能力**，但受平台政策约束，必须先验证该店铺的多渠道配送资质。

### 9.3.3.1 履约请求

- **职责**：编排一次履约：锁定预占 → 生成出库单 → 编排作业 → 跟踪完成；持久化流程状态，支持断点恢复与超时重试。
- **输入**：分仓与拆合单结果；库存预占指令；`expected_version`。
- **输出**：履约请求 + 出库单 + 流程状态记录 + 事件（下游消费）。
- **关系**：上游 = 9.3.1/9.3.2；下游 = 8.3.1 出库单、7.2 预占、10 物流下单。**流程状态必须持久化**，不能只放内存——断电重启后要能继续（实体目录 trade 段）。

### 9.3.3.2 履约流程监控

- **职责**：监控履约流程的异常与超时：预占失败、库存不足、流程卡在某步、超时未发货，提供重试、切换路径、人工介入入口。
- **输入**：履约流程状态；超时阈值配置。
- **输出**：异常流程清单 + 处置操作 + 处置记录。
- **关系**：上游 = 9.3.3.1；下游 = 1 工作台待办、7.2.1.3 释放。**超时不是失败**：流程卡住时先查证再决定重试或释放预占，否则会出现"重试造成重复发货"。

### 9.4.1.1 待发货

- **职责**：待发货订单看板：按仓库、承运渠道、承运商、发货时限分组展示，支持批量申请运单号、批量打单、批量交接。
- **输入**：已完成打包的出库单；发货时限要求（平台 SLA）。
- **输出**：待发货清单 + 批量操作任务。
- **关系**：上游 = 8.3.3.2；下游 = 10 物流下单、8.3.4.1 交接。**按承运商分组是大促期效率关键**，混在一起会导致交接混乱。

### 9.4.1.2 发货记录

- **职责**：查询已发货记录：包裹、运单号、承运商、发货时间、轨迹状态、买家可见状态、平台回传状态。
- **输入**：筛选条件；发货事件。
- **输出**：发货记录列表 + 明细。
- **关系**：上游 = 8.3.4.1；下游 = 10 轨迹、9.4.2.1 回传。**发货记录是平台绩效指标的计算依据**（迟发率、有效追踪率）。

### 9.4.2.1 平台回传

- **职责**：把发货信息（运单号、承运商、发货时间）回传平台并跟踪结果：成功/失败/结果未知；支持批量重试与人工修正。
- **输入**：发货事件；`idempotency_key`；平台回传接口。
- **输出**：回传任务与状态（经 2 队列）；平台侧确认状态。
- **关系**：上游 = 8.3.4.1、9.3.1.2；下游 = 2.5.1.1。**回传失败会导致平台显示未发货并可能判定迟发**，因此回传状态必须可监控可补偿；结果未知要先查证再重发。

### 9.5.1.1 时效分析

- **职责**：统计订单时效分布：下单到出库、出库到交接、承诺到货 vs 实际到货，按店铺、仓库、商品、承运商维度拆解。
- **输入**：各环节时间戳；承诺时效配置；轨迹实际时间。
- **输出**：时效报表 + 分维度对比 + 超时明细。
- **关系**：上游 = 9.4.1.2、10 轨迹；下游 = 13 分析、16 合规（绩效指标）。**时效是平台算法权重项**，超时会持续压低自然流量。

### 9.5.2.1 履约质量

- **职责**：统计履约质量：发货及时率、完整发货率、错发漏发率、取消率、纠纷率、退货率，按店铺与人员维度对比。
- **输入**：订单履约与售后数据；平台绩效指标同步。
- **输出**：质量指标卡 + 明细下钻。
- **关系**：上游 = 9.4、11 售后；下游 = 17 绩效、16 账号健康。**纠纷率与订单缺陷率直接关联账号安全**，需要与 16 联动预警。

### 9.6.1.1 代发模式配置

- **职责**：配置店铺/SKU 是否走代发（一件代发），以及代发供应商、结算方式（下单/确认收货后结算、差价抽成）、可售校验规则；区分"自营发货"与"供应商直发"两种履约路径。纯代理代发不占用自有仓库存；其他直发模式的货权与结算规则须单独确认。
- **输入**：店铺/商品代发标记；供应商与结算规则；可售校验（供应商库存是否足够）。
- **输出**：代发模式生效配置；代发可售标记（决定是否可售、是否可刊登）。
- **关系**：上游 = 2.3.1 店铺、3.6.2 供应商报价、7.1.1.3（代发不查自有库存）；下游 = 9.6.1.2。**物流路径与货权分开判断**：不经自有仓不代表不承担货权；只有已确认的纯代理模式才适用不记我方库存，其他模式与 7.7 货权规则联合评审。

### 9.6.1.2 代发单与供应商下单

- **职责**：买家下单后，自动/手工向 1688 等供应商代发平台下单，传递地址与商品信息，回填供应商单号与代发成本，计算我方差价毛利。
- **输入**：已付款代发订单；供应商代发接口或人工录入；代发成本（采购价 + 供应商运费）。
- **输出**：代发单（供应商、单号、发货状态）；差价成本；差异告警（供应商无货/涨价/失败）。
- **关系**：上游 = 9.6.1.1、9.1 订单；下游 = 9.6.1.3 跟踪、12 财务（差价结算）、10 物流（取供应商运单号）。**供应商涨价或无货必须显式告警**，否则差价转负的订单会静默亏损。

### 9.6.1.3 代发履约跟踪与异常

- **职责**：跟踪代发订单的供应商发货与妥投状态，同步供应商运单号回传平台，处理代发异常（延迟、丢件、供应商跑单），并把"我方"与"供应商"两段物流在订单上分开呈现。
- **输入**：供应商发货/物流状态（接口或录入）；平台回传结果。
- **输出**：代发履约状态；异常清单 + 处置（催供应商/改自营发货/退款）。
- **关系**：上游 = 9.6.1.2；下游 = 2.5.1.1 回传、11 售后、10.3 轨迹。**代发模式下"及时发货"是供应商责任但平台考核算我方**，因此异常必须可发现可切换，否则直接掉绩效。

### 9.6.2.1 代发差价与对账

- **职责**：管理代发业务的成本与结算：代发采购成本（供应商结算价 + 供应商运费）、我方售价、差价毛利；按周期与供应商对账，识别亏损代发单（售价低于代发成本+平台费）并预警。
- **输入**：代发单成本与售价（9.6.1.2）；平台费用规则（5.2.3.1）；供应商结算周期。
- **输出**：代发差价与毛利报表（按店铺/供应商/SKU）；供应商对账单（→ 12 应付）；亏损单预警。
- **关系**：上游 = 9.6.1.2、5 定价；下游 = 12.1.2.1 应付、13.4.1.2 利润。**代发模式的"成本"是采购差价而非自有库存成本**，利润口径与自营不同，13 利润报表需按经营模式分组呈现（13.4.1.1 已含模式维度），否则代发店铺利润会被算错。

### 9.7.1.1 批发订单与账期

- **职责**：支持 B2B/批发订单：客户分级价、起订量、阶梯价、账期结算（不即时收款）、开票与对账；与零售订单在订单类型、收款方式、成本口径上区分。
- **输入**：B2B 订单录入；客户分级与账期（3.6.1.2）；阶梯价（3.6.2 / 05 价目）。
- **输出**：批发订单 + 应收（按账期，12 应收）；开票需求。
- **关系**：上游 = 3.6.1.2 客户档案、05 价目；下游 = 12.1.1 应收、12.6.2 发票。**B2B 未发货不产生应收但发货确认为应收**，与零售"平台先收款后发货"现金流方向相反，资金计划需分开（12.1.2.2）。

### 9.7.1.2 经销与分销管理

- **职责**：管理经销商/分销商：授权区域与产品线、授权期限、经销价与返点、销量配额与回款考核、窜货监控（跨区域销售预警）。
- **输入**：经销商档案与授权（区域/品类/期限/价格）；经销订单；销量与回款。
- **输出**：经销授权台账；配额完成率；返点计提；窜货预警。
- **关系**：上游 = 3.6.1.2、16 合规（授权）；下游 = 12 应付/返点、13 分析、5 定价。**经销返点是应收外的负债性承诺**，需与财务确认计提口径；窜货预警可复用 5.5.2 的站点价差倒挂逻辑。
