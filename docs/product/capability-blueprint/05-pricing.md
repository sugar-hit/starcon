# 05 定价与价目系统

> **定位**：回答"这个 SKU 在这个店铺应该卖多少钱"。向上给出**利润底线**，向下从**真实成本**倒推。
> **后端归属**：`catalog` 服务拥有 `price_list` `price_list_item`；成本与汇率来自 `finance`，本系统只读引用。
> **前端入口**：`/pricing`

## 边界

**做**：价目表与价目项、适用范围（法人/店铺/站点）、成本构成与到岸成本、汇率管理、利润测算、保本价与目标毛利价、价格规则与调价、平台价格回写。

**不做**：不维护成本账（属 12 财务）、不执行发货、不做促销活动的平台侧创建（属 14）。

**关键约束**：
- **成本来自 12 的真实成本核算结果**，不手工拍脑袋填——手填成本是利润失真的第一大来源
- 汇率必须**记录在单据上**（含使用哪天的汇率、什么舍入方式）
- 价格计算全程 `BigDecimal`，明确币种与舍入责任方
- 调价到平台是**幂等回写**，不因重试产生错价

## 详细设计

### 5.1.1.1 价目表列表

- **职责**：管理价目表（如"北美自发货零售价"），每张表绑定一个币种、适用法人/店铺/站点、生效区间，展示表内价目项数量与最近更新时间。
- **输入**：价目表增删改；币种与适用范围选择；生效区间设置。
- **输出**：价目表记录 + 覆盖范围摘要。
- **关系**：上游 = 5.1.2.1；下游 = 5.1.1.2 价目项、5.3.2.1 定价模板。**一价目一币种**是硬约束——混币种的价目表会让利润计算失效。

### 5.1.1.2 价目项批量维护

- **职责**：在价目表内维护 SKU 价格，支持按分类/品牌/SKU 范围批量设价、阶梯价（按数量门槛）、Excel 导入导出，保存前预览影响范围。
- **输入**：价目项录入/批量操作（固定值、按百分比、按类目统一）；`price_list_item` 记录。
- **输出**：价目项记录（SKU、单价、货币、数量门槛、生效区间）；导入校验报告。
- **关系**：上游 = 5.1.1.1、3.1.2.1 SKU；下游 = 5.3 测算、5.4 调价。**同优先级多条有效价目必须报错让用户选**，不随机取（实体目录 catalog 价格规则）。

### 5.1.2.1 优先级与冲突检测

- **职责**：定义多张价目表的适用优先级，保存时检测冲突（同 SKU + 同店铺 + 同站点 + 同时段生效的多个价目），冲突即拒绝并列出冲突明细。
- **输入**：适用范围配置（法人/店铺/站点）；现有生效价目集合。
- **输出**：冲突检测结果；最终的生效价目解析规则。
- **关系**：上游 = 5.1.1.1；下游 = 5.3.1.1、5.4 调价。**这是价格正确性的守门员**：允许多价目但必须能唯一解析出"这个 SKU 在这个店铺此刻该卖多少"。

### 5.2.1.1 成本构成

- **职责**：展示并维护 SKU 的单位成本构成：采购成本、头程分摊、包装成本、关税、其他直接成本。采购成本来自 06 采购的实际单价（按成本法加权），其他项来自参数或手工调整。
- **输入**：成本法选择（移动加权/先进先出/批次）；12 财务的成本核算结果；手工调整项及原因。
- **输出**：单位成本明细（分项 + 合计 + 生效时间）；成本变动历史。
- **关系**：上游 = 06 采购、12 财务、10 头程费用；下游 = 5.3.1.1 测算、13 利润。**成本口径必须在页面上明示用了哪种成本法**，否则同一 SKU 今天显示毛利 30% 明天 25% 无法解释。

### 5.2.1.2 到岸成本

- **职责**：计算"货到目标仓可售"的总成本 = 采购价 + 国际头程 + 关税 + 清关 + 目的地操作费 + 尾程预备，用于海外仓/FBA 定价。
- **输入**：批次/货件的采购明细；头程费用（10 物流与头程）；税率与清关费参数（16 合规）。
- **输出**：按 SKU/批次的到岸单位成本；不同目的地的成本对比。
- **关系**：上游 = 6 采购、10 头程、16 税务参数；下游 = 5.3.1.1。**到岸成本与仓库成本是两个口径**（海外仓 vs 自发货），定价时必须选对，否则自发货商品按海运成本定价会低估。

### 5.2.1.3 成本分摊

- **职责**：把混合成本的货件（一次采购多个 SKU 共用头程）按重量/体积/金额/数量规则分摊到各 SKU，支持人工微调并留痕。
- **输入**：货件成本总额；分摊规则；人工调整值与原因。
- **输出**：分摊明细（每 SKU 分摊金额）；重算与差异对比。
- **关系**：上游 = 10 头程费用、12 landed_cost_allocation；下游 = 5.2.1.1 成本构成、13 利润。**分摊规则变更会导致历史利润变化**，因此调整必须留历史版本，不能就地覆盖。

### 5.2.2.1 汇率查询

- **职责**：查询各币种对各本位币的汇率（来源：中行/央行/平台结算汇率，可配置），展示汇率日期与来源，支持手动录入特定日期的汇率。
- **输入**：币种对与日期；汇率来源配置；手工汇率录入。
- **输出**：汇率记录（汇率、方向、生效日期、来源）。
- **关系**：上游 = 外部汇率源；下游 = 5.2.2.2、5.3 测算、12 财务。**汇率方向必须显式**（1 USD = X CNY 与 1 CNY = X USD 混淆是常见错源）。

### 5.2.2.2 汇率快照

- **职责**：在单据/定价生效时冻结所用汇率，保留换算过程（原价、汇率、舍入方式、目标币金额），保证历史利润可复算。
- **输入**：定价/单据生成时的汇率；舍入规则配置。
- **输出**：汇率快照记录；利润复算能力。
- **关系**：上游 = 5.2.2.1；下游 = 09 订单、12 财务、13 利润。**汇率快照是利润可追溯的前提**：今天汇率变了不能让上个月的利润报表数字跟着变。

### 5.2.3.1 平台费用

- **职责**：维护平台侧费用的计算规则：佣金比例或阶梯、订阅费分摊、Referral Fee、交易费、罚款类型，用于利润测算的扣项。
- **输入**：平台费用规则配置（按平台/站点/类目）；实际费用的历史值用于校准。
- **输出**：费用规则；测算时的费用项。
- **关系**：上游 = 2 平台目录；下游 = 5.3.1.1 测算、13 利润、14 广告。**规则参数用于事前测算，实际费用来自 12 的结算对账**——两者差额要在利润报表中显性展示为"费用差异"，否则测算永远不准却不知道为什么。

### 5.2.3.2 物流与头程费用

- **职责**：维护物流渠道的计费规则（按重量/体积/件数、燃油附加、旺季附加、偏远附加）与头程费用结构，用于测算运费占成本比。
- **输入**：渠道计费规则；附加费参数；头程运输方式费用。
- **输出**：费用规则集；测算输入。
- **关系**：上游 = 10 物流与头程；下游 = 5.3.1.1。**渠道规则与 10 的实际运费是两套数据**：规则用于事前测算，实际用于事后核算，差异归入费用差异。

### 5.3.1.1 利润测算器

- **职责**：输入 SKU + 目标店铺 + 售价，输出完整利润拆解：售价 → 平台费用 → 物流成本 → 采购成本 → 头程 → 其他 → 毛利额与毛利率；反向支持输入目标毛利率倒推可承受售价。
- **输入**：SKU、店铺、币种、售价或目标毛利率、数量（用于阶梯与运费）；成本、费用规则、汇率快照。
- **输出**：利润瀑布图 + 保本价 + 目标毛利价 + 盈亏平衡销量；参数可分享为方案。
- **关系**：上游 = 5.2 全部、6 采购成本、2 平台参数；下游 = 5.3.2.1 模板、5.4 调价。**这是定价决策的核心工具**，必须显式列出每一项扣减并允许展开查看来源，不能只给一个毛利率数字。

### 5.3.1.2 批量测算

- **职责**：对一批 SKU 批量测算，按当前成本与规则输出利润表，标记亏损品与低毛利品，支持导出并筛选（毛利率 < X%、售价 < Y）。
- **输入**：SKU 范围（按分类/品牌/店铺）；测算参数。
- **输出**：批量测算结果表 + 异常标记。
- **关系**：上游 = 5.3.1.1；下游 = 5.4.1.2 批量调价。**批量测算是选品与清库存决策的依据**：亏损品要么涨价要么清仓，人工逐个测算不可行。

### 5.3.2.1 定价模板

- **职责**：沉淀定价策略模板：成本加成、固定毛利、竞品跟随（若允许）、按站点差异化、按库存周转调整，新品与老品用不同模板。
- **输入**：模板定义（基准 + 调整项）；适用对象（分类/品牌/店铺）。
- **输出**：模板记录；一键应用到商品生成建议价。
- **关系**：上游 = 5.3.1.1；下游 = 5.4.1.1 调价。**模板与价目表的关系**：模板是"怎么算"，价目表是"算完是多少"。

### 5.3.2.2 价格规则

- **职责**：定义自动调价规则：触发条件（库存低于阈值/竞品降价/成本上涨/毛利低于下限/库龄超期）+ 动作（降价/涨价/暂停促销/下架），支持优先级与生效时段。
- **输入**：规则条件与动作；作用范围；生效时段。
- **输出**：规则记录 + 命中记录 + 建议调价列表。
- **关系**：上游 = 7 库存、5.3.2.1；下游 = 5.4.1.1。**自动调价必须先"建议"再"执行"**，高风险规则（降价超过 X%）需人工确认，避免错误规则批量改价造成损失。

### 5.4.1.1 调价单

- **职责**：发起价格变更：选择 SKU 与目标店铺、输入新旧价、说明原因、提交审批（若启用）；记录变更前后值。
- **输入**：调价请求；`expected_version`；审批要求（17 组织的审批规则）。
- **输出**：调价单（草稿/待审/已批/已执行/已驳回）；生效后触发平台回写。
- **关系**：上游 = 5.3.1.1、5.3.2.2；下游 = 5.4.2.1、17 审批。**调价是受控动作**：大额或大幅调价走审批，普通调整可配置免审。

### 5.4.1.2 批量调价

- **职责**：对选中的一批 listing 统一改价（固定金额/百分比/按模板），支持预览影响范围（涉及多少店铺、多少商品、预计利润变化）。
- **输入**：目标集合；调价参数；预览确认。
- **输出**：批量调价单 + 影响预览报告。
- **关系**：上游 = 5.3.1.2、4.1.1.1；下游 = 5.4.2.1。**必须先看预览再执行**，预览要包含"改完后预计亏损的商品数"这类反向指标。

### 5.4.2.1 平台价格同步

- **职责**：把生效价格回写到平台，处理平台定价规则（平台可能有最低价/自动比价/多站点联动），记录回写结果与被平台调整后的实际价。
- **输入**：价格变更事件；平台定价规则；`idempotency_key`。
- **输出**：回写任务（经 02 队列）；实际价与期望价的差异记录。
- **关系**：上游 = 5.4.1.1/5.4.1.2；下游 = 2.5.1.1 平台操作。**平台可能拒绝或调整价格**（如低于最低价触发），差异必须显性反馈，不能假设回写即成功。

### 5.5.1.1 价格历史

- **职责**：记录 SKU/listing 的价格变更历史（时间、旧价、新价、操作人/来源、原因），支持按时间轴回溯并对比同期销量利润变化。
- **输入**：价格变更事件（人工与自动规则都记）；查询条件。
- **输出**：价格时间轴 + 关联的销售/利润变化。
- **关系**：上游 = 5.4.1、5.3.2.2；下游 = 13 分析。**价格历史 + 销量 + 利润三者对齐，才能回答"降价到底有没有用"**。

### 5.5.2.1 异常告警

- **职责**：监测价格异常：平台价与内部价长期不一致、售价低于成本线、平台自动降价、多站点价格倒挂（同商品不同站点价差导致窜货）。
- **输入**：平台价回流；内部价；成本线；站点价差规则。
- **输出**：异常清单 + 预警通知。
- **关系**：上游 = 4.3.2.2、5.2.1.1；下游 = 1 工作台预警、16 合规（窜货风控）。**站点价差倒挂是跨境特有的风险**：德国站定价低于美国站会引发跨区窜货与合规问题。
