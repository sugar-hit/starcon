# 12 财务核算系统

> **定位**：starcon 的**账**。钱的进出、对得上、算得准。企业最终信不信这套 ERP，看的是这里。
> **后端归属**：`finance` 服务（唯一拥有应收应付、收付款、对账、成本、总账、发票税务）。
> **前端入口**：`/finance`

> 评审提示：本文为能力蓝图。代发的货权/资金政策、财务确认与关账规则须在对应 PRD 中确认；未决项见 [业务设计审查](../../backlog/2026-09-30-business-design-review.md)。不能将经营形态直接等同于会计政策。

## 边界

**做**：应收应付、收付款与核销、平台结算对账、费用归集与分摊、成本核算与利润结转、总账与凭证、发票与税务、税务合规（VAT/IOSS/销售税）、资金账户与对账。

**不做**：不把订单状态当资金流水（未发货订单不等于收入）、不改数量账（属 07）、不自己定会计政策（政策由用户确认）。

**关键约束**：

- 金额一律 `BigDecimal` + `NUMERIC`，**禁止浮点**
- **汇率快照**必须留在单据上，今天汇率变了不能让上月报表变
- 凭证过账后**不可改行**，只能红冲；过账事务需锁头、校验平衡与期间开放
- 平台账单**不强制每行都有订单**（佣金、罚款、调整类无订单行）
- 成本算法（先进先出/移动加权/批次）由用户选定，**系统不替用户决定会计政策**

## 详细设计

### 12.1.1.1 应收单管理

- **职责**：管理应收账款：来源（平台结算、平台代扣、B2B 客户账期、其他）、应收对象、金额与币种、到期日、账龄、明细核销状态。
- **输入**：应收确认规则（什么业务确认为应收）；结算数据；B2B 订单发货确认；人工录入。
- **输出**：应收单 + 明细行 + 账龄分布；生成催收任务。
- **关系**：上游 = 12.3.1 结算、9 订单（发货确认）；下游 = 12.2.1.2 核销、13 分析。**未发货订单不默认等于收入**——应收确认政策需单独配置（实体目录 finance 段明确）。

### 12.1.1.2 应收账龄

- **职责**：按账龄区间（未到期/1-30/31-60/61-90/90+）统计应收分布，支持按店铺、客户、币种维度查看，识别逾期集中风险。
- **输入**：应收单集合；账龄区间配置。
- **输出**：账龄分布报表 + 逾期清单。
- **关系**：上游 = 12.1.1.1；下游 = 1.3 催收预警、12.1.1.3。**跨境应收的最大风险是平台争议冻结**，账龄报表需单独标识"争议中"金额。

### 12.1.1.3 坏账与核销

- **职责**：处理坏账：争议损失确认、买家拒付、平台冻结无法收回的核销，保留核销依据与审批。
- **输入**：核销申请；依据材料；审批。
- **输出**：坏账核销记录 + 会计处理 + 审计留痕。
- **关系**：上游 = 12.1.1.2、11.4.1.1 纠纷；下游 = 12.5.2.1 凭证。**核销是财务终审动作**，需要完整依据链，不允许批量一键核销无审批。

### 12.1.2.1 应付单管理

- **职责**：管理应付账款：来源（采购收货、供应商对账、物流费用、平台费用、其他）、应付对象、金额与币种、到期日、已付金额与未付余额。
- **输入**：采购收货确认（8.2.1.1）；服务费用（物流、平台、广告）；供应商对账单（6.5.1）；人工录入。
- **输出**：应付单 + 明细 + 未付清单。
- **关系**：上游 = 6 采购、10 物流、14 广告；下游 = 12.2.2.1 付款。**应付、预付款与采购承诺分开建模**；确认依据由业务合同和已批准政策决定，不能仅凭下单或收货统一推导。

### 12.1.2.2 付款计划

- **职责**：按付款条件（账期、里程碑、到期日）生成付款计划与到期提醒，支持按供应商与到期窗口批量安排付款。
- **输入**：应付到期日；账期规则；资金计划。
- **输出**：付款计划表 + 到期提醒 + 资金需求预测。
- **关系**：上游 = 12.1.2.1；下游 = 12.2.2.1、1.3 提醒。**付款计划与资金预测联动**：跨境资金常有回款延迟与付款刚性，错配会导致现金流断裂。

### 12.1.2.3 供应商对账

- **职责**：财务侧供应商对账：核对采购侧对账单（6.5.1）与收货/质检数据，差异处理与确认，最终生成应付依据。
- **输入**：供应商对账单；收货与质检明细；差异说明。
- **输出**：对账确认结果 + 差异清单 + 应付生成依据。
- **关系**：上游 = 6.5.1 采购发起；下游 = 12.1.2.1 应付。**财务是最终确认方**，采购不能自行确认应付——这是职责分离。

### 12.2.1.1 收款单

- **职责**：登记与跟踪资金收入：平台回款、银行到账、PayPal/Stripe/PingPong 等第三方支付到账、其他收入；记录资金账户、金额币种、到账时间与来源。
- **输入**：到账流水导入或手工登记；结算数据。
- **输出**：收款单 + 未核销余额。
- **关系**：上游 = 12.3.1 结算；下游 = 12.2.1.2 核销、12.7.1 资金账户。**一笔收款可核销多笔应收**（合并回款），也可能是预收。

### 12.2.1.2 核销

- **职责**：把收款核销到应收：自动匹配（金额+订单号+日期）或人工指定，支持部分核销、合并核销、预收挂账、核销撤销。
- **输入**：收款单；待核销应收；匹配规则或人工分配。
- **输出**：核销记录 + 应收余额更新 + 预收余额。
- **关系**：上游 = 12.2.1.1、12.1.1.1；下游 = 13 利润（回款口径）。**核销必须精确到明细行**，只核销到订单头无法处理部分回款与折让。

### 12.2.2.1 付款单与审批

- **职责**：发起付款申请：选择应付明细、付款账户、币种与汇率、付款方式、分批安排，走分级审批。
- **输入**：付款申请；审批规则（金额阈值）；汇率快照。
- **输出**：付款单（草稿/待审/已批/执行中/已付/失败）+ 审批记录。
- **关系**：上游 = 12.1.2.1、12.1.2.2；下游 = 12.2.2.2、17 审批。**付款审批是资金安全的第一道控制**，大额付款必须双人复核或多级审批。

### 12.2.2.2 付款执行

- **职责**：执行付款：对接支付渠道/银企直连，发送付款指令，跟踪结果，失败重试与异常处理；处理汇率锁汇。
- **输入**：已批付款单；支付渠道配置（密钥引用）；汇率锁定。
- **输出**：付款结果 + 渠道流水号 + 失败原因。
- **关系**：上游 = 12.2.2.1；下游 = 12.7.1 资金账户、12.5.2 凭证。**外部支付超时不等于失败**，必须先查证再重发——重复付款是严重资损事故。

### 12.3.1.1 结算单管理

- **职责**：管理平台结算单：结算周期、店铺、平台账单汇总（销售额、退款、佣金、FBA 费用、广告费、赔付、其他调整）、结算金额、到账状态。
- **输入**：平台结算报告同步（2 同步）；人工上传账单；结算周期配置。
- **输出**：结算单 + 汇总项 + 明细行 + 与我方账的差额。
- **关系**：上游 = 2 渠道与店铺；下游 = 12.3.2.1 对账、12.2.1.1 收款、13 利润。**平台账单是财务事实的重要外部来源**，需保留原始文件与解析版本。

### 12.3.1.2 交易明细

- **职责**：管理结算单下的逐笔明细：订单销售、退款、费用（佣金/仓储/配送/广告）、赔付、调整、代扣税，保留外部流水号与币种；**允许无订单行的费用类明细**。
- **输入**：平台交易报告解析结果；`idempotency_key`。
- **输出**：明细行 + 汇总校验（明细合计 = 结算单汇总）。
- **关系**：上游 = 12.3.1.1；下游 = 12.3.2.1 对账、13 利润。**不强制每行都有订单**是硬约束——佣金、罚款、月度调整天然无订单行，硬要匹配会产生大量虚假异常。

### 12.3.1.3 延迟结算

- **职责**：管理平台延迟结算（部分平台按周期后结算或滚动结算）：单列在途未结算金额、结算条件、预计到账时间，支持查询"订单已发货但钱未到账"的明细。
- **输入**：结算规则；订单与结算状态。
- **输出**：延迟结算明细 + 在途资金统计 + 预计到账时间。
- **关系**：上游 = 12.3.1.1、9 订单；下游 = 13 利润（按已结算/未结算区分口径）。**延迟结算是跨境特有的资金口径问题**：利润报表必须能同时看"已结算利润"和"订单口径利润"，否则运营会误判。

### 12.3.2.1 对账任务

- **职责**：发起与执行对账任务：选择对账范围（店铺 + 周期 + 账户）、运行自动匹配、输出匹配结果与差异。
- **输入**：对账范围；我方账数据（结算、应收、应付、银行流水）；平台账单。
- **输出**：匹配结果（一对一、一对多、多对一）+ 差异清单。
- **关系**：上游 = 12.3.1.1、12.7.1.2；下游 = 12.3.2.2。**不允许"金额相同即匹配"**（实体目录 finance 段硬约束）——金额相同只是候选，必须结合订单号、日期、类型。

### 12.3.2.2 差异处理

- **职责**：处理对账差异：分类（我方多记/对方多记/时间差/汇率差/手续费遗漏）、指定责任人、人工判定与调整、闭环跟踪。
- **输入**：差异明细；处理结论；调整凭证或说明。
- **输出**：差异处理记录 + 调整分录 + 闭环状态。
- **关系**：上游 = 12.3.2.1；下游 = 12.5.2 凭证、1.3 预警。**差异分类是改进闭环的输入**：某类差异反复出现说明上游流程有系统性问题。

### 12.3.2.3 自动匹配规则

- **职责**：配置对账自动匹配规则：匹配键（订单号 + 金额 + 日期 + 类型）、容差（汇率差、手续费）、优先级、模糊匹配兜底，配置匹配率目标与监控。
- **输入**：规则配置；历史对账结果用于规则调优。
- **输出**：规则集 + 匹配率统计 + 未匹配原因分布。
- **关系**：上游 = 12.3.2.1；下游 = 匹配引擎。**匹配率是财务自动化的核心指标**，持续低于目标时应排查上游数据质量而非调规则。

### 12.4.1.1 计价方法配置

- **职责**：配置成本计算方法（先进先出/移动加权平均/批次成本/指定成本法），按法人或品类设置，确定生效时间。
- **输入**：计价方法选择；生效时间；适用范围。
- **输出**：生效的成本方法配置。
- **关系**：上游 = 用户会计政策决定；下游 = 12.4.1.2、13 利润。**系统提供选项与试算，不替用户决定政策**；切换方法需重算并留版本对比。

### 12.4.1.2 成本计算执行

- **职责**：执行成本计算：对销售出库、发货、平台仓转出计算应结转成本，生成成本层与成本分录；支持按期间批量重算与差异对比。
- **输入**：库存流水（7.1.2.1）；计价方法；成本层数据；计算期间。
- **输出**：成本计算结果（成本层 + 结转金额）+ 差异对比。
- **关系**：上游 = 7 库存流水、12.4.1.1；下游 = 13 利润、12.5.2 凭证。**数量账在 warehouse、价值账在 finance**——这是两个服务的职责划分，重算不能写库存。

### 12.4.1.3 成本差异分析

- **职责**：分析成本差异：实际成本 vs 预算/标准成本、采购价波动、头程成本波动、损耗差异、汇率影响，定位利润波动主因。
- **输入**：成本计算结果；预算或历史基线；价格与汇率历史。
- **输出**：差异分析报表 + 主因归因 + 异常提示。
- **关系**：上游 = 12.4.1.2；下游 = 13 分析、6 采购（价格谈判依据）。**利润下滑时先看成本差异**，比看销售额更能定位问题。

### 12.4.2.1 费用归集

- **职责**：归集各类费用到指定维度：按月分摊的平台费/订阅费、按单分摊的物流费、按 SKU 分摊的头程费、按期间分摊的人员与办公费用，保留归集依据。
- **输入**：费用来源（平台、物流、订阅、人工录入）；分摊目标维度。
- **输出**：归集明细（费用项 → 分摊对象 → 金额）。
- **关系**：上游 = 12.3.1.2、10 物流、14 广告；下游 = 12.4.2.2。**归集与分摊要分开**：先按规则归集费用池，再按维度分摊，便于核对与调整。

### 12.4.2.2 分摊规则

- **职责**：配置费用分摊规则：分摊维度（SKU/SPU/店铺/订单/类目）、分摊基数（数量/金额/重量/体积/等额）、生效区间、分摊顺序与舍入差处理。
- **输入**：规则配置；待分摊费用池。
- **输出**：分摊结果（保留舍入差额到指定对象）+ 分摊明细。
- **关系**：上游 = 12.4.2.1；下游 = 13 利润（SKU 利润）。**分摊结果之和必须等于被分摊总额**（含舍入差处理），否则利润报表总额对不上——这是财务最不能接受的错误。

### 12.5.1.1 会计科目

- **职责**：维护法人账簿的会计科目表：科目编码、名称、类别（资产/负债/权益/成本/损益）、余额方向、是否明细科目、关联税务属性；支持科目映射到业务事件。
- **输入**：科目定义；业务事件映射（如发货 → 收入 + 结转成本）。
- **输出**：科目表 + 映射规则。
- **关系**：上游 = 用户会计体系；下游 = 12.5.2.1 凭证、12.5.2.2 报表。**科目体系是用户自定的**，系统提供模板但必须允许完全自定义。

### 12.5.1.2 会计期间

- **职责**：管理会计期间（自然月或 4-4-5 fiscal 周期）：期间状态（开放/关闭）、关账与重开、期间内凭证限制。
- **输入**：会计日历配置；关账/重开操作；审批。
- **输出**：期间状态；关账记录。
- **关系**：上游 = 会计日历；下游 = 12.5.2.1 凭证（已关闭期间禁止过账）。**重开已关期间是高风险操作**，必须审批留痕。

### 12.5.1.3 关账

- **职责**：期末关账流程：检查未处理事项（未对账差异、未结转成本、未核销款项、未过账凭证），按已批准清单区分阻断项与可结转未清项后关闭期间；禁止向已关闭期间录入业务凭证。
- **输入**：关账检查清单结果；关账确认。
- **输出**：关账完成记录；期间锁定。
- **关系**：上游 = 12.5.1.2；下游 = 12.5.2.2 报表。**关账检查清单是防错最后一道关**：阻断项未解决不允许关账；正常未到期应收应付不要求清零，例外与结转须保留依据。

### 12.5.2.1 凭证管理

- **职责**：生成与管理会计凭证：由业务事件自动生成或手工录入，支持过账、校验（至少两行、金额有效、期间开放、借贷平衡）与红冲；已过账凭证不得反过账后改写，导出标准凭证文件。
- **输入**：业务事件（发货、收货、收付款、费用计提）；手工凭证；`expected_version`。
- **输出**：凭证 + 分录行 + 过账状态；审计记录。
- **关系**：上游 = 全部业务系统事件；下游 = 12.5.2.2 报表。**过账后不可改行，只能红冲**；过账事务要锁凭证头并在数据库层防护（实体目录 §9 明确触发器要求）。

### 12.5.2.2 财务报表

- **职责**：生成财务报表：资产负债表、利润表、现金流量表、科目余额表、明细账，支持期间对比、导出、钻取到凭证。
- **输入**：已过账凭证；期间范围；报表模板。
- **输出**：报表 + 钻取路径 + 导出文件。
- **关系**：上游 = 12.5.2.1；下游 = 17 审计、对外报送。**报表数字必须能钻到凭证**，"报表与明细对不上"是财务系统的致命问题。

### 12.6.1.1 税率配置

- **职责**：维护税率配置：目的国/地区的销售税率、VAT 税率、IOSS 适用税率、代扣代缴税；支持按店铺站点绑定默认税率与税码。
- **输入**：税率定义；适用站点；生效时间。
- **输出**：税率记录；供订单与申报引用。
- **关系**：上游 = 2 店铺站点、16 合规；下游 = 9 订单（税额）、12.6.1.2 申报。**税率必须带生效时间**，历史订单用当时税率，不能被新政策追溯修改。

### 12.6.1.2 VAT/IOSS 申报数据

- **职责**：按辖区与周期汇总申报所需数据： taxable 销售额、已收 VAT、IOSS 订单与代collected 金额、可抵扣进项，导出申报文件或对接申报接口。
- **输入**：订单税务数据；结算与收付款数据；汇率快照；辖区规则。
- **输出**：申报底稿 + 汇总报表 + 可导出文件。
- **关系**：上游 = 12.6.1.1、9 订单、12.2.1.1；下游 = 16 合规（申报日历提醒）。**本系统提供申报底稿，不替代税务申报动作**——申报主体与责任在用户，系统保证数据完整可核。

### 12.6.2.1 发票管理

- **职责**：管理销售发票与贷项通知单：按平台/国家模板生成、维护税码税率税额、编号与状态（草稿/开具/作废/红冲），支持批量与平台开票对接。
- **输入**：订单与结算数据；发票模板；编号规则；作废申请。
- **输出**：发票与贷项单 + 编号序列 + 状态记录。
- **关系**：上游 = 9 订单、12.3.1；下游 = 12.5.2.1 凭证、11.4 售后（退货开票调整）。**各国发票要求差异大**，模板必须按国家配置；本系统不承诺覆盖所有国家税务规则。

### 12.7.1.1 账户管理

- **职责**：管理资金账户：银行账户、支付平台账户、平台备付金账户，记录币种、账号、余额、开户主体（法人）、账户类型。
- **输入**：账户定义；余额同步或手工更新；关联法人。
- **输出**：账户档案 + 余额历史。
- **关系**：上游 = 17 法人；下游 = 12.2 收付款、12.7.1.2 对账。**账户必须绑定法人**，跨法人混用资金账户会导致收入归属错误。

### 12.7.1.2 银行对账

- **职责**：导入银行/支付平台流水与系统记录自动匹配，输出未匹配项，支持人工认领与说明，生成对账报告。
- **输入**：流水文件（导入）；系统收支记录；匹配规则。
- **输出**：匹配结果 + 未匹配清单 + 对账报告。
- **关系**：上游 = 12.7.1.1、12.2；下游 = 12.3.2.1 对账。**未匹配项要能认领到具体单据**，否则余额永远平不了——这是财务日常最高频的工作。

### 12.7.2.1 资金分析

- **职责**：资金分析：现金流入流出趋势、各币种资金分布与汇率敞口、资金周转天数、付款集中度与流动性预警。
- **输入**：资金流水；应收应付账期；汇率数据。
- **输出**：资金报表 + 汇率敞口测算 + 流动性预警。
- **关系**：上游 = 12.7.1、12.1.2.2；下游 = 1 工作台。**汇率敞口是跨境特有风险**：大量外币存货 + 本币负债的组合下，汇率波动直接影响利润。
