# 16 合规与风控系统

> **定位**：跨境生意的"刹车系统"。合规出问题不是效率损失，是封店、下架、罚款、罚款乃至账号永久损失。
> **后端归属**：`channel` 服务负责平台账号健康数据；`identity` 负责访问安全与租户隔离；产品与税务合规配置在各自业务系统，本系统提供判定与阻断能力。
> **前端入口**：`/compliance`

## 边界

**做**：账号健康与绩效监控、合规规则库与拦截、税务合规（VAT/IOSS/EPR/销售税）、产品合规与认证、侵权与知识产权、黑名单与风控、防关联与账号安全、数据合规（GDPR）。

**不做**：不替代法务与税务顾问出具意见、不代办平台申诉（提供材料与指引）、不代缴税金。

**关键约束**：
- **阻断类规则必须在服务端强制**，前端提示不构成防线
- 规则要有**生效时间与版本**，规则变更不能追溯改变历史判定
- 合规判定失败的商品不能刊登、不能发货（可按严重度分级）
- 账号安全事件要有**审计与追溯**，涉及密钥与凭据的操作全部留痕

## 详细设计

### 16.1.1.1 账号健康总览

- **职责**：按店铺展示账号健康状态：绩效指标（ODR、迟发率、取消率、有效追踪率）、政策违规计数、申诉状态、风险等级，支持跨店铺对比与风险排序。
- **输入**：平台绩效数据同步；风险等级计算规则；用户数据范围（店铺维度）。
- **输出**：店铺健康卡片 + 风险排序 + 需处理项跳转。
- **关系**：上游 = 2 同步；下游 = 16.1.1.2 指标明细、16.1.2.1 违规。**风险排序比明细更重要**：先处理最可能掉号的店铺。

### 16.1.1.2 绩效指标监控

- **职责**：监控各平台核心绩效指标的趋势与阈值：订单缺陷率、迟发率、取消率、有效追踪率、响应时间、账户评级，支持自定义阈值预警与趋势预测（是否会跌破阈值）。
- **输入**：指标时间序列；阈值配置；预测模型参数。
- **输出**：指标趋势图 + 阈值预警 + 跌破预测。
- **关系**：上游 = 16.1.1.1；下游 = 1 工作台预警、9 订单履约（迟发预警前置）。**预测跌破比已跌破更有价值**——提前几天知道就能提前改。

### 16.1.2.1 违规与处罚

- **职责**：记录与管理平台违规与处罚：违规类型、涉及商品/订单、处罚措施（警告/下架/限制销售/扣款/停号）、处理状态与整改要求。
- **输入**：平台违规通知同步；整改记录。
- **输出**：违规记录 + 整改跟踪 + 扣款金额（进 12 财务）。
- **关系**：上游 = 2 同步；下游 = 12 财务（罚扣款）、4 刊登（问题商品下架）、16.1.2.2 申诉。**违规常涉及多个商品**，需批量定位受影响 listing 与库存。

### 16.1.2.2 申诉管理

- **职责**：管理平台申诉：申诉类型、举证材料收集、申诉文本、提交跟踪、结果记录与申诉次数统计。
- **输入**：违规记录；申诉材料；提交动作。
- **输出**：申诉单 + 提交记录 + 结果（通过/驳回）。
- **关系**：上游 = 16.1.2.1；下游 = 平台申诉接口。**申诉配额有限**，需记录已用次数并优先申诉高影响违规。

### 16.2.1.1 规则库

- **职责**：管理合规规则库：规则类型（违禁词、极限词、侵权词、认证要求、禁限售、标签要求、材质要求）、严重度（阻断/警告/提示）、适用平台与站点、生效时间与版本。
- **输入**：规则定义与词库上传；版本更新；适用范围配置。
- **输出**：规则集 + 生效版本。
- **关系**：上游 = 平台政策同步 + 人工维护；下游 = 16.2.1.2 执行、4.2.3.2 预检。**规则版本化是关键**：政策变化时历史商品的判定结果要可解释，不能因为规则库更新就说过去的商品当时违规。

### 16.2.1.2 拦截执行

- **职责**：在关键业务节点执行合规校验并阻断：刊登发布前、发货前、结算提现前；展示拦截原因与解除方式（提交资质、申请豁免）。
- **输入**：合规规则集；业务动作触发的校验请求（商品/订单/店铺）。
- **输出**：校验结论（通过/警告/阻断）+ 原因 + 解除入口；豁免申请与审批。
- **关系**：上游 = 16.2.1.1；下游 = 4.3.1.1 发布、8.3.4.1 发货、12 提现。**豁免必须有审批与理由**，否则阻断会被随意绕过。

### 16.2.2.1 合规预检

- **职责**：发布前的合规体检：内容违规、认证缺失、尺寸规格不符、材质与描述不符、危险品与运输限制、标签与说明书要求，多维度检查并给出整改建议。
- **输入**：listing 内容草稿；商品属性；认证状态；平台要求。
- **输出**：体检报告（分维度得分 + 问题清单 + 整改建议）。
- **关系**：上游 = 4.2.1.1 编辑器；下游 = 16.2.1.2 拦截。**预检在保存草稿时就跑一次**（即时反馈），发布时再跑一次（强制校验）。

### 16.2.2.2 认证与资质

- **职责**：管理产品认证与资质（CE、FCC、RoHS、PSE、FDA、CCC 等）：认证编号、有效期、适用 SKU、对应类目要求，支持上传扫描件与到期提醒。
- **输入**：认证录入；文件上传；有效期。
- **输出**：认证档案 + 到期提醒 + 覆盖情况统计（哪些 SKU 缺认证）。
- **关系**：上游 = 6.1.2.3 供应商资质；下游 = 16.2.2.1 预检、4 刊登。**认证缺失是listing 被抑制与下架的高频原因**，且属于"上架时不管、出事才补"的典型滞后项。

### 16.3.1.1 税号与辖区

- **职责**：维护各店铺/法人在各销售辖区的税务登记：税号、VAT 状态、是否注册、EPR 注册号、注册有效期与申报周期。
- **输入**：税号录入；辖区选择；有效期。
- **输出**：税务登记档案 + 缺失项提示。
- **关系**：上游 = 17 法人、2 店铺；下游 = 16.3.2.1、12.6 税务。**未注册辖区的销售额是合规炸弹**：欧洲没有 VAT 号还在欧盟销售，是稽查重点。

### 16.3.1.2 申报日历

- **职责**：管理各辖区申报日历：申报周期、截止日、所需数据、状态（未开始/数据就绪/已提交/已确认），到期提醒与责任人。
- **输入**：申报周期配置；辖区要求；12.6.1.2 数据就绪状态。
- **输出**：申报日历视图 + 提醒 + 状态跟踪。
- **关系**：上游 = 16.3.1.1、12.6.1.2；下游 = 1 工作台待办。**漏报罚款远高于系统能提供的价值**，日历提醒是最低成本的合规保障。

### 16.3.2.1 VAT/IOSS

- **职责**：管理 VAT 与 IOSS 制度：适用店铺与商品、申报周期、税率适用、IOSS 订单识别与代收代缴统计、与财务申报数据的对接。
- **输入**：IOSS 配置；订单税务数据；12.6.1.2 申报底稿。
- **输出**：IOSS 订单清单与金额统计；申报状态。
- **关系**：上游 = 12.6.1.1 税率、9 订单；下游 = 12.6.1.2。**IOSS 订单与一般 VAT 订单必须区分统计**，混在一起申报是最常见的错误。

### 16.3.2.2 EPR/包装法

- **职责**：管理 EPR 与包装法合规（德国 LUCID、包装注册、电池法、WEEE 等）：注册号、适用国家与品类、申报周期与关联费用。
- **输入**：注册信息；适用规则；申报数据。
- **输出**：EPR 档案 + 合规状态 + 费用记录。
- **关系**：上游 = 16.3.1.1；下游 = 12 财务（费用）、4 刊登（是否允许在相关国家销售）。**EPR 未注册的国家应直接限制刊登**，这是避免下架与罚款最有效的做法。

### 16.3.2.3 销售税与平台代收

- **职责**：处理美国各州销售税与 Marketplace Facilitator 制度：应缴/代缴状态、州级阈值、免征额、按平台的代扣代缴说明与对账。
- **输入**：店铺所在州数据；平台代扣代缴报表；自营应税销售额。
- **输出**：各州税务状态 + 代扣代缴对账结果。
- **关系**：上游 = 2 店铺、12.3.1.2；下游 = 12.6 申报。**平台代扣代缴不等于免税**，卖家的申报义务依然存在，只是由平台代收代缴，需要正确对账。

### 16.4.1.1 侵权库

- **职责**：维护知识产权风险库：品牌商标、专利、版权、肖像权，登记风险等级与适用平台。
- **输入**：侵权条目登记；批量导入。
- **输出**：侵权库记录。
- **关系**：上游 = 3.3.2 品牌；下游 = 16.4.1.2 检测。**侵权检测是刊登前拦截而非事后申诉**，成本差一个数量级。

### 16.4.1.2 检测与预警

- **职责**：对商品内容做侵权检测：标题/描述/图片/品牌字段比对侵权库，输出风险等级与命中项；接入外部商标/专利查询；已上架商品的定期巡检。
- **输入**：商品内容与图片；侵权库；外部查询结果。
- **输出**：检测报告 + 预警 + 整改建议。
- **关系**：上游 = 16.4.1.1、4.2.1.1；下游 = 16.2.1.2 拦截、16.4.2 授权核验。**图片侵权检测难度高于文本**，误判与漏判都要留人工复核环节。

### 16.4.2.1 品牌授权

- **职责**：管理品牌授权：授权方、授权范围（店铺/国家/类目/期限）、授权文件、被授权主体，校验刊登时的品牌使用是否在授权范围内。
- **输入**：授权录入；文件上传；有效期。
- **输出**：授权档案 + 校验结果。
- **关系**：上游 = 6.1.2.3 供应商资质；下游 = 3.3.2 品牌状态、4.2.3.2 预检。**授权过期是"平时没事、上新时出事"的典型**，需到期提醒与刊登阻断。

### 16.4.2.2 授权凭证

- **职责**：集中存储与核验授权凭证文件：真伪验证记录、文件版本、签署方信息，支持一键核验。
- **输入**：凭证上传；核验操作。
- **输出**：凭证档案 + 核验记录。
- **关系**：上游 = 16.4.2.1；下游 = 16.4.1.2。**凭证需保留原始文件与元数据**，争议时是唯一证据。

### 16.5.1.1 黑名单

- **职责**：维护买家黑名单：买家标识、店铺、原因、风险等级、生效范围（仅本店铺/全店铺），下单时自动标记并可拦截。
- **输入**：黑名单录入（手工/自动，来自风控信号）；解除操作。
- **输出**：黑名单记录；订单拦截标记。
- **关系**：上游 = 16.5.1.2 评分、9.2 审单；下游 = 9.2.1.3 拦截、11 售后。**黑名单应支持申诉解除**，永久不解除会让误判的正常买家永久损失。

### 16.5.1.2 风险评分

- **职责**：计算买家风险分：历史退款率、纠纷率、欺诈特征、地址模式、下单行为、关联账号，输出评分与建议动作。
- **输入**：买家行为数据；风险特征规则；权重配置。
- **输出**：风险评分 + 特征解释。
- **关系**：上游 = 15 客户、11 售后、9 订单；下游 = 16.5.1.1、9.2.2.2。**评分要能解释**（为什么这个买家 80 分），黑盒分数客服无法向平台申诉。

### 16.5.2.1 登录与访问安全

- **职责**：管理平台账号与系统的访问安全：多因子认证、登录审计、异常登录告警、IP 白名单、会话管理；平台授权凭据的访问审计。
- **输入**：认证配置；登录事件；访问审计事件。
- **输出**：安全配置 + 审计记录 + 告警。
- **关系**：上游 = 17 identity；下游 = 2 凭据引用。**平台凭据是最值钱的资产**，访问必须有审计且最小权限。

### 16.5.2.2 关联风险

- **职责**：识别账号关联风险：同一支付方式/收款账户/设备/IP/地址/法人关联的店铺，输出关联图谱与风险提示，提示避免触发平台关联处罚。
- **输入**：店铺与支付/设备/地址/法人关系数据；平台政策要求。
- **输出**：关联图谱 + 风险提示 + 整改建议。
- **关系**：上游 = 2 店铺、12.7.1 资金账户；下游 = 1 工作台预警。**关联封号是跨境多店经营的头号风险**：官方 API 授权是规避关联的关键，本系统只做官方 API，绝不提供任何模拟登录/指纹浏览器能力。

### 16.6.1.1 PII 管理

- **职责**：管理个人信息（买家姓名、地址、电话、邮箱）的访问与脱敏：默认脱敏展示、按角色授权查看完整信息、访问留痕、导出审批。
- **输入**：PII 访问请求；授权配置；导出申请。
- **输出**：脱敏数据或授权后的完整数据；访问审计记录。
- **关系**：上游 = 15 客户、9 订单；下游 = 客服与运营页面。**完整地址查看需留痕**——批量导出 PII 是数据泄露事件的典型形态。

### 16.6.2.1 数据出境与留存

- **职责**：管理数据合规：跨境数据传输登记与合法性基础、数据留存期配置、到期清理与删除请求（被遗忘权）、保留期与财务留存期的区分。
- **输入**：数据流登记；留存策略；删除请求。
- **输出**：合规登记 + 清理/删除执行记录。
- **关系**：上游 = 17 权限、全部数据域；下游 = 数据清理任务。**财务数据有法定留存期，PII 有 GDPR 删除权，两者冲突时按财务留存优先**——实体目录 §5 已明确这条边界。
