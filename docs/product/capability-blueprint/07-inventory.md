# 07 库存核算系统

> **定位**：库存的**账本**。回答"有多少、在哪、属于谁、能不能卖、成本多少"。所有增减都必须留下可核对的分录。
> **后端归属**：`warehouse` 服务（唯一拥有 `stock_bucket` `inventory_balance` `inventory_transaction` `inventory_reservation` `inventory_lot` `inventory_serial` 等）。
> **前端入口**：`/inventory`

> 评审提示：本文为能力蓝图。代发的货权/资金政策、财务确认与关账规则须在对应 PRD 中确认；未决项见 [业务设计审查](../../backlog/2026-09-30-business-design-review.md)。不能将经营形态直接等同于会计政策。

## 边界

**做**：库存余额与明细、可用量计算、预占与释放、批次与序列号、库存调整、盘点、调拨与在途、库存策略与预测、库龄呆滞、**货权与经营模式、多平台可售量分摊**。

**不做**：不执行仓库现场作业（属 08，那边只是调用这里的账本接口）、不判定采购需求（属 06）、不记会计价值（数量在此、价值在 12 财务）、**不在寄售/代销下虚构自有库存**。

**关键约束**（本系统最容易出错的地方，全部是硬约束）：

- `available = on_hand − reserved`，**没有第三个来源**
- 一次库存业务 = 一个 `inventory_transaction` + N 条带符号的 `inventory_entry`，**append-only**
- 预占/释放/消费是**显式状态机**（held→committed/consumed/released/expired），终态不可复活
- 数量为负由策略决定，**第一期默认禁止负库存**
- 质量状态不可售时**禁止销售预占**
- 序列号库存每件只能处于一个有效位置，出入库数量必须与序列号条数一致
- **供应商直发不发生自有仓实物出入库**；是否记货权库存、采购及资金事实取决于合同与经营责任，须在代发 PRD 明确
- **寄售/VMI 库存的货主是供应商**，我方只记持有位置与可销售权，不记为自有资产

## 详细设计

### 7.1.1.1 库存总览

- **职责**：按仓库/法人/SKU 维度汇总展示在手、预占、可用、在途、待检、残次数量，支持按类目/品牌/店铺筛选，识别零库存与超储。
- **输入**：筛选条件（仓库、法人、类目、库存状态）；用户数据范围；`inventory_balance` 聚合。
- **输出**：汇总表 + 分组统计图；点击进入 7.1.1.2 明细。
- **关系**：上游 = 7.1.1.2；下游 = 7.1.1.2、6.2.1.1 补货。**总览数字必须能下钻到明细且能核对上**，总览只是聚合视图，不存独立数据。

### 7.1.1.2 库存明细

- **职责**：最细粒度库存视图：法人货权 × SKU × 仓库 × 库位 × 批次 × 质量状态，每行显示在手/预占/可用/版本号与最近变动时间。
- **输入**：逐级下钻条件（法人、仓库、库位、SKU、批次）；用户数据范围。
- **输出**：bucket 级明细行；行内操作入口（发起调整、发起调拨、查看流水）。
- **关系**：上游 = 7.1.1.1；下游 = 7.1.2.1 流水、7.4.1.1 调整、7.5.1.1 调拨。**bucket 是库存的最小事实单位**，界面上必须能看到"在哪个货位、什么批次、什么质量状态"，否则无法解释差异。

### 7.1.1.3 可用量计算

- **职责**：统一计算并展示可售量（available），明确其口径：bucket 可用 = 在手 − 预占；可售 = 合格且允许销售的 bucket 可用量之和，再按策略扣一次安全缓冲。待检、残次、未上架等被排除的 bucket 不重复扣减；支持查看构成拆解。
- **输入**：bucket 明细；质量状态；预占状态；渠道可售量策略（7.2.2.1）。
- **输出**：可售量数值 + 构成拆解（每一项扣了多少）。
- **关系**：上游 = 7.1.1.2、7.2.1.2；下游 = 04 刊登（平台库存回写）、09 订单（审单判断）、3.1.2.1 SKU 列表。**可售量是全系统的单一口径来源**，不允许各系统各自算——这是超卖的第一根源。

### 7.1.2.1 库存流水台账

- **职责**：按时间顺序展示所有库存业务（入库、出库、预占、释放、调整、盘点、组装、调拨），每笔含来源单据、数量符号、操作人、发生时间，可下钻到分录行。
- **输入**：时间范围、SKU、仓库、业务类型、来源单据类型；用户数据范围。
- **输出**：流水列表 + 分录明细 + 期间净变动汇总。
- **关系**：上游 = 全部库存业务；下游 = 7.1.2.2 核对、12 财务（成本结转的来源追溯）。**流水只追加不修改**，错误用反向分录纠正，原记录永久保留。

### 7.1.2.2 账实核对

- **职责**：定期核对"按流水累计的余额"与"当前余额快照"是否一致，差异时列出可疑区间（漏记、重复记、并发丢失）。
- **输入**：余额快照；流水累计值；时间区间。
- **输出**：核对结果 + 差异明细 + 可疑流水定位。
- **关系**：上游 = 7.1.2.1；下游 = 1 工作台预警（异常阻断）、4 外部仓对账。**这套核对是库存账可信度的底线检查**，应作为定时任务常驻运行，而不是出事才查。

### 7.1.3.1 多仓分布视图

- **职责**：把同一 SKU（或 SPU）在所有仓库的库存并列展示，含本地仓/海外仓/FBA/三方仓/在途，用于调拨决策与缺货判断。
- **输入**：SKU 或 SPU；仓库集合（含 FBA 与在途 bucket）。
- **输出**：多仓对照矩阵（行=仓库，列=在手/预占/可用/在途/周转天数）。
- **关系**：上游 = 7.1.1.2、10 外部仓观测；下游 = 7.5.1.1 调拨。**FBA 库存是平台仓观测值，不是自有账本**，需标注来源与采集时间。

### 7.2.1.1 预占需求列表

- **职责**：展示所有预占需求（来自订单履约、加工领料、其他占用），含需求来源、数量、状态（held/committed/consumed/released/expired）、剩余量、超时时长。
- **输入**：筛选条件（状态、来源类型、时间）；用户数据范围。
- **输出**：预占需求列表 + 状态汇总。
- **关系**：上游 = 09 订单（履约需求）、6.4.1.1 加工；下游 = 7.2.1.2 分配明细、7.2.1.3 释放。**预占需求由 trade 持久化协调**，本系统只执行分配与账变（实体目录 §6）。

### 7.2.1.2 预占分配明细

- **职责**：展示一个预占需求实际分配到了哪些 bucket（哪个仓、哪个货位、哪个批次），以及每个分配的 held→终态迁移记录。
- **输入**：`reservation_id`；`reservation_allocation` 与 `reservation_entry`。
- **输出**：分配明细行 + 状态迁移时间线。
- **关系**：上游 = 7.2.1.1；下游 = 7.2.1.3。**分配到具体 bucket 而不是只记总量**，是批次追溯与成本精确分摊的前提。

### 7.2.1.3 释放与过期

- **职责**：处理预占的释放（订单取消、支付超时、拆单减少）与过期回收，提供手动释放入口与批量过期清理，释放时同步恢复可用量。
- **输入**：释放请求（业务事件或人工）；过期时间规则；批量清理任务。
- **输出**：预占终态记录 + 余额恢复分录。
- **关系**：上游 = 09 订单取消事件、7.2.1.1；下游 = 7.1.1.3 可用量。**承诺分配（committed）后不再自动 TTL 释放**，只能由消费或显式释放终结（实体目录 §6.5）——否则已承诺发货的货会被误释放导致超卖。

### 7.2.2.1 可售量口径

- **职责**：配置不同渠道/店铺的库存口径：是否共享同一池、是否允许超卖多少、平台可售量是按自有仓还是含 FBA、平台可售数保留缓冲比例。
- **输入**：店铺/渠道维度配置（共享策略、缓冲比例、是否含在途）。
- **输出**：生效的可售量口径；供 7.1.1.3 与 04 回写使用。
- **关系**：上游 = 2.3 店铺；下游 = 7.1.1.3、4.3.2.1。**平台库存回写缓冲是防超卖的最后一道防线**：多店铺共享池时，缓冲不足会在同步延迟期间超卖。

### 7.2.2.2 安全库存

- **职责**：按 SKU/分类/仓库配置安全库存阈值与预警级别，低于阈值时触发预警并可关联自动生成补货建议。
- **输入**：阈值配置；当前可用量投影；日均销量。
- **输出**：安全库存预警 + 可选自动触发 6.2.1.2 补货建议。
- **关系**：上游 = 7.1.1.3、13 销量；下游 = 6.2.1.1、1 工作台预警。**安全库存要区分"平台断货风险"和"自有仓耗尽"**：FBA 断货造成的损失远大于自有仓。

### 7.3.1.1 批次管理

- **职责**：管理批次（lot）：批号、生产日期、失效日期、来源采购单/供应商，支持按批次查询库存与流向追溯。
- **输入**：批次建立（收货时生成或手工建）；批次属性；查询条件。
- **输出**：批次档案 + 批次库存分布 + 出入库历史。
- **关系**：上游 = 8 收货、6 采购；下游 = 7.1.1.2 明细、11 售后（批次追溯）。**批次与序列号是两个独立实体**（实体目录 warehouse 段），不能合成一个"批次序列号"字段。

### 7.3.1.2 效期与先进先出

- **职责**：对有保质期的商品，按 FEFO（先到期先出）或 FIFO 分配出库批次，预警临期与过期库存。
- **输入**：批次失效日期；出库分配策略（FEFO/FIFO/指定批次）；预警提前天数。
- **输出**：推荐出库批次；临期/过期预警清单。
- **关系**：上游 = 7.3.1.1、8 拣货；下游 = 8 拣货任务（指定批次）、6.4.2（临期品处理）。**效期商品（FIFO/FEFO）是食品化妆品类目的硬需求**，第一期是否启用可延后，但维度已保留。

### 7.3.2.1 序列号

- **职责**：序列号级库存管理：录入/扫码、状态（在库/已售/在途/维修/报废）、当前位置、绑定 SKU 与批次，出入库时强校验数量与序列号条数一致。
- **输入**：序列号扫码/批量导入；出库/入库操作；状态变更。
- **输出**：序列号档案 + 位置流转历史 + 校验错误。
- **关系**：上游 = 8 收货拣货、6 采购；下游 = 11 售后（单件退换）、16 合规（电子产品合规）。**序列号校验是一致性硬约束**：数量为 1 时必须有且仅有 1 个序列号，不允许"大概齐"。

### 7.4.1.1 调整单管理

- **职责**：发起库存调整（盘盈盘亏、损坏、报废、错发纠正、平台仓差异），填写原因与凭证，支持批量调整。
- **输入**：调整请求（bucket、数量、原因码、附件）；`expected_version`。
- **输出**：调整单（草稿/待审/已批/已执行）；库存分录（反向或正向）。
- **关系**：上游 = 7.1.1.2、6.4.2.2；下游 = 7.4.1.2 审批、7.1.2.1 流水。**调整必须走单据**，不允许在明细页直接改余额——没有单据就没有责任人与原因。

### 7.4.1.2 调整审批

- **职责**：按金额/数量阈值审批调整单，审批通过后才执行库存分录；支持批量审批与驳回。
- **输入**：待审调整单；17 审批规则。
- **输出**：审批结果；执行后的库存分录；审计记录。
- **关系**：上游 = 7.4.1.1；下游 = 7.1.2.1 流水、12 财务（调整的会计影响）。**库存调整是舞弊高发区**（无审批的调整 = 任意改账），阈值审批是必要控制。

### 7.4.2.1 盘点单

- **职责**：发起盘点：选择范围（按仓库/类目/库位/ABC 分类）、冻结时点快照、生成盘点任务（按库位或按 SKU）、录入实盘数。
- **输入**：盘点范围；冻结快照；实盘结果录入（扫码）。
- **输出**：盘点单 + 账面/实盘/差异三列数据。
- **关系**：上游 = 7.1.1.2；下游 = 7.4.2.2。**盘点时点必须冻结账面数**，否则边盘边卖会产生虚假差异。

### 7.4.2.2 盘点差异处理

- **职责**：处理盘点差异：按差异原因（损耗、错发、偷盗、未入账、时点差）分类，生成调整单走审批，盘盈盘亏入账并可追责。
- **输入**：盘点差异明细；差异原因；处理决定（调整/复盘/忽略）。
- **输出**：调整单 + 盘点完成报告（含盘盈率、差异率指标）。
- **关系**：上游 = 7.4.2.1；下游 = 7.4.1.1 调整单、13 分析（盘点差异统计）。**差异不直接改余额**，必须经调整单与审批，这是实体目录明确的红线。

### 7.5.1.1 调拨单

- **职责**：发起仓库间调拨：选择源仓与目标仓、调拨 SKU 与数量、预计发出与到达时间，跟踪发出、在途、目标实收。
- **输入**：调拨请求（源仓、目标仓、SKU、数量）；`expected_version`。
- **输出**：调拨单（草稿/待发/在途/部分收/已收/差异）；库存分录（发出转入途、实收转入目标仓）。
- **关系**：上游 = 7.1.3.1 多仓视图、10 物流（调拨运输）；下游 = 7.5.1.2 在途。**调拨不是瞬时**：发出后进入在途 bucket，目的仓分次收货逐笔转入，"异地收发同一瞬间"是错的（实体目录 warehouse 段）。

### 7.5.1.2 在途库存

- **职责**：跟踪所有在途库存（调拨在途、头程在途、采购在途、FBA 发货在途），含起止仓、批次、数量、预计到达。
- **输入**：调拨发出与头程发运事件；预计到达时间；收货事件。
- **输出**：在途库存清单 + 到达预警（逾期未达）。
- **关系**：上游 = 7.5.1.1、10 物流与头程；下游 = 7.1.3.1 多仓分布、6.2.1.1 补货（缺口计算必须扣在途）。**在途漏算会导致重复补货**，这是跨境库存积压的最常见原因。

### 7.5.2.1 跨法人调拨

- **职责**：法人之间的库存转移（业务上是货权转移 + 内部结算），需要定价、生成内部往来单据、双方确认，不能当作普通同仓调拨。
- **输入**：转出与转入法人；转移 SKU 与数量；转移定价。
- **输出**：跨法人调拨单 + 内部结算单据 + 双方库存变更。
- **关系**：上游 = 7.5.1.1；下游 = 12 财务（内部结算/收入确认）、17 权限（双方法人授权）。**货权变了意味着利润归属变了**，这是财务处理而非库存处理的差异点。

### 7.6.1.1 库龄与呆滞

- **职责**：按入库时间计算库龄分布，识别滞销、临期、残次、呆滞库存，给出处置建议（降价促销、清仓、退仓、报废）。
- **输入**：批次/入库时间；当前可用量；销售速度；品类特性。
- **输出**：库龄分桶报表（0-30/31-60/61-90/90+ 天）+ 呆滞清单 + 占用资金估算。
- **关系**：上游 = 7.1.1.2、13 销量；下游 = 5.4.1 调价（清仓定价）、6.4.2.2 处置。**呆滞占用的资金是最容易被忽略的利润黑洞**，库龄 + 占用金额双维度才有效。

### 7.6.2.1 库存健康

- **职责**：库存健康度诊断：周转率、缺货率、超储率、呆滞占比、库存准确率、负库存发生次数，按仓库与类目打分并给出改进建议。
- **输入**：库存与销售聚合；盘点历史（准确率）；异常事件记录。
- **输出**：健康度评分卡 + 趋势 + 问题清单与建议。
- **关系**：上游 = 7.1.2.2 核对、7.6.1；下游 = 1 工作台、13 分析。**库存准确率是硬指标**，低于阈值应阻断结算与对账——账不准时报表全是错的。

### 7.7.1.1 货主与所有权

- **职责**：为库存 bucket 显式标注**货主（stock_owner）**与所有权类型（自有 / 供应商寄售 / 平台所有 / 代销），使"货在谁的仓库"与"货是谁的"不再混为一谈。默认自有，但租户可把整仓或整 SKU 设为寄售。
- **输入**：货主与所有权配置（按仓库/法人/SKU 维度）；库存业务上下文。
- **输出**：bucket 上的货权维度；报表中按货主拆分的库存与货值。
- **关系**：上游 = 17.1.2.1 法人、3.6.1.2 供应商档案；下游 = 7.7.1.2、7.5.2.1 跨法人调拨、12 财务（自有货才进自有资产，寄售不进）。**同一仓内不同货主必须能并存**——`stock_bucket` 的组成维度要含货主，不能用 `tenant` 代替货主（实体目录 §8 已把寄售列为未决项，此处给出显式建模）。

### 7.7.1.2 寄售与代销

- **职责**：管理寄售与代销业务：寄售协议（供应商货、我方销，结算按实际售出）、寄售可用量、销售触发结算数量、未售退货与期末清理。支持"寄售库存不计入我方采购入库成本，仅在售出时结转"。
- **输入**：寄售协议（供应商、SKU、寄售量、结算价、结算周期、期末处理约定）；销售事实。
- **输出**：寄售库存视图（寄售量/已售/剩余）；结算触发单（→ 12 应付）；期末退回或转入采购的单据。
- **关系**：上游 = 3.6.2 供应商报价、9 订单（售出事实）；下游 = 12.1.2.1 应付（售出才产生应付）、10 物流（期末退回运输）。**寄售未售出不产生采购成本与应付**，这条是寄售与普通采购在财务上的根本分叉，必须在成本核算侧同步支持。

### 7.7.2.1 VMI 供应商管理库存

- **职责**：支持供应商管理库存（VMI）：货权属供应商、我方享有可销售权，按约定补货或由系统触发供应商备货；记录安全水位与补货信号，售出后与供应商对账结算。
- **输入**：VMI 协议（SKU、水位、补货倍数、结算价、结算周期）；实时销量与在库数据。
- **输出**：VMI 水位监控与补货信号（推给供应商或 6.2.1.2 备货）；VMI 结算对账单。
- **关系**：上游 = 13 销量、7.1.1.3 可用量；下游 = 6 采购（补货信号）、12 结算。**VMI 的"可售"不等于"自有"**：可售量要计入可售额，货值不能计入自有资产，两者必须分开统计。

### 7.7.2.2 平台托管与全托管备货

- **职责**：处理平台托管（全托管）下的"备货"语义：发给平台的货进入平台仓但**所有权与结算规则随模式变化**，需与自有仓库存分账；支持备货单、平台仓收发对账、按件/按日结算口径标记。
- **输入**：店铺经营模式（2.3.2.1）；备货单与发运数据；平台仓库存与结算回执。
- **输出**：托管备货台账（备货量/平台在库/平台已售/结算未结）；与自有库存的对账结果；结算口径标记供 12 使用。
- **关系**：上游 = 2.3.2.1 经营模式、10.4.2.2 备货预报；下游 = 12.3.1 结算、13.4.1.1 利润（按模式分组）。**全托管下"备货"不等于"自有库存"**，平台仓在库数是平台回执的观测值，不得并入自有库存余额；结算按平台规则（可能按件或按日）而非我方发货确认。

### 7.8.1.1 分配策略配置

- **职责**：定义同一总可用库存分配给多个店铺/平台的方式：按销量占比比例分配、按固定优先级先到先得、按店铺类型（自营/托管）优先级、留出不分配缓冲。支持 SKU 或店铺维度的策略覆盖。
- **输入**：分配策略配置（方法、参数、生效范围）；当前可用量；各店铺历史销量。
- **输出**：生效的分配策略；各店铺分摊额。
- **关系**：上游 = 2.3 店铺、7.2.2.1；下游 = 7.8.2.1。**多平台共享库存时必须有一份统一的分摊算法**，否则会出现"某个店铺一直抢不到货"或"所有店铺都以为有货"的超卖（实体目录 §6）。

### 7.8.1.2 优先级与保底

- **职责**：在分摊冲突时按优先级裁决，并为高价值店铺设置保底可用量与安全垫，防止低优先级店铺长期断货影响其店铺绩效与平台考核。
- **输入**：店铺优先级；保底数量/比例；当前销售与绩效。
- **输出**：分摊结果（含被压低店铺的提示）；保底生效记录。
- **关系**：上游 = 7.8.1.1；下游 = 7.8.2.1、7.8.2.2。**保底是策略不是事实**，需可解释可调整。

### 7.8.2.1 分摊结果查看

- **职责**：展示某 SKU/仓在各店铺的分摊量、已用、剩余、回写平台的数值，以及回写失败或延迟导致的实际风险敞口。
- **输入**：分摊结果；平台回写状态（4.3.2.1）。
- **输出**：分摊明细表 + 平台回写一致性核对。
- **关系**：上游 = 7.8.1、4.3.2.1；下游 = 04 刊登（回写依据）。**平台回写有延迟**，分摊需保留缓冲以覆盖同步窗口，缓冲不足会超卖。

### 7.8.2.2 缺货与饥饿预警

- **职责**：识别因分摊/优先级导致的店铺"饥饿"（长期分不到货、影响绩效），以及真正的全网缺货，区分两者给出不同处置建议。
- **输入**：分摊结果；店铺销售与绩效；总可用量。
- **输出**：饥饿店铺清单 + 缺货清单 + 建议（调优先级/调保留/补货）。
- **关系**：上游 = 7.8.2.1、13 销量；下游 = 6.2.1.2 补货、1 工作台预警、17 绩效。**"没货卖"和"没分到货"是两种问题**，处置完全不同，不能混在一个缺货告警里。
