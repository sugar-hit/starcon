# 04 刊登与内容系统

> **定位**：把内部商品变成平台上的商品，并管住"改了内部商品要不要同步、怎么同步、失败了怎么办"。
> **后端归属**：`channel` 服务拥有 `listing` `listing_variant` `listing_mapping_version`；内容编辑复用 `catalog` 的商品主数据。
> **前端入口**：`/listings`

## 边界

**做**：listing 资产与生命周期、平台变体到内部 SKU 的映射版本、多语内容编辑与模板、批量发布与回写、商品采集与跨店搬家、平台商品监控。

**不做**：不新建 SKU（引导到 03）、不判定售价（05 给价，这里只做回写）、不直接改平台数据（经 02 回写队列）。

**关键约束**：
- 映射必须**版本化**，旧版保留；历史订单冻结当时映射版本
- 内容按**平台 + 站点**隔离，同一商品在不同平台内容互不污染
- 发布是**异步任务 + 幂等**，重复触发不产生重复 listing
- 平台限流与字段必填差异由 02 的平台能力矩阵统一裁决

## 功能职责（L2）

| 功能 | 职责 | 主责服务 |
|---|---|---|
| **4.1 Listing 资产** | 管理平台商品在系统里的资产形态：列表与详情、生命周期状态、变体到内部 SKU 的**版本化映射** | channel |
| **4.2 内容编辑** | 提供按平台字段动态渲染的编辑表单、批量编辑、模板与类目映射，并在发布前做合规预检 | catalog + channel |
| **4.3 发布与同步** | 编排一键刊登与批量发布任务，并管理内容回写与平台状态回流；跨平台发布按平台独立成败 | channel |
| **4.4 采集与搬家** | 解决"货从哪来、商品怎么铺到新店"：链接/插件采集、采集箱、跨店认领与批量搬迁 | channel |
| **4.5 平台商品监控** | 监控 listing 表现、关键词排名、跟卖与竞品变更，把平台侧变化带回系统视野 | channel |

## 详细设计

### 4.1.1.1 Listing 列表

- **职责**：按店铺/站点/状态/负责人/类目/是否有映射/是否缺货筛选平台商品，展示内部 SKU、价格、库存、销量、评分、近 7 日状态变化，支持批量改价改库存（跳 05/07）、批量下架、批量分配负责人。
- **输入**：筛选条件；用户数据范围（店铺维度）；`listing` + `listing_variant` + 销量/库存投影。
- **输出**：分页列表（含内部 SKU 映射状态、缺货标记、审核状态）；批量操作任务；点击进入 4.1.1.2。
- **关系**：上游 = 02 店铺、03 SKU、05 价格、07 库存；下游 = 4.1.1.2、4.2.1.1、4.3.1。**"未映射"和"缺货"是两个独立状态**，列表要能同时显示且可分别筛选。

### 4.1.1.2 Listing 详情

- **职责**：单个平台商品的全景：平台原始信息（ASIN/item_id、标题、状态、评分评论数）、内部映射、内容对照（平台当前内容 vs 内部草稿内容）、价格库存差异、发布历史、平台操作记录。
- **输入**：`listing_id`；聚合平台快照与内部数据；用户权限。
- **输出**：左右对照视图 + 编辑入口 + 差异高亮 + 回写按钮。
- **关系**：上游 = 4.1.1.1；下游 = 4.2.1.1 编辑、4.3.2.1 回写。**差异对照是本模块的核心价值**：让运营一眼看出"平台上卖的价格/库存和我系统里设的不一样"。

### 4.1.1.3 生命周期与下架

- **职责**：管理 listing 状态：在售 / 草稿 / 平台审核中 / 平台驳回 / 主动下架 / 平台下架 / 被封禁。支持平台侧状态变更被动同步，以及主动下架时选择是否回写平台。
- **输入**：平台状态回流事件；用户下架/上架操作；平台驳回原因。
- **输出**：状态变更记录（来源：平台 or 人工）+ 可选的平台操作任务。
- **关系**：上游 = 02 同步、4.3.2.2；下游 = 02 回写队列（5.1.1）。**平台下架与内部下架是两个事实**，分别记录并展示差异——平台把商品下架了而内部不知情，是最常见的漏单原因。

### 4.1.2.1 映射管理

- **职责**：建立并维护"平台变体 → 内部 SKU/套装"的映射，支持一对一、一对多（套装）、多对一；支持批量映射（按规则：SKU 编码匹配、条码匹配、标题相似度推荐但需人工确认）。
- **输入**：映射建立操作；匹配规则；批量候选。
- **输出**：`listing_mapping_version` 记录（当前生效版本 + 历史版本）；未映射清单回流 02 映射缺失队列。
- **关系**：上游 = 4.1.1.1、02 同步到的 listing；下游 = 09 订单（订单行按映射解析 SKU）、07 库存（回写可售量）。**映射未建立时订单进入待映射状态，绝不按名称猜 SKU**（实体目录 §6）。

### 4.1.2.2 映射版本

- **职责**：映射变更时生成新版本而非原地修改，保留每个版本对应的商品/订单范围，支持查看某订单使用的是哪个版本、按版本回溯受影响订单。
- **输入**：映射变更；生效时间点；变更原因。
- **输出**：版本列表 + 受影响订单范围查询。
- **关系**：上游 = 4.1.2.1；下游 = 09 订单（`order_line_component` 冻结）。**改映射不影响已产生的订单**，只对新订单生效——这是财务与售后追溯的前提。

### 4.1.2.3 套装组件映射

- **职责**：当平台商品对应内部虚拟套装时，维护组件 SKU 与数量的映射，支持平台变体与不同套装版本对应，并校验组件 SKU 在目标仓库可售。
- **输入**：组件映射维护；套装版本选择。
- **输出**：组件映射记录 + 可售性校验结果。
- **关系**：上游 = 3.5.1 套装版本、4.1.2.1；下游 = 07 库存（按组件预占）。**组件数量必须大于 0**，缺任一组件时整个套装不可售。

### 4.2.1.1 刊登编辑器

- **职责**：单商品的平台内容编辑表单：按目标平台动态渲染字段（标题、要点、描述、变体维度、图片集、视频、A+ 模块、类目属性、合规声明），左侧编辑右侧实时预览，支持多语言 Tab、保存草稿、提交审核。
- **输入**：源商品（03 SKU/SPU）、目标店铺与站点、平台字段要求（02 能力矩阵）；用户编辑内容；已填内容的草稿。
- **输出**：内容草稿（按平台 + 站点 + 语言分别保存）；提交发布或保存模板的动作；校验结果。
- **关系**：上游 = 03 商品主数据、03 媒体与文案、02 平台字段要求；下游 = 4.3.1.1 发布。**表单字段由平台要求驱动生成**，不是固定一套表单套所有平台——平台能力矩阵变化时表单自动变化。

### 4.2.1.2 批量编辑

- **职责**：对一批 listing 执行统一的字段修改（追加/替换/正则替换标题、批量换图、统一加卖点、批量改类目），支持按平台差异化模板与操作预览（改前 vs 改后）。
- **输入**：目标 listing 集合；批量操作定义；预览确认。
- **输出**：批量修改草稿（待发布）；修改记录。
- **关系**：上游 = 4.1.1.1；下游 = 4.3.1.2。**批量编辑只改草稿不直接改线上**，必须走发布流程——这是"误改全店标题"事故的唯一防线。

### 4.2.2.1 刊登模板

- **职责**：沉淀可复用的刊登模板（类目级、店铺级），保存字段填充规则（取自商品属性、引用文案库、套用图片组），一键套用到目标商品。
- **输入**：模板定义（字段规则 + 图片组 + 必填校验）；套用目标。
- **输出**：模板记录；套用后的内容草稿。
- **关系**：上游 = 03 文案资产、03 媒体库；下游 = 4.2.1.1 编辑器。**模板引用的是"取值规则"而非一次性拷贝**，商品改价或换图后套用结果跟着变。

### 4.2.2.2 描述模板

- **职责**：管理富文本描述模板：段落结构（产品介绍、使用场景、规格参数、注意事项、售后承诺）、变量占位、多语言版本、图片插入位。
- **输入**：模板结构定义；变量绑定；翻译版本。
- **输出**：描述模板 + 渲染后的描述 HTML（供编辑器与平台上传）。
- **关系**：上游 = 3.4.2.2 描述库、3.4.3 多语言；下游 = 4.2.1.1。**变量未绑定必须显式提示**，不允许把 `{{尺寸}}` 原样发到平台。

### 4.2.3.1 平台类目映射

- **职责**：维护内部分类 ↔ 平台类目的多对多映射，附带平台类目必填属性映射规则（平台的"材质"对应内部哪个属性），支撑 4.2.1.1 表单生成。
- **输入**：映射维护（内部分类 + 平台 + 站点 + 平台类目）；属性映射规则。
- **输出**：映射记录；平台类目必填属性清单。
- **关系**：上游 = 3.3.1.1 分类、2.1.1.2 能力矩阵；下游 = 4.2.1.1、4.3.1.1。**同一个内部类目在不同平台映射到不同平台类目**，映射必须带平台与站点维度。

### 4.2.3.2 合规预检

- **职责**：发布前扫描内容的违规风险：违禁词/敏感词命中、极限词、品牌侵权（外观/商标）、平台类目必填缺失、图片不合规（尺寸/白底/水印）、认证缺失。
- **输入**：内容草稿；租户违禁词库；平台规则库；16 合规的侵权与认证状态；03 品牌授权状态。
- **输出**：风险清单（风险等级、命中位置、规则来源、建议替换）；阻断项（未修复不允许发布）与提醒项。
- **关系**：上游 = 16 合规与风控、03 品牌、02 平台规则；下游 = 4.3.1.1（阻断发布）。**阻断项在服务端强制校验**，前端提示不能作为唯一防线。

### 4.3.1.1 一键刊登

- **职责**：单个 SKU 一次性发布到多个目标店铺/站点：自动套模板、填充内容、建立映射、上传媒体、设置价格库存、提交平台审核。
- **输入**：源 SKU；目标店铺与站点集合；模板选择；价格库存来源策略；`idempotency_key`。
- **输出**：N 个发布任务（每个目标一个）+ 各任务的进度与结果（草稿/审核中/成功/驳回+原因）。
- **关系**：上游 = 4.2.1.1、5 定价（取价）、7 库存（取可售量）、02 平台能力；下游 = 2.5.1.1 回写任务。**跨平台发布不是一个事务**：某个平台失败不影响其他平台，各自独立重试。

### 4.3.1.2 批量发布

- **职责**：批量刊登队列：按规则筛选待发布商品（如"SPU 状态=在售 且 未在任何店铺发布"），生成任务批次，支持暂停、调整顺序、批量重试。
- **输入**：筛选规则与数量上限；发布策略；用户确认。
- **输出**：批次任务列表 + 总体进度 + 失败明细（可跳转 4.3.1.3）。
- **关系**：上游 = 4.1.1.1、4.2.1.2；下游 = 4.3.1.3。**批量任务必须限流**：按平台各自的 API 配额排队，否则会触发平台限流并可能影响店铺安全（实体目录 §6 平台限流要求）。

### 4.3.1.3 发布任务

- **职责**：单次发布任务的进度视图：各步骤状态（内容校验 → 平台创建 → 变体创建 → 媒体上传 → 价格库存设置 → 提交审核）、失败步骤与原因、可重试的步骤。
- **输入**：任务 ID；平台返回结果。
- **输出**：步骤时间线 + 错误明细 + 重试操作。
- **关系**：上游 = 4.3.1.1/4.3.1.2；下游 = 2.5.1.1。**平台提交审核是异步的**，任务在"审核中"结束，实际结果由 4.3.2.2 回流。

### 4.3.2.1 内容回写

- **职责**：把内部已发布的商品内容变更推送到平台（改标题、改图、改描述、改 A+），支持按变更类型触发或批量触发，并记录回写前后快照。
- **输入**：内容变更事件；用户批量回写操作；目标 listing 集合。
- **输出**：回写任务（经 02 队列）+ 变更历史。
- **关系**：上游 = 3 商品主数据变更、4.2.1.2 批量编辑；下游 = 2.5.1.1。**内容回写不触碰价格与库存**（那是 05/07 的事），三条回写通道独立失败独立重试。

### 4.3.2.2 平台状态回流

- **职责**：接收并展示平台侧的商品状态变化：审核通过/驳回、下架、限流、被抑制（suppressed）、类目审核、价格异常通知，并支持一键处理（如按驳回原因批量修正重发）。
- **输入**：平台事件/webhook；轮询补充。
- **输出**：状态变更记录 + 需处理队列。
- **关系**：上游 = 02 同步；下游 = 4.1.1.3、4.3.1.3。**回流是平台状态的权威来源**，内部状态与之冲突时以平台为准并告警。

### 4.4.1.1 链接采集

- **职责**：粘贴外部商品链接（1688/淘宝/供应商站/同行 listing），抓取标题、主图、规格、属性、描述等，生成采集草稿供认领为内部商品。
- **输入**：商品 URL（支持平台白名单）；抓取任务。
- **输出**：采集到的商品草稿（图片下载入媒体库）；来源 URL 与抓取时间。
- **关系**：上游 = 外部页面；下游 = 4.4.1.3 采集箱、3.1.1.1（认领为 SPU）。**采集只产生草稿**，进入正式商品库必须走 03 的建档流程并补全属性与合规信息。

### 4.4.1.2 批量/插件采集

- **职责**：支持按分类页、关键词搜索结果批量采集，以及浏览器插件在用户浏览时抓取当前页商品，解决大批量找货场景。
- **输入**：分类页 URL / 关键词 + 页数范围；插件上报的页面数据。
- **输出**：批量采集任务 + 结果清单。
- **关系**：上游 = 4.4.1.1；下游 = 4.4.1.3。**抓取必须有频率限制与去重**（同 URL 不重复抓、已存在的商品跳过），避免重复劳动与外部站点压力。

### 4.4.1.3 采集箱

- **职责**：采集结果的暂存区，按平台/来源/标签分组，支持勾选后批量认领为内部商品（生成 SPU/SKU 草稿并预填内容）、批量删除、批量打标。
- **输入**：勾选操作；认领规则（目标分类、品牌映射、命名规则）。
- **输出**：认领后的商品草稿；采集箱状态更新。
- **关系**：上游 = 4.4.1.1/4.4.1.2；下游 = 3.1.1.1 商品建档、4.2.1.1 编辑器。**认领时必须做品牌与分类映射**，否则采集来的商品归属混乱，后续无法按品牌做合规与绩效分析。

### 4.4.2.1 商品认领

- **职责**：把已在 A 店铺的 listing 认领到 B 店铺（跨店搬家），复用原商品内容与映射，生成 B 店铺的新 listing 草稿。
- **输入**：源 listing；目标店铺与站点；保留/重写的内容字段选择。
- **输出**：目标店铺的 listing 草稿 + 待发布任务。
- **关系**：上游 = 4.1.1.2；下游 = 4.3.1.1。**新店铺 listing 是全新平台资源**，需重新过平台审核；源 listing 不受影响。

### 4.4.2.2 批量搬迁

- **职责**：批量把一批 listing 从一个店铺搬到多个店铺，支持按规则筛选（类目、销量区间、价格区间），并对重复铺货风险给出提示。
- **输入**：筛选规则；目标店铺集合；重复度控制参数。
- **输出**：批量搬迁任务 + 结果明细；重复度风险提示。
- **关系**：上游 = 4.4.2.1；下游 = 4.3.1.2。**搬迁后必须做标题差异化**，否则平台可能判定重复铺货并抑制 listing。

### 4.5.1.1 Listing 表现

- **职责**：单个 listing 的表现明细：曝光、点击、转化率、销量、销售额、Session、退货率、评分变化，支持时间范围对比。
- **输入**：`listing_id`；平台表现数据同步结果；时间范围。
- **输出**：表现指标 + 趋势图；下钻到 13 产品表现。
- **关系**：上游 = 02 同步的平台流量数据；下游 = 13 产品表现、14 广告（关联投放）。**表现数据来自平台而非内部订单**，与内部订单口径不同，展示时需标注来源。

### 4.5.1.2 关键词排名

- **职责**：监控商品在核心关键词下的自然排名与广告排名，记录历史变化，低于阈值时预警。
- **输入**：关键词集合（按商品维护）；排名抓取任务；阈值设置。
- **输出**：排名历史表 + 变化预警 + 关键词维度报表。
- **关系**：上游 = 抓取任务（02 通道）；下游 = 1 工作台预警、14 广告。**排名数据依赖抓取频率与平台限制**，必须明确标注抓取时间与可能的不准确窗口。

### 4.5.2.1 跟卖监控

- **职责**：监控他人/己方其他店铺对本 ASIN 的跟卖行为，记录跟卖者、价格、店铺，发现异常跟卖或恶意压价时告警。
- **输入**：定时抓取或平台接口返回的跟卖信息。
- **输出**：跟卖记录 + 预警通知 + 对比视图。
- **关系**：上游 = 抓取任务；下游 = 16 合规（品牌保护）、1 工作台预警。**跟卖数据只能作为参考**，处置动作（投诉/举报）在平台侧完成，系统只负责发现与提醒。

### 4.5.2.2 上新与变更监控

- **职责**：监控目标 ASIN/竞品的上下架、价格、排名、评论数变化，识别市场机会（如竞品断货涨价）。
- **输入**：监控对象列表；抓取频率。
- **输出**：变更事件流 + 历史对比。
- **关系**：上游 = 抓取任务；下游 = 13 分析、1 工作台。**监控对象与自有商品分离**，竞品数据不进自有商品模型，只做参考指标。
