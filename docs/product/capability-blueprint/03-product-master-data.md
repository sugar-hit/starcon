# 03 商品主数据系统

> **定位**：全系统**唯一**的商品事实源。SPU 是什么、SKU 有哪些规格、属性是什么、属于哪个分类、贴什么图——这里说了算。其他系统只引用，不复制。
> **后端归属**：`catalog` 服务（唯一拥有 `spu` `sku` `category` `brand` `unit_of_measure` `attribute_*` `spu_attribute_*` `sku_attribute_*` `bundle_*` `party` `supplier_offer` 等）。
> **前端入口**：`/products`
> **状态**：**已实现**（D2 阶段，当前真实运行的模块）。

## 边界

**做**：SPU/SKU 建模、属性体系、分类品牌单位、媒体与文案资产、组合套装、BOM、往来单位档案、商品级合规属性、批量导入导出。

**不做**：不维护可售库存（属 07 库存）、不拥有平台 listing（属 04 刊登）、不判定销售价格（属 05 定价）、不持有订单快照。

**关键约束**：
- SPU 与 SKU 严格分离；**SPU 不存库存**，库存按 SKU 计
- 已被单据引用的主数据**只能停用，不能删除**
- 单据行冻结商品属性快照，商品后续改参数不影响历史单据
- 同一 SKU 的规格组合唯一；跨租户关联一律拒绝

## 功能职责（L2）

| 功能 | 职责 | 主责服务 |
|---|---|---|
| **3.1 商品建模** | 建立 SPU 与 SKU 两层模型，管理规格轴与组合唯一性、编码条码、单位换算；商品事实的唯一来源 | catalog |
| **3.2 属性体系** | 定义属性字典与取值，并支持"SPU 公共值 + SKU 覆写/清空"的有效值解析，避免每个 SKU 重复维护共性参数 | catalog |
| **3.3 分类品牌单位** | 维护多棵分类树、类目属性要求、品牌与计量单位换算；这些是商品的归类与计量基础 | catalog |
| **3.4 媒体与文案** | 沉淀图片视频与标题描述等多语言内容资产，供批量刊登与客服话术复用 | catalog |
| **3.5 组合与物料** | 管理虚拟套装版本（销售用，扣组件）与 BOM 版本（生产用，产成品）两类不同的组合结构 | catalog |
| **3.6 商业伙伴** | 统一维护供应商/客户/承运商等往来单位及其角色档案、报价、地址与联系人 | catalog |
| **3.7 商品合规属性** | 维护报关信息（HS 编码、申报要素、目的地版本）与物理安全属性，直接决定渠道可用性与申报成功率 | catalog |
| **3.8 批量数据管理** | 提供商品主数据的批量导入导出通道与逐行校验报告，是新租户初始化与批量维护的主路径 | catalog |
| **3.9 主数据治理** | 处理 SKU 上万后的重复合并、完整度评分与僵尸数据清理；品牌化客户的长期维护成本项 | catalog |

## 详细设计

### 3.1.1.1 SPU 列表

- **职责**：按编码/名称/品牌/分类/状态/创建人检索商品族，展示核心指标（SKU 数、销量、近 30 日销售额、库存覆盖天数），支持批量停用、批量改分类、批量分配负责人。
- **输入**：列表筛选条件（关键词、分类树、品牌、状态、负责人、时间范围）；用户数据范围；SPU 与 SKU/库存/销量的只读投影。
- **输出**：分页结果（编码、名称、品牌、主分类、SKU 数、状态、在售平台数）；批量操作结果；点击进入 3.1.1.2。
- **关系**：上游 = 07 库存（覆盖天数）、13 分析（销量/销售额）；下游 = 3.1.1.2 详情、04 刊登（一键刊登）。共享数据：`spu`、`spu_category_link`、性能投影。**库存与销量是投影，SPU 本身的权威数据不受影响**。

### 3.1.1.2 SPU 详情

- **职责**：单商品族全景页：基础信息、品牌分类、公共属性、SKU 矩阵、媒体、多语言内容、套装/BOM、关联的 listing 与供应商报价、变更历史。
- **输入**：`spu_id`；聚合子资源；用户权限。
- **输出**：分区详情视图 + 各子资源的编辑入口 + `version`（乐观锁，供编辑提交）。
- **关系**：上游 = 3.1.1.1；下游 = 3.1.2 SKU 列表、3.2.2.1 属性、3.4 媒体、3.5 套装/BOM、04 刊登。**详情页是商品的"控制塔"，所有子资源的创建入口都从这里发起**。

### 3.1.1.3 SPU 生命周期

- **职责**：管理商品状态流转：草稿 → 待上架 → 在售 → 停售 → 停产，并记录变更原因与时间。支持按批量规则流转（如"有库存且 30 天无销量"批量转停售）。
- **输入**：状态变更操作 + 原因；批量规则定义；当前库存与销量投影。
- **输出**：状态变更记录（操作人、时间、原因）；触发下游动作（停售是否同步下架平台商品，由 04 决定）。
- **关系**：上游 = 3.1.1.1；下游 = 04 刊登（下架联动）、13 分析（生命周期统计）。**状态不是自由文本**，只能按合法转换矩阵流转（实体目录 §5）。

### 3.1.2.1 SKU 列表

- **职责**：全租户 SKU 明细表：SKU 编码、商品名、规格、条码、库存（在仓/在途/可售）、成本、采购价、售价、状态、在售平台。支持多维筛选与批量操作（批量停售、批量改状态、批量分配、批量生成刊登）。
- **输入**：筛选条件（SPU、分类、状态、库存区间、价格区间、是否缺货、是否在售）；库存/成本/售价投影。
- **输出**：分页结果 + 批量操作任务；导出。
- **关系**：上游 = 07 库存（数量）、05 定价（售价）、06 采购（成本）；下游 = 3.1.2.2 详情、04 刊登、08 拣货、10 物流。**SKU 列表是仓储、采购、财务共用的事实入口**，字段口径必须与各归属系统一致（库存数以 07 为准，售价以 05 为准）。

### 3.1.2.2 SKU 详情

- **职责**：单个 SKU 的完整档案：编码与规格、属性有效值（公共值 + 覆写解析结果）、单位换算、包装尺寸重量、条码、库存分布、平台 listing、成本与售价、各单据引用。
- **输入**：`sku_id`；聚合子资源（属性、媒体、包装、映射、库存、报价）。
- **输出**：分区详情 + 编辑入口 + `version`。
- **关系**：上游 = 3.1.2.1；下游 = 3.2.2.2 属性、3.5 组件、3.7 合规属性。**属性区展示的是"有效值"（公共值经 SKU 覆写后的解析结果）**，不是原始存的值。

### 3.1.2.3 编码与条码

- **职责**：管理内部 SKU 编码规则（手工输入/按规则自动生成/批量补齐）与外部条码（`sku_identifier`，按 scheme+value 唯一，如 EAN/UPC/自定义）。
- **输入**：编码规则定义；条码批量导入/扫码录入；唯一性冲突。
- **输出**：编码/条码记录 + 冲突拒绝清单；供 08 拣货扫码、10 面单打印使用。
- **关系**：上游 = 3.1.2.2；下游 = 08 仓储作业（扫码作业）、10 物流（包裹条码）。**店铺的 `seller_sku` 是平台属性，不是内部编码**，映射关系在 04 维护。

### 3.1.2.4 单位与换算

- **职责**：维护 SKU 的采购单位、销售单位、基础单位与换算比例（如 1 箱 = 12 件），支持多版本换算且单据冻结当时比例。
- **输入**：单位定义（`unit_of_measure`）；SKU 的换算关系与生效版本；单据上的数量单位。
- **输出**：换算后的基础数量（入库、出库、采购统一到基础单位）。
- **关系**：上游 = 3.3.3 单位；下游 = 06 采购（采购单位）、07 库存（基础单位记账）、08 拣货（拣货单位）。**换算比例必须版本化并有生效区间**，单据生成时冻结快照，之后修改比例不影响已发生单据。

### 3.1.3.1 规格轴定义

- **职责**：定义商品的规格维度（颜色、尺码、容量）与可选值，规格轴与属性选项**共享同一个值源**，避免同一值两处维护。
- **输入**：属性定义（用途=规格）；可选项集合；类目允许的规格轴规则。
- **输出**：可用规格轴 + 选项列表；驱动 SKU 矩阵的生成与展示。
- **关系**：上游 = 3.2.1.1；下游 = 3.1.3.2 组合校验、3.1.2.1 SKU 矩阵。**规格选项不得独立于属性选项存在**，这是数据一致性的硬约束。

### 3.1.3.2 组合唯一性校验

- **职责**：保证同一 SPU 下不存在重复的规格值组合（如"红色/大"出现两次），并在生成 SKU 矩阵前阻止非法组合。
- **输入**：待创建/修改的 SKU 规格值组合集合；已存在的 SKU 组合。
- **输出**：冲突清单（重复组合）；通过则生成待建 SKU 草稿。
- **关系**：上游 = 3.1.3.1；下游 = 3.1.2.1。**唯一性约束在数据库层也要有**，应用层校验只用于友好提示，不能替代 DB 约束。

### 3.2.1.1 属性定义列表

- **职责**：管理属性字典：名称、编码、数据类型（文本/数字/枚举/布尔）、用途（描述/规格/物流/合规）、是否必填、是否参与筛选、是否多值。支持按类目配置必填与可选范围。
- **输入**：属性定义的新增/编辑；类目属性规则；用户权限。
- **输出**：属性定义记录 + 选项集合 + 类目绑定规则。
- **关系**：上游 = 类目配置；下游 = 3.2.2 属性赋值、04 刊登（平台属性映射）、3.7 合规属性。**核心业务字段（SKU 编码、品牌、分类）不用属性承载**，属性只用于扩展维度，避免 EAV 泛滥。

### 3.2.1.2 属性选项管理

- **职责**：维护枚举属性的取值集合，支持选项的启用/停用与排序，停用不删除（历史单据仍需可展示）。
- **输入**：选项定义；引用计数（该选项被多少商品使用）。
- **输出**：选项记录 + 引用统计。
- **关系**：上游 = 3.2.1.1；下游 = 3.2.2.1/3.2.2.2。**有商品引用的选项只能停用**。

### 3.2.2.1 SPU 公共属性

- **职责**：设置该商品族的公共属性值（多数 SKU 共有的参数），支持类型化单值/多值，是 SKU 有效值的基线。
- **输入**：属性选择与取值；批量应用到多个 SPU 的需求（走 3.8 导入）。
- **输出**：SPU 公共属性记录；作为 SKU 有效值解析的默认来源。
- **关系**：上游 = 3.2.1.1；下游 = 3.2.2.2（覆写解析）。**SPU 层只设"默认"，具体 SKU 可覆写或显式清空**。

### 3.2.2.2 SKU 属性覆写

- **职责**：对单个 SKU 覆写 SPU 公共属性值，或显式清空（区别于"未设置"）。展示解析后的最终有效值，并标注"来自 SPU / SKU 覆写 / 未设置"。
- **输入**：覆写/清空操作；SPU 公共值；类目必填校验。
- **输出**：覆写记录 + 有效值解析结果；缺失必填项时阻止保存。
- **关系**：上游 = 3.2.2.1；下游 = 04 刊登（属性映射）、12 财务（成本相关属性）。**"显式清空"与"未设置"必须是两种状态**，否则无法表达"这个 SKU 确实没有该属性"。

### 3.3.1.1 分类树管理

- **职责**：维护多级商品分类树（支持多棵树，如内部管理分类与平台类目映射），支持拖拽调整层级、防环、启用停用、主分类与辅助分类区分。
- **输入**：分类增删改、拖拽排序、启用停用；多语言分类名。
- **输出**：分类树结构 + 路径串 + 各分类下的商品数统计。
- **关系**：上游 = —；下游 = 3.1.1.1（筛选）、4 刊登（平台类目映射）、13 分析（品类维度）。**分类是多棵独立的树，不能混为一棵**——内部类目与平台类目的维护节奏完全不同。

### 3.3.1.2 类目属性要求

- **职责**：按类目配置必填属性、可选属性与取值范围，驱动商品录入时的校验与录入表单动态生成。
- **输入**：类目属性规则配置；属性定义。
- **输出**：录入表单 schema；保存前的校验结果。
- **关系**：上游 = 3.2.1.1、3.3.1.1；下游 = 3.1.1.2 商品编辑、04 刊登表单。**不同平台的类目要求可能不同**，平台侧要求在 04 按平台维护，此处只管内部类目。

### 3.3.2.1 品牌管理

- **职责**：维护品牌字典：名称、多语言名、Logo、授权状态（自有/代理/需授权）、关联类目，用于 16 合规的侵权判断与刊登的品牌字段。
- **输入**：品牌定义；授权状态维护（可引用 16 的授权凭证）。
- **输出**：品牌记录；刊登与合规的引用候选。
- **关系**：上游 = 16 合规（授权凭证）；下游 = 04 刊登、16 侵权检测。**品牌授权状态直接影响能否刊登**，品牌"需授权"但无有效凭证时应阻止发布。

### 3.3.3.1 计量单位

- **职责**：维护单位字典：单位编码、名称、所属量纲（重量/长度/体积/数量/包装）、数量精度、是否可用于采购/销售/存储，并定义单位组内的换算关系。
- **输入**：单位定义与换算系数；精度设置。
- **输出**：单位记录 + 换算查询能力。
- **关系**：上游 = —；下游 = 3.1.2.4、06 采购、07 库存、08 拣货。**量纲不匹配的单位之间不允许换算**（如"件"不能换算成"千克"）。

### 3.4.1.1 媒体库

- **职责**：集中管理图片与视频：上传、分类标签、引用计数（被哪些 SPU/SKU/listing 使用）、版本、失效检测。支撑批量刊登时的"素材库复用"。
- **输入**：文件上传；标签/分类；使用查询。
- **输出**：媒体对象元数据（存储键、尺寸、格式、哈希）；删除保护（有引用不可删）。
- **关系**：上游 = 4 刊登（引用）；下游 = 3.4.1.2 处理、04 批量上传。**媒体用对象存储 + 元数据本地管理的组合**（实体目录 §4），不把二进制存业务库。

### 3.4.1.2 图片处理

- **职责**：对图片做刊登前的加工：白底、去背景、水印添加、尺寸裁剪到平台要求、格式转换、生成多比例版本（如主图 1:1 + 缩略图）。
- **输入**：原图 + 处理参数（目标平台规格）；批处理任务。
- **输出**：处理后图片 + 处理任务记录（成功/失败原因）。
- **关系**：上游 = 3.4.1.1；下游 = 04 刊登上传。**处理是异步任务**，长批量不阻塞页面；处理结果不可逆覆盖原图，原图始终保留。

### 3.4.2.1 标题库

- **职责**：沉淀可复用的标题模板与标题记录，支持变量占位（品牌+品类+核心词+卖点），批量生成差异化标题（同一商品在多平台不同标题以避重复铺货判定）。
- **输入**：标题模板；批量生成参数（SKU 范围、平台、词根）。
- **输出**：生成的标题候选集；供 04 选用或导出。
- **关系**：上游 = 3.1.1.1；下游 = 04 刊登。**批量生成要保证"相似但不雷同"**，需在生成算法中显式控制重复度。

### 3.4.2.2 描述与卖点库

- **职责**：管理详情描述模板、卖点短语库、使用说明、注意事项，支持变量占位与多语言版本，供刊登批量填充。
- **输入**：模板定义；变量绑定；多语言翻译（可由 18 的 AI 翻译预填）。
- **输出**：填充后的描述文本（分语言）；供 04 引用。
- **关系**：上游 = 3.4.2.1；下游 = 04 刊登、15 客服（答复话术可复用）。**变量缺失必须在填充时报告**，不能静默留下占位符。

### 3.4.3.1 多语言内容

- **职责**：维护 SPU/SKU 的多语言名称与描述（`spu_translation` `sku_translation`），按语言唯一，支持人工校对与 AI 翻译的建议采纳流程。
- **输入**：翻译文本（人工/AI 建议）；语言列表（由店铺启用的站点决定实际需要哪些语言）。
- **输出**：各语言的名称与描述记录 + 翻译状态（待翻/已翻/已校对）。
- **关系**：上游 = 18 AI 翻译、4 刊登（实际站点需求）；下游 = 04 刊登填充。**需要哪些语言由店铺启用站点推导**，不靠人肉记忆。

### 3.5.1.1 套装版本管理

- **职责**：管理组合套装（多个 SKU 按数量捆绑销售）的版本：创建版本、设置生效区间、发布后不可变。
- **输入**：套装名称、组件清单、版本号、生效区间；发布操作。
- **输出**：套装版本记录（草稿/已发布）；供 04 刊登为独立商品、供 09 订单展开组件。
- **关系**：上游 = 3.5.1.2；下游 = 3.1.2.2（套装作为可售 SKU）、09 订单（组件展开）。**虚拟套装不持有独立库存**，扣的是组件库存（实体目录 §3.4）。

### 3.5.1.2 组件维护

- **职责**：维护套装组件 SKU 与数量，校验不出现循环引用（套装 A 含套装 B 且 B 含 A）与组件数量必须大于 0。
- **输入**：组件增删改；`bundle_component` 记录；循环检测。
- **输出**：组件清单；校验结果（循环、数量非法、组件不存在均拒绝保存）。
- **关系**：上游 = 3.5.1.1；下游 = 07 库存（预占组件）、09 订单（`order_line_component` 冻结展开结果）。**已发布版本的组件不可改**，只能新建版本——历史订单冻结的是当时版本。

### 3.5.2.1 BOM 版本管理

- **职责**：维护物料清单（成品由哪些组件组成），支持多版本、版本生效区间、单位用量与损耗率，服务于委外加工与生产型卖家。
- **输入**：BOM 版本、组件行（SKU、单位用量、损耗率、生效区间）；发布操作。
- **输出**：BOM 版本记录；供 06 采购建议与 08 加工单引用。
- **关系**：上游 = 3.5.2.2；下游 = 06 采购与供应（加工采购）、08 仓储作业（组装单）。**BOM 与套装的区别**：BOM 用于生产/加工（产生实物成品），套装用于销售（虚拟扣组件）。

### 3.5.2.2 BOM 展开

- **职责**：按 BOM 版本与需求量展开出需要采购/备货的组件清单与数量，支持多层展开和按仓库过滤。
- **输入**：成品 SKU + BOM 版本 + 需求量（或基于 06/07 的缺口触发）。
- **输出**：多级展开的组件清单（含需求量、当前可用、在途、缺口）。
- **关系**：上游 = 3.5.2.1、07 库存、06 采购；下游 = 06 采购单（缺口转采购）、07 补货。**展开结果是建议不是事实**，实际采购由 06 生成单据后成立。

### 3.6.1.1 往来单位档案

- **职责**：统一维护业务主体（`party`）：企业或个人，可同时扮演供应商/客户/承运商；包含编码、名称、联系方式、状态。
- **输入**：新增/编辑往来单位；角色指派；状态变更。
- **输出**：往来单位档案 + 关联的角色档案。
- **关系**：上游 = —；下游 = 3.6.1.2 角色档案、06 采购、11 售后、12 财务。**同一主体可同时是供应商和客户，用角色档案区分，不用多份记录**（实体目录 §3.5）。

### 3.6.1.2 角色档案

- **职责**：在往来单位上挂载角色特有信息：供应商（账期、MOQ、合作等级、结算方式）、客户（客户分级、默认币种、信用额度）、承运商（接口类型、账号、服务能力）。
- **输入**：角色字段维护；账期与信用额度设置。
- **输出**：角色档案记录；供 06 采购单、12 应收应付默认取值。
- **关系**：上游 = 3.6.1.1；下游 = 06、12。**每个角色一张 1:1 档案表**，不用一个巨大可空字段表——否则"客户没有账期"和"供应商有账期"无法区分。

### 3.6.2.1 供应商报价

- **职责**：维护供应商对 SKU 的报价：供应商货号、采购单位、币种、MOQ、交期、有效期、阶梯价，支持同一供应商同一 SKU 多个报价版本与按租户优先级选择。
- **输入**：报价录入/导入；有效期；优先级设置。
- **输出**：有效报价列表（默认取优先级最高且在有效期内的版本）。
- **关系**：上游 = 3.6.1.2；下游 = 06 采购（采购单带出价格）、05 定价（成本参考）、13 利润（成本波动）。**同一优先级多条有效报价必须报错让用户选**，不能随机取一条（实体目录 catalog 价格规则）。

### 3.6.3.1 地址与联系人

- **职责**：维护往来单位的收发货地址与联系人；地址变更留历史版本。
- **输入**：地址与联系人增删改；地址版本。
- **输出**：地址与联系人记录。
- **关系**：上游 = 3.6.1.1；下游 = 06 采购（发货地址）、10 物流（提货地址）。**单据上的地址是冻结快照**，本模块改地址不影响已发生单据。

### 3.7.1.1 HS 编码与申报要素

- **职责**：维护商品的 HS 编码、原产地、申报品名、申报价值参考、法定计量单位、是否享惠（RCEP 等），供 10 报关清关生成申报资料。
- **输入**：HS 编码与申报要素维护；原产地设置。
- **输出**：报关属性记录；供申报单引用。
- **关系**：上游 = —；下游 = 10 物流与头程（报关）、16 合规（税则校验）。**HS 编码错误直接导致申报失败与罚款**，必须允许审核流程而非任意填写。

### 3.7.1.2 目的地报关版本

- **职责**：维护同一 SKU 在不同目的地国家的报关差异（不同税号、不同申报品名、不同认证要求），按目的地版本化。
- **输入**：目的地国家；对应报关版本内容；生效区间。
- **输出**：按目的地查询的有效报关版本。
- **关系**：上游 = 3.7.1.1；下游 = 10 报关、12 财务（关税成本）、16 合规（认证要求）。**不同目的地必须用不同版本**，不能用一套申报资料打通全球。

### 3.7.2.1 物理与安全属性

- **职责**：维护裸品物理参数（长宽高、净重、毛重、包装方式）与安全属性（是否带电、是否液体、是否危险品、是否磁性），决定可走哪些物流渠道与是否需要特殊申报。
- **输入**：物理参数与安全属性设置；包装信息。
- **输出**：SKU 物理档案；供 10 物流渠道筛选、8 拣货装箱体积核算。
- **关系**：上游 = —；下游 = 10 物流（渠道适配、体积重）、16 合规（危险品与认证）。**这些属性直接决定物流可用性**，采集时点应尽量前置到 SKU 建档。

### 3.8.1.1 导入向导

- **职责**：批量导入商品（SPU/SKU/属性/包装/条码/报价），四步引导：下载模板 → 上传文件 → 字段映射 → 预校验 → 执行。
- **输入**：Excel/CSV 文件；字段映射配置；导入模式（新增/更新/按编码匹配）。
- **输出**：导入任务 + 结果统计。
- **关系**：上游 = —；下游 = 3.8.1.2 校验报告。**导入是异步任务**，大文件不阻塞页面；同一租户同时只允许一个同类导入任务，避免并发覆盖。

### 3.8.1.2 校验报告

- **职责**：展示逐行校验结果：必填缺失、格式错误、重复编码、引用不存在（分类/品牌/属性）、唯一冲突。区分"可跳过"与"必须修正"，允许导出带标注的错误文件。
- **输入**：导入预校验结果。
- **输出**：错误明细表 + 可下载的修正版模板。
- **关系**：上游 = 3.8.1.1；下游 = 无（修正后重新上传）。**校验失败的行不落库**，不允许"尽力导入"产生半截数据。

### 3.8.2.1 导出

- **职责**：按当前列表页的筛选条件导出结果数据（SPU/SKU/库存视图/报价等），支持字段选择、排序还原与大文件异步导出，导出记录可追溯到操作人。
- **输入**：列表筛选条件；字段选择；导出请求；用户数据范围。
- **输出**：导出文件（带下载有效期）+ 导出记录（条件、字段、行数、时间、操作人）。
- **关系**：上游 = 3.1.1.1 / 3.1.2.1 / 3.6.2 等列表页；下游 = 用户本地文件；大批量统一走 18.1.3.1 导入导出任务通道。**导出必须服从数据范围与 PII 授权**：含联系方式等敏感字段的导出需显式授权并留审计（见 16.6.1）。

### 3.9.1.1 重复 SKU 识别

- **职责**：识别重复/近重复商品：同 SPU 下重复规格组合、同商品不同 SPU 重复建档、同条码多 SKU、近似标题+相似图片疑似同品，输出候选与相似度供人工确认。
- **输入**：商品与 SKU 全量；条码、标题、属性、图片特征。
- **输出**：重复候选清单（相似度、重叠维度、影响引用数）；确认合并/保留决定。
- **关系**：上游 = 3.1.1.1/3.1.2.1；下游 = 3.9.1.2。**重复 SKU 会污染销量、采购、库存与利润统计**（同一商品被拆成两条，各算各的），治理的价值在于报表可信。

### 3.9.1.2 SKU 合并

- **职责**：执行 SKU/SPU 合并：把重复记录归并到主记录，迁移关联（listing 映射、库存 bucket、采购历史、价格、订单快照保留指向），原记录标记合并并停用而非物理删除；可回溯合并来源。
- **输入**：合并决定（主记录、被合并记录）；`expected_version`。
- **输出**：合并结果；引用迁移报告；原记录合并标记。
- **关系**：上游 = 3.9.1.1；下游 = 04 映射、07 库存、06 采购。**历史订单行冻结当时 SKU 快照，不随合并回溯改写**（实体目录 §3.6）——只迁移"当前引用"（映射/库存/价格），历史事实保持冻结。

### 3.9.2.1 完整度评分

- **职责**：给每个 SPU/SKU 打主数据完整度分：必填属性、类目必填、图片数量与尺寸、报关属性（HS 编码、申报品名）、包装尺寸重量、认证；按分数分档，驱动补全清单。
- **输入**：主数据集合；类目必填规则；16 认证状态。
- **输出**：完整度评分卡 + 缺失项清单 + 批量补全入口。
- **关系**：上游 = 3.1/3.2/3.7、16 合规；下游 = 4.2.3.2 预检、3.8 批量导入。**完整度直接决定能否刊登与能否清关**，是主数据质量与业务动作的连接点。

### 3.9.2.2 僵尸主数据清理

- **职责**：识别僵尸主数据：从未被订单引用、无库存、无 listing、成本为 0、长期未维护的 SKU/供应商/客户，输出候选并支持批量停用；避免报表与下拉被无效数据淹没。
- **输入**：引用统计；时间范围；清理规则配置。
- **输出**：僵尸清单 + 停用/保留决定 + 停用记录。
- **关系**：上游 = 3.1.1.3 生命周期；下游 = 3.1.1.1 列表。**停用而非删除**（主数据被引用后只能停用，实体目录 §5），确保历史单据仍可展示。
