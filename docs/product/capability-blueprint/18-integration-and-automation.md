# 18 集成开放与智能自动化系统

> **定位**：让 starcon 能被接入、能对外提供能力、能自动干活。规则引擎与 AI 都建在这一层。
> **后端归属**：`platform` 公共能力 + 各服务内的事件/outbox/inbox。
> **前端入口**：`/integrations` `/copilot`

## 边界

**做**：开放 API 与访问凭证、Webhook 订阅、导入导出通道、外部系统对接（金蝶/用友/支付/ERP）、业务规则引擎、AI 助手与智能功能、通知模板与投递。

**不做**：不提供任何绕过平台官方 API 的模拟登录能力（合规红线）、不代替用户做会计与经营决策、不把 AI 结果直接写为业务事实（未经确认的建议不落库）。

**关键约束**：

- **AI 输出必须可解释、需确认**，直接改价改库存必须人工或规则确认
- 对外 API 严格按租户隔离 + 权限校验 + 限流 + 审计
- 规则引擎必须**幂等、可重放、可追溯**，同一触发条件重复执行结果一致
- AI 处理买家 PII 必须脱敏，且不留存到训练日志

## 详细设计

### 18.1.1.1 应用与凭证

- **职责**：管理第三方接入的应用：应用注册、API Key/Secret 生成与轮换、授权范围（可访问的资源与操作）、IP 白名单、调用配额。
- **输入**：应用注册；凭证轮换；授权范围配置。
- **输出**：应用档案 + 凭证（**明文仅在生成时展示一次**，之后只存摘要）。
- **关系**：上游 = 17 权限；下游 = 18.1.1.2 接口目录。**对外凭证与平台凭据同等对待**：不落库明文、访问有审计、泄露可一键吊销。

### 18.1.1.2 接口目录

- **职责**：对外开放 API 的目录与文档：按业务域列出接口、参数、返回、限流说明、示例；支持在线测试（沙箱环境）。
- **输入**：接口定义（OpenAPI 生成物）；测试请求。
- **输出**：接口文档 + 测试结果。
- **关系**：上游 = 后端 OpenAPI spec（单一真相源）；下游 = 外部系统。**接口契约由后端 spec 生成，文档不手写**——手写文档必然与实现漂移。

### 18.1.1.3 调用监控

- **职责**：监控 API 调用：QPS、错误率、限流命中、慢调用、按应用与接口维度分析，异常告警。
- **输入**：调用埋点；配额配置。
- **输出**：调用统计 + 告警。
- **关系**：上游 = API 网关；下游 = 1 工作台告警、18.1.1.1 配额调整。**外部系统调用错误要能被快速定位**，否则对接方只会说"你们接口有问题"。

### 18.1.2.1 事件订阅

- **职责**：对外提供事件订阅（webhook）：可订阅事件列表、订阅端点配置、签名密钥、事件过滤、重试与死信策略。
- **输入**：订阅配置；事件定义（schema 版本）。
- **输出**：订阅记录；事件投递（带签名）。
- **关系**：上游 = 业务事件（outbox）；下游 = 外部端点。**事件 schema 必须版本化**，破坏性变更要新增版本而非原地修改。

### 18.1.2.2 投递记录

- **职责**：记录事件投递明细：事件 ID、订阅方、投递状态、响应码、重试次数；提供手动重投与死信重放。
- **输入**：投递记录；重放请求。
- **输出**：投递日志 + 重放任务。
- **关系**：上游 = 18.1.2.1；下游 = 外部端点。**接收方应按 event_id 幂等去重**——投递保证是"至少一次"，不是"恰好一次"。

### 18.1.3.1 导入导出任务

- **职责**：统一的数据导入导出通道：任务创建（选择数据域与范围）、异步执行、进度跟踪、结果下载、失败行报告、模板下载。
- **输入**：导出/导入请求；文件上传。
- **输出**：任务记录 + 文件（带有效期）+ 错误报告。
- **关系**：上游 = 全部业务域；下游 = 用户本地文件。**大文件一律异步**，并在下载链接上设置有效期，避免存储无限增长。

### 18.1.3.2 数据迁移

- **职责**：支持从其他 ERP 迁移历史数据：映射配置（外部字段 → 内部模型）、试运行预览、正式迁移、失败回滚与核对报告。
- **输入**：源数据文件；字段映射配置。
- **输出**：迁移任务 + 迁移核对报告（成功/失败/跳过数量与原因）。
- **关系**：上游 = 18.1.3.1；下游 = 各业务域。**历史数据迁移必须支持试运行**，直接正式跑会产生大量脏数据难以回退。

### 18.2.1.1 财务软件

- **职责**：对接第三方财务软件（金蝶、用友、SAP、Odoo）：凭证推送、科目映射、主数据同步、余额核对；导出标准凭证文件（Excel/XML）。
- **输入**：凭证数据；科目映射配置；对账需求。
- **输出**：推送结果；凭证文件；核对差异。
- **关系**：上游 = 12.5.2.1 凭证；下游 = 外部财务软件。**业财一体化的常见做法是本系统管业务账、外部软件管法定账**，两边通过凭证文件与科目映射衔接。

### 18.2.2.1 支付与资金

- **职责**：对接支付与资金服务（PayPal、Stripe、PingPong、连连、万里汇）：余额查询、收款登记、付款执行、汇率查询、手续费明细同步。
- **输入**：资金操作请求；接口配置（密钥引用）。
- **输出**：操作结果 + 资金流水同步。
- **关系**：上游 = 12.2 收付款、12.7 资金账户；下游 = 支付服务商。**所有第三方资金操作必须有幂等键与查询兜底**，超时先查证再重试（实体目录 §6）。

### 18.2.3.1 其他对接

- **职责**：对接其他外部系统：1688/淘宝货源平台、海外仓服务商、物流商、聚合认证服务、自建 BI。统一管理连接配置与同步健康。
- **输入**：连接配置；同步任务配置。
- **输出**：连接状态 + 同步记录。
- **关系**：上游 = 2 渠道机制；下游 = 外部服务。**每个对接都有独立连接与独立健康状态**，一个外部服务故障不应影响其他集成。

### 18.3.1.1 规则列表

- **职责**：管理自动化规则：规则名称、触发事件、条件（过滤）、动作（多步）、优先级、启用范围（租户/店铺/仓库）、试运行开关、执行统计。
- **输入**：规则增删改；启用停用；排序。
- **输出**：规则档案 + 执行统计。
- **关系**：上游 = 各业务事件；下游 = 18.3.1.2 编辑器、18.3.2.1 执行日志。**规则要能看出最后一次执行结果**，否则坏规则静默失败无人察觉。

### 18.3.1.2 规则编辑器

- **职责**：可视化编辑规则：选择触发事件 → 配置条件（字段/操作符/值）→ 编排动作（调接口/改状态/建任务/发通知/生成单据）→ 测试与保存。
- **输入**：规则配置；测试样本数据。
- **输出**：规则定义；测试运行结果。
- **关系**：上游 = 18.3.1.1；下游 = 18.3.2 执行。**规则必须支持用样本测试**，否则只能在生产上试错。

### 18.3.2.1 执行日志

- **职责**：记录每次规则执行：触发事件、条件命中情况、执行的动作、每步结果、耗时、错误；支持查看上下文与手动重跑。
- **输入**：执行记录；重跑请求。
- **输出**：执行明细 + 失败原因定位。
- **关系**：上游 = 18.3.1.2；下游 = 1 工作台告警。**规则必须幂等**：同一事件重复触发不能重复执行副作用（如重复改价、重复建单）。

### 18.3.2.2 规则效果

- **职责**：统计规则效果：触发次数、成功率、平均耗时、节省工时预估、误触发反馈与规则优化建议。
- **输入**：执行日志聚合。
- **输出**：规则效果报表。
- **关系**：上游 = 18.3.2.1；下游 = 18.3.1.1（优化依据）。**误触发率高的规则要能快速定位并关闭**，自动化失控比没有自动化更危险。

### 18.3.3.1 自动审批

- **职责**：自动化审批场景：自动通过低风险小额单据、自动驳回明显不合规单据、金额分层路由审批人、超时自动升级。
- **输入**：审批规则配置；单据风险信号。
- **输出**：自动审批结果 + 决策依据记录。
- **关系**：上游 = 17.4 审批；下游 = 各业务系统。**自动审批只处理"明确安全"的场景**（小额 + 供应商已验证 + 无风险信号），其余仍走人工——审批是内控底线。

### 18.4.1.1 对话助手

- **职责**：自然语言助手：用中文提问业务问题（"上周哪个店利润最差""哪些 SKU 该补货了"），返回答案并附数据来源链接；支持追问与上下文延续。
- **输入**：用户问题；当前上下文（租户、数据范围、当前页面）。
- **输出**：答案 + 数据明细链接 + 建议的下一步操作。
- **关系**：上游 = 各域只读查询接口；下游 = 无（只读）。**答案必须附明细链接**——不给依据的 AI 数字不能用于决策。

### 18.4.1.2 智能查询

- **职责**：结构化智能查询：自然语言转查询条件（筛选、聚合、排序），生成报表草稿，支持保存为常用查询。
- **输入**：自然语言查询意图；可用指标与维度清单。
- **输出**：查询结果表 / 报表配置草稿。
- **关系**：上游 = 18.4.1.1；下游 = 13.6.1.1 自定义报表。**自然语言只映射到受控语义层指标**，不生成任意 SQL。

### 18.4.2.1 文本与翻译

- **职责**：AI 文本能力：多语言翻译（标题/描述/客服话术，支持保留品牌词与专业术语）、标题优化与生成、卖点提炼、违禁词规避建议、客服回复草稿。
- **输入**：源文本；目标语言；风格要求；术语表。
- **输出**：翻译/生成结果 + 置信度提示 + 可人工编辑。
- **关系**：上游 = 3.4.3 多语言、4.2.1.1 编辑器、15.1.1.2 发送；下游 = 无（结果需人工确认）。**翻译结果必须人工确认后发布**，直接发机器翻译是品牌风险。

### 18.4.2.2 选品与需求预测

- **职责**：AI 预测能力：销量预测（含促销与大促影响）、补货量建议、价格弹性与调价建议、爆品识别与机会品发现。
- **输入**：历史销量、库存、在途、价格、促销日历；预测参数。
- **输出**：预测结果 + 置信区间 + 关键影响因素说明。
- **关系**：上游 = 13 分析、6 采购、7 库存；下游 = 6.2.1.2 补货建议、5.4 调价。**预测必须给置信区间和影响因素**，单点数字会让用户过度信任；建议只作为参考输入，不自动执行。

### 18.4.2.3 异常诊断

- **职责**：AI 异常诊断：对库存异常、利润异常、发货延迟、同步失败、广告亏损等给出可能原因分析（自动关联相关数据）与处置建议。
- **输入**：异常事件 + 关联数据（订单、库存、成本、历史记录）。
- **输出**：诊断结论 + 依据 + 建议动作。
- **关系**：上游 = 1 工作台待办、各域异常；下游 = 对应处理页。**诊断要给依据**（"因为 SKU X 的头程成本上涨 18%"），不能只给结论。

### 18.4.3.1 使用与配额

- **职责**：管理 AI 使用：按租户与用户的调用量与成本、配额限制、模型选择、敏感数据处理策略开关。
- **输入**：调用记录；配额配置。
- **输出**：用量报表 + 配额执行。
- **关系**：上游 = 18.4 全部；下游 = 17.6.1 计费。**AI 是有边际成本的能力**，必须可计量可限额，否则成本不可控。

### 18.4.3.2 效果评估

- **职责**：评估 AI 功能效果：翻译采纳率、预测准确度回测、助手答案有用性反馈，识别低价值功能并下线。
- **输入**：人工采纳/修改记录；预测回测结果；用户反馈。
- **输出**：效果报表 + 改进建议。
- **关系**：上游 = 18.4 全部；下游 = 18.4 迭代。**采纳率是 AI 功能唯一诚实的指标**——生成了但没人用的功能应下线。

### 18.5.1.1 模板管理

- **职责**：管理通知与消息模板：模板内容、变量、适用场景、语言版本、启用状态；修改后新产生的通知使用新版本，历史通知保留当时内容。
- **输入**：模板编辑；变量定义。
- **输出**：模板记录 + 渲染预览。
- **关系**：上游 = 3.4.2 文案资产；下游 = 1.3.1.1、15.1.1.2、18.5.2。**模板必须版本化**，已发出的通知不能被新模板"篡改"。

### 18.5.2.1 投递记录

- **职责**：记录通知投递结果：模板、收件范围、渠道、状态、失败原因、重试；统计触达率与退订情况。
- **输入**：投递记录；重试请求。
- **输出**：投递日志 + 统计。
- **关系**：上游 = 18.5.1；下游 = 1.3.2.2 外部推送、15.5.2 触达。**退订必须被尊重并生效**，反复触达退订用户是投诉与合规风险的主要来源。
