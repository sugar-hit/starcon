# 01 工作台与门户系统

> **定位**：starcon 的统一入口。不产生新的业务事实，只聚合各系统的投影，让用户一屏知道"现在该我做什么"。
> **后端归属**：前端聚合层 + 各服务的只读投影（不新增业务服务）。
> **前端入口**：`/`（工作台，默认落地页）、顶部固定区、右侧通知抽屉。

## 边界

**做**：跨域聚合、待办与异常收敛、全局检索、个人布局与偏好、消息订阅。
**不做**：任何写业务数据的操作。工作台只读 + 跳转；一切状态变更回到归属系统完成（除布局偏好这类纯个人配置）。

**关键设计约束**：工作台的所有数字都是**投影**，允许秒级延迟，不允许与业务系统不一致到需要解释的程度。任何在此处出现的指标都必须能点进去看到明细，且明细口径与此处一致。

## 功能职责（L2）

| 功能                   | 职责                                                                                                             | 主责服务              |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------- |
| **1.1 今日工作台**     | 把散落在 12 个系统的"需要人处理"的动作收敛成一屏，按紧急度排序并直达处理页；同时给出经营指标的当日快照与风险水位 | 前端聚合 + 各服务投影 |
| **1.2 全局检索与导航** | 提供跨系统的一处搜索与个性化入口，降低在多层菜单中翻找的成本                                                     | 前端 + 跨服务只读索引 |
| **1.3 消息与预警**     | 承载系统通知与用户自定义预警规则，把"该关注的事"主动推给对的人                                                   | support + 各域事件    |

## 详细设计

### 1.1.1.1 我的待办

- **职责**：把散落在 12 个系统的"需要人处理"的动作收敛成一条按紧急度排序的队列，每项都有明确的下一步入口。覆盖：超期未发货、待审订单、库存缺口、待处理同步失败、待核对账差异、待回复站内信、待审批单据、库存低于安全线。
- **输入**：用户点击刷新；各系统的待办投影事件（如 `order.overdue`、`inventory.below_safety`、`sync.failed`、`reconciliation.diff`）；用户当前身份与**数据范围**（法人/店铺/仓库/部门）。
- **输出**：待办卡片列表（类型、单据引用、严重度、停留时长、下一步链接）；点击直达归属系统的处理页并带上定位参数；未读计数角标。
- **关系**：上游 = 09 订单、07 库存、02 渠道、12 财务、15 客户、17 审批；下游 = 各系统的处理页（`/orders`、`/inventory`、`/notifications`）。共享数据：`membership`、`role_assignment_scope`（决定用户能看到哪些待办）。**不写业务数据**，只读投影。

### 1.1.1.2 异常订单队列

- **职责**：识别"卡住了"的订单并给出处置建议。异常类型：平台超时未回传发货、地址不可达、买家留言待确认、黑名单买家、库存不足卡单、地址欺诈疑似、重复下单。
- **输入**：`order.status_history` 投影、`order_charge` 异常标记、地址规则判定结果、黑名单匹配结果（16 合规与风控）、库存可用量投影（07 库存）。
- **输出**：异常订单清单（订单号、店铺、异常类型、停留时长、建议动作）；批量标记忽略 / 转人工 / 转售后；生成的处理工单。
- **关系**：上游 = 09 订单、07 库存、16 合规；下游 = 09 订单处理页、11 售后（转售后）、02 渠道（平台侧查询）。共享数据：`sales_order` 摘要、`listing` 映射状态。

### 1.1.1.3 审批待办

- **职责**：待我审批的单据统一入口，支持按单据类型、业务域、金额阈值、超时时长筛选；展示审批链路当前节点与已耗时长。
- **输入**：17 组织权限系统的 `approval_instance` 投影；用户角色与审批人规则。
- **输出**：待审批列表（单据头信息、金额、申请人、停留时长、节点）；跳转到 17 的审批详情页。
- **关系**：上游 = 17 组织权限与系统设置；下游 = 17 审批详情。共享数据：`approval_request`、`legal_entity`（金额阈值按法人配置）。**工作台不执行审批动作**，避免两处审批逻辑不一致。

### 1.1.2.1 核心指标卡

- **职责**：一屏展示今日/昨日/本月的销售额、订单量、销量、库存总额、毛利、回款、在途金额，每张卡带环比与同比，点击下钻到对应报表。
- **输入**：reporting 服务的聚合投影（`revenue_daily`、`order_daily_fact`、`profit_daily`）；用户数据范围；时间口径选择。
- **输出**：指标数值 + 趋势箭头 + 同比环比 + 下钻链接；口径说明悬浮提示。
- **关系**：上游 = 13 利润与经营分析、12 财务；下游 = 13 各报表页。共享数据：`legal_entity`、`shop`（按数据范围过滤）。**口径由 13 单点定义**，工作台只引用不重算。

### 1.1.2.2 店铺概览

- **职责**：按店铺横向对比当期表现（销售额、订单量、利润率、库存天数、广告花费），识别掉队店铺。
- **输入**：店铺维度聚合投影；店铺列表（02）；权限过滤后的可见店铺集合。
- **输出**：店铺对比表/卡片；点击进入该店铺在 13 的分析页。
- **关系**：上游 = 13、02、14；下游 = 13 店铺分析、09 该店铺订单。共享数据：`shop`、`shop_marketplace`。

### 1.1.2.3 履约健康

- **职责**：展示履约链路的健康水位：待发货积压、平均出库时长、超时发货率、物流异常件占比、平台绩效指标（ODR、迟发率、有效追踪率）。
- **输入**：08 仓储作业的出库时效投影；10 物流的轨迹异常投影；02 渠道同步的绩效指标。
- **输出**：健康度卡片 + 红灯项明细跳转。
- **关系**：上游 = 08、10、02；下游 = 08 出库看板、10 轨迹异常列表。共享数据：`parcel`、`shipment`、`platform_performance_metric`。

### 1.1.3.1 库存风险

- **职责**：集中呈现缺货、超卖风险、呆滞、超储四类库存问题，区分本地仓/海外仓/FBA/在途。
- **输入**：07 库存的可用量投影（按 bucket 汇总）；销售速度；06 采购的在途量；10 的头程在途。
- **输出**：风险清单（SKU、仓库、可用量、日均销、可用天数、风险类型、建议动作如"生成采购单"）。
- **关系**：上游 = 07 库存、06 采购、10 物流；下游 = 06 采购单创建、07 库存调拨、07 补货建议。共享数据：`stock_bucket`、`inventory_reservation`。

### 1.1.3.2 资金与回款风险

- **职责**：展示应收账龄、平台待结算金额、逾期应收、即将到期的供应商应付、在途资金占用。
- **输入**：12 财务的应收应付账龄投影；02 同步的结算报告；07 库存货值。
- **输出**：账龄分布图 + 逾期清单 + 待结算金额；点击进入 12 对应收款。
- **关系**：上游 = 12 财务、02 渠道、07 库存；下游 = 12 应收应付、12 收付款。共享数据：`receivable`、`payable`、`settlement`。

### 1.2.1.1 全局搜索框

- **职责**：一个输入框跨系统检索：SKU、SPU、订单号、采购单号、店铺名、供应商、物流单号、客户。返回分组结果并直接跳转到对应详情页。
- **输入**：用户键入关键词（≥2 字符）；用户租户与数据范围；最近搜索记录。
- **输出**：分组下拉结果（商品/订单/采购/物流/客户/仓库），每项带主标识 + 副信息；选中回填到对应页面的筛选器。
- **关系**：上游 = 各系统只读检索索引；下游 = 各系统详情页。共享数据：跨服务投影索引。**只做前缀/精确匹配**，不做全文语义检索；模糊搜索在各自系统列表内完成。

### 1.2.1.2 搜索结果分组

- **职责**：把多系统命中结果按业务域分组展示，显示各组数量，支持"只看某一组"，并标注结果是否在当前数据范围内。
- **输入**：全局搜索的原始命中集；用户数据范围；各系统的可访问性（权限过滤后为空则整组隐藏）。
- **输出**：分组结果视图 + 无权限结果计数提示。
- **关系**：上游 = 1.2.1.1；下游 = 各系统列表页。**无权限的组直接不返回结果**，而不是返回后再置灰。

### 1.2.2.1 常用页面收藏

- **职责**：用户把高频页面（某店铺订单、某仓库库存、某报表）收藏到工作台侧边快捷区，形成个人工作流。
- **输入**：用户收藏/取消收藏操作；页面注册表（前端路由 + 标题 + 所属系统）。
- **输出**：收藏列表（有序、支持拖拽排序）；点击直达。
- **关系**：上游 = 前端页面注册表；下游 = 各系统页面。共享数据：纯个人配置，存 `user_preference`，**不含业务数据，不受租户角色权限以外的限制**，但仍受页面级权限约束（无权限的收藏自动隐藏）。

### 1.2.2.2 快捷入口配置

- **职责**：按角色/团队预置快捷入口模板，新成员加入时自动获得岗位常用入口，减少培训成本。
- **输入**：17 系统配置的岗位模板；用户所属部门/角色；用户个人覆盖项。
- **输出**：最终生效的快捷入口集合（模板 + 个人覆盖的合并结果）。
- **关系**：上游 = 17 组织权限与系统设置；下游 = 1.2.2.1 收藏列表。共享数据：`role`、`org_unit`。

### 1.3.1.1 通知列表

- **职责**：系统级与业务级通知的统一收件箱，区分严重级别，支持已读/未读、批量处理、按类型订阅。
- **输入**：业务事件产生通知（`notification` 记录）；用户已读状态。
- **输出**：通知流（类型、严重度、时间、关联单据跳转链接）；未读计数。
- **关系**：上游 = 各系统事件（06 缺货、09 超时、10 异常、12 对账差异、15 站内信）；下游 = 对应处理页。**通知是投影，允许丢弃后重算**，不作为业务事实来源。

### 1.3.1.2 通知偏好

- **职责**：用户按通知类型选择接收渠道（站内/邮件/企业 IM）与免打扰时段。
- **输入**：用户的偏好修改；通知类型的系统枚举。
- **输出**：偏好配置；供 1.3.2.2 推送时过滤。
- **关系**：上游 = 1.3.1.1；下游 = 1.3.2.2 外部渠道推送。共享数据：`user_preference`。**关键业务通知（超期发货、账务差异）不允许被完全关闭**，系统强制保留下不可关闭的底线项。

### 1.3.2.1 预警规则

- **职责**：用户自定义阈值预警（某 SKU 库存低于 N 天、某店铺销售额环比跌超 X%、应收超期 Y 天）。系统预置跨境常用规则集，用户可改参数或关闭。
- **输入**：规则定义（对象类型、度量、阈值、时间窗、比较方向）；各系统指标投影。
- **输出**：规则命中记录 → 生成通知 + 工作台待办项；规则命中历史用于趋势观察。
- **关系**：上游 = 13 指标、07 库存、12 应收；下游 = 1.1 待办、1.3 通知。共享数据：投影指标。**规则引擎本体在 18 系统**，此处只做配置界面。

### 1.3.2.2 外部渠道推送

- **职责**：把选定的通知推送到企业 IM（企业微信/钉钉/飞书）或邮件，支持卡片化消息与点击跳转。
- **输入**：1.3.1.2 偏好；1.3.2.1 命中；外部渠道 Webhook 地址（存密钥管理器引用）。
- **输出**：外部渠道投递记录（成功/失败/重试）；失败自动重试并告警。
- **关系**：上游 = 1.3.1、1.3.2.1；下游 = 外部 IM。**凭据不落库**，只存 secret manager 引用（见 18 集成系统）。

### 1.4.1.1 工作台布局

- **职责**：用户拖拽调整指标卡顺序、隐藏不需要的卡片、选择默认落地 Tab。
- **输入**：拖拽/显隐操作；系统可选卡片清单。
- **输出**：个性化后的工作台布局；可重置为默认布局。
- **关系**：上游 = 前端卡片注册表；下游 = 1.1 全部卡片渲染。**布局是纯个人偏好，不进业务库**。

### 1.4.1.2 列表与表格偏好

- **职责**：记住各列表页的列显示、排序、分页大小、筛选条件，降低重复操作成本。
- **输入**：用户在列表页的列显隐/排序/分页操作；`user_preference`。
- **输出**：下次进入该页时恢复上次的视图状态。
- **关系**：上游 = 各系统列表页；下游 = 各列表页初始状态。**偏好按页面 key 存储**，新增字段不影响旧偏好。

### 1.4.2.1 语言与时区

- **职责**：界面语言（中文/英文等）与展示时区，影响时间显示与日期分组，不改变存储时区。
- **输入**：用户选择；平台站点时区清单。
- **输出**：界面语言包与时间显示口径。
- **关系**：上游 = 02 平台时区参数；下游 = 全站时间渲染。**存储统一 `timestamptz`**，只在展示层转换；业务日期口径由各单据自己定义。

### 1.4.2.2 默认店铺与仓库

- **职责**：设定默认进入的店铺与默认操作的法人/仓库，减少每次进入的重复选择。
- **输入**：用户选择；用户有权限的店铺/仓库集合。
- **输出**：默认上下文，注入后续页面初始筛选。
- **关系**：上游 = 02 店铺、08 仓库、17 权限；下游 = 09、07、13 各页面的默认筛选。**默认值必须在权限范围内**，权限变更后自动失效并回落。

### 1.5.1.1 同步与 API 健康

- **职责**：一屏回答"现在能不能正常同步"：各平台连接状态、最近同步时间、失败计数、限流命中、队列积压，按店铺/连接展示红黄绿。
- **输入**：channel 的连接与同步运行指标（2.2.2.1、2.4.1.1）；事件积压与失败队列计数。
- **输出**：连接健康卡片 + 需处理项跳转（重授权、看失败队列、查积压）。
- **关系**：上游 = 02 渠道与店铺；下游 = 2.2.1.2 重新授权、2.4.2.1 失败队列。**这是跨系统排查的起点**：用户反馈"没同步/没订单"时，第一个该看的页面，而不是让人在 5 个页面里找。

### 1.5.1.2 数据一致性体检

- **职责**：跨域一致性自检：库存账实核对结果、待处理对账差异率、库存准确率、订单/履约/财务三方金额差异、待处理映射缺失数，给出健康结论。
- **输入**：7.1.2.2 账实核对、12.3.2 对账差异、7 库存准确率、2.4.2.3 映射缺失。
- **输出**：一致性体检报告（分项健康 + 异常清单 + 处置入口）。
- **关系**：上游 = 07 库存、12 财务、02 渠道；下游 = 各差异处理页。**一致性指标是账可信的底线**，低于阈值应阻断结算与对账出结论。

### 1.5.2.1 服务与任务状态

- **职责**：展示平台自身运行状态：后台任务/同步任务最近运行与耗时、失败任务、计划任务是否停滞，便于运维与用户自助判断"是系统问题还是数据问题"。

- **关系**：上游 = 02、18；下游 = 1.3 通知。**区分"系统故障"与"业务数据问题"**，避免把同步失败当成商品/订单问题排查。
