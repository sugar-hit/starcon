# IAM：登录、用户与租户

## 产品目标

用户只登录一次，在明确获授权的企业工作空间内使用 ERP。租户所有者从独立组织管理入口管理用户与成员、角色、部门和子租户，不需要进入商品中心或持有商品查看权限。

## 对象与职责

- 用户：全局登录账号，可加入多个租户。租户管理员不能因为拥有一个 membership 就修改用户在其他租户的身份。
- 租户：业务数据、安全和管理边界。子租户独立授权，不继承父租户业务权限。
- 成员：用户在目标租户的身份，可启用、停用、分配部门和多个角色。移除成员不等于删除全局用户。
- 角色分配：页面动作和 ALL / DEPARTMENT / SELF 范围共同校验；管理写操作继续要求所有者。
- 店铺：渠道业务资源，第三方平台授权不等于 ERP 登录。

## 页面与流程

| 地址               | 产品职责                                                                       |
| ------------------ | ------------------------------------------------------------------------------ |
| `/login`           | 独立登录页；账号密码验证；多成员时明确选择工作空间；错误重试；成功回到原访问页 |
| 顶栏               | 全局当前租户、切换租户、我的账户、组织管理和退出；没有演示提权开关             |
| `/account`         | 查看当前已认证账号 ID、成员身份和角色，不捏造邮箱、姓名或可编辑能力            |
| `/org`             | 当前租户概览与可用管理任务                                                     |
| `/org/members`     | 新建本地账号或关联已有账号；部门与角色分配；成员启停、移除、所有者转移         |
| `/org/roles`       | 角色、页面权限与范围配置                                                       |
| `/org/departments` | 部门维护                                                                       |
| `/org/children`    | 子租户建立、指定首位所有者、租户状态维护                                       |

保留四个业务系统；组织能力由全局入口直达，运营导航保留组织快捷入口。旧 `/products/{roles,members,departments,children}` 仅重定向到新地址。

## 状态与验收

1. 未认证访问任意业务页面显示独立登录，业务内容不挂载；styleguide 为公开设计预览。
2. 登录后刷新与跨模块访问复用 HttpOnly 会话。认证失败清空整个应用会话，不仅清空商品列表。
3. 多租户选择只展示服务端返回的有效成员；不接受客户端租户头作为授权。
4. 租户切换需提示未保存内容，成功后卸载旧工作区及表单，返回工作台；失败保留当前身份并显示错误。
5. 成员管理和组织概览不请求 catalog 服务；无商品权限仍可使用获授权的组织功能。
6. 退出撤销服务端会话，再清空前端；失败不能假装退出成功。
7. 无权限与加载失败分别显示；按钮不能绕过后端角色、所有者和 RLS 检查。
8. 登录密码不写浏览器存储；敏感 token 仅经同源代理写 HttpOnly cookie。

## 分期边界

本轮交付现有认证/管理能力的应用级产品化及完整迁移。保留本地账号开通方式，不冒充邮件邀请。
后续增量：邮件邀请与找回密码、个人资料和自助改密、MFA/SSO、设备与会话撤销、审计查询、根租户自助注册与套餐开通。它们需要邮件或 IdP 集成、认证凭据生命周期与防滥用设计，不能用前端原型宣称已实现。

研究依据见 [调研](../../investment/2026-09-28-saas-iam.md)，授权规则继续遵守 ADR-0002 / ADR-0005。
