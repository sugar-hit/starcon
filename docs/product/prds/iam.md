## 1. 摘要

为跨租户 ERP 用户提供一次登录、显式选择工作空间、可靠会话和独立组织管理入口；所有访问都以服务端成员关系、角色动作和数据范围为准，不把商品权限或客户端租户标识当作 IAM 授权依据。

本文 §6–§12 是待验收的产品要求，不能据此认定当前实现全部满足。代码中可定位登录、切换、退出及组织管理入口；未保存内容保护、认证全链路审计与跨标签页并发行为仍需逐项验收。

## 2. 背景与问题

starcon 的一个全局用户可以加入多个租户，同一租户内又可能拥有多个角色。IAM 曾嵌在商品中心，导致登录、租户切换和成员管理错误依赖商品页面及 catalog 权限，也容易混淆以下对象：

- **用户（User）**：全局登录主体，可加入多个租户。
- **租户（Tenant）**：业务数据、安全和管理边界；子租户也是独立边界。
- **成员（Membership）**：用户在目标租户中的身份，可被启用、停用或移除。
- **角色分配（Role assignment）**：在目标租户内同时授予动作与数据范围。
- **店铺（Shop）**：渠道业务资源；第三方店铺授权不等于 ERP 登录身份。

如果这些对象继续混用，会产生跨租户越权、伪退出、切换后残留旧数据以及“无商品权限就无法管理组织”等问题。

## 3. 目标与非目标

### 3.1 目标

1. 未认证用户无法挂载或短暂看到业务工作区。
2. 一个有效登录会话可跨业务模块复用，并可由服务端撤销。
3. 多成员用户只可进入服务端确认有效的租户，切换后不残留原租户数据与操作上下文。
4. 租户所有者无需 catalog 权限即可管理成员、角色、部门和子租户；普通角色仅按权限查看。
5. 所有关键 IAM 操作都有明确失败反馈和可审计结果。

### 3.2 非目标

本基线不提供邮件邀请、找回密码、个人资料编辑、自助改密、MFA、SSO、设备/会话列表、根租户自助注册、套餐开通或完整审计查询。已有本浏览器头像自定义仅为本地偏好，不代表服务端资料或跨设备同步。上述账号能力需要凭据生命周期、防滥用、邮件或 IdP 集成，应分别立项，不用前端占位宣称可用。

## 4. 用户、权限与数据范围

| Persona      | 主要任务                                              | 必要权限                                                    |
| ------------ | ----------------------------------------------------- | ----------------------------------------------------------- |
| 普通成员     | 登录、选择/切换已有工作空间、查看自己的成员身份、退出 | 有效成员关系                                                |
| 组织管理员   | 按授权查看部门、成员和角色                            | 目标租户相应页面动作 + 同一角色分配内的数据范围             |
| 租户所有者   | 维护成员、角色和部门，创建子租户及转移所有权          | 目标租户 Owner；不能由普通管理角色替代                      |
| 平台支持人员 | 排查认证或授权故障                                    | 不在本 PRD 内授予业务数据访问；任何支持通道需另行设计和审计 |

父租户关系不授予子租户访问权。租户管理员也不能因为拥有一个成员关系而修改用户在其他租户的身份。

## 5. 范围与信息架构

### 5.1 本期范围

| 地址/入口          | 产品职责                                                                  |
| ------------------ | ------------------------------------------------------------------------- |
| `/login`           | 账号密码验证、多成员时选择工作空间、错误重试、成功后安全回到原应用内地址  |
| 顶栏账户入口       | 显示当前租户，提供租户切换、我的账户、组织管理和退出                      |
| `/account`         | 查看当前认证账号 ID、当前成员身份与角色；不展示不存在的资料字段或编辑能力 |
| `/org`             | 当前租户概览及用户有权执行的管理任务                                      |
| `/org/members`     | 创建本地账号或关联已有账号；分配部门与角色；成员启停、移除和所有者转移    |
| `/org/roles`       | 角色、页面动作和数据范围配置                                              |
| `/org/departments` | 平级部门维护；部门树另行交付                                              |
| `/org/children`    | 创建子租户、指定首位所有者和维护租户状态                                  |

旧 `/products/{roles,members,departments,children}` 仅用于兼容重定向，不再作为功能入口。

### 5.2 范围外

见 §3.2；此外，店铺授权由“渠道与店铺”负责，商品访问由 catalog 的权限与 RLS 负责，均不在 IAM 页面中复制管理。

## 6. 关键流程

### 6.1 登录

1. 未认证用户访问受保护地址，系统记录安全的应用内回跳地址并显示独立登录页。
2. 服务端验证账号密码。失败时不创建会话，并给出不泄露账号存在性的错误。
3. 只有一个有效成员租户时进入该租户；有多个时必须由用户显式选择；没有有效成员时显示不可进入工作区的状态。
4. 服务端建立会话后进入原地址；无效或外部回跳地址降级为工作台。

### 6.2 切换租户

1. 用户选择服务端返回的另一个有效成员租户。当前基线对每次切换均提示未保存内容风险；取消不发切换请求。
2. 有未保存内容时先提示，用户取消则不切换。
3. 服务端确认目标成员关系后更新会话；前端卸载旧工作区、表单与租户级缓存，再进入目标租户工作台。
4. 服务端明确拒绝时保留原租户身份，关闭的编辑视图不自动恢复；响应丢失或超时则进入“正在确认工作空间”，暂停业务操作并重新读取服务端身份。确认后清理旧上下文再恢复；无法确认时保持阻断并提供重试，不假定切换失败。

### 6.3 退出与失效

1. 用户退出时先请求服务端撤销会话。
2. 撤销确认后清除本地认证视图并回到登录页。
3. 会话在任意模块失效时，整个应用回到未认证状态；不得只清空当前模块的数据。
4. 服务端撤销结果未知时显示重试状态，不得先假装退出成功。

### 6.4 组织管理

本期所有组织写操作限定目标租户 Owner；普通管理角色仅可查看，不能通过配置写权限绕过 Owner 限制。委派管理另行立项。组织页面只依赖 identity 能力。每项写操作由后端同时校验目标租户、成员状态、角色动作、数据范围和 Owner 限制；前端隐藏按钮只改善体验，不构成安全边界。

## 7. 业务规则与不变量

- `BR-01`：租户上下文来自已认证会话及有效成员关系，不信任客户端 `X-Tenant-Id`。
- `BR-02`：用户、成员和租户生命周期分离；移除成员不删除全局用户。
- `BR-03`：子租户默认隔离，父租户成员不能自动访问子租户。
- `BR-04`：动作权限与数据范围必须由同一个角色分配同时满足，禁止跨角色拼接。
- `BR-05`：所有者转移必须保证目标成员有效，且租户始终至少有一个有效所有者。
- `BR-06`：登录密码不得进入浏览器持久化存储；敏感 token 仅通过同源代理写入 `HttpOnly` cookie。
- `BR-07`：登录、退出、切换租户、成员状态变更、角色分配和所有者转移均记录脱敏审计事件。
- `BR-08`：未认证、动作无权限和依赖服务失败必须有可识别结果；对象级无权访问与对象不存在对外统一为不可访问，避免泄露其他租户对象是否存在。

## 8. 功能需求

- `FR-01 登录边界`：受保护页面在会话确认前不挂载业务内容；公开设计预览不获得业务权限。
- `FR-02 登录与回跳`：支持账号密码登录、错误重试和仅限应用内地址的安全回跳。
- `FR-03 工作空间选择`：多成员用户必须显式选择服务端返回的有效工作空间。
- `FR-04 会话复用与失效`：同一会话跨模块复用；失效时统一清理整个应用的认证状态。
- `FR-05 租户切换`：处理未保存内容、成功后的隔离清理、明确拒绝时的原状态保留，以及结果未知时的身份核验。
- `FR-06 账户查看`：展示真实存在的认证 ID、成员和角色信息，不捏造邮箱、姓名或编辑能力。
- `FR-07 组织管理解耦`：组织概览及管理不请求 catalog 服务，也不要求商品查看权限。
- `FR-08 成员与授权管理`：支持本地账号创建/关联、成员启停/移除、部门与角色分配和所有者转移。
- `FR-09 退出`：服务端会话撤销成功后才完成客户端退出；未知结果可重试。
- `FR-10 后端强制授权`：所有组织写操作在后端执行 Owner、角色、范围和 RLS 校验。
- `FR-11 安全审计`：认证与授权关键动作留下脱敏结果记录；登录失败尚无已认证主体时记录关联号与失败类型，不虚构操作者或目标租户。

## 9. 验收标准

- `AC-01（FR-01）`：未认证访问任意受保护页面时，页面只显示登录边界；页面源与加载过程均不出现业务数据。
- `AC-02（FR-02）`：登录失败不创建 cookie；登录成功只可回到本站应用内路径，外部或畸形回跳地址进入工作台。
- `AC-03（FR-03）`：多租户选择器只显示服务端返回的有效成员租户；伪造租户请求不能创建该租户会话。
- `AC-04（FR-04）`：登录后刷新及跨模块导航保持会话；任一模块收到认证失效后，所有业务工作区都被卸载并回到登录页。
- `AC-05（FR-05）`：存在未保存修改时切换会先提示；取消不改变租户；成功后原租户表单、缓存和页面实例均不可继续使用；明确拒绝保留原身份；服务端已切换但响应丢失时，旧页面不能继续写入，核验后显示真实租户。
- `AC-06（FR-06）`：账户页只展示服务端真实返回的字段；缺失字段不以示例姓名、邮箱或可编辑控件补齐。
- `AC-07（FR-07）`：没有商品查看权限但具有组织查看权限的成员可以访问组织页面，且访问过程不调用 catalog 接口。
- `AC-08（FR-08/FR-10）`：无相应管理权限的成员即使直接调用接口也不能更改成员、角色、部门或子租户；结果记录为拒绝审计事件。
- `AC-09（FR-08）`：移除成员后全局用户仍存在；暂停事务提交后，新开始身份核验的受保护请求必须被拒绝；已通过核验的在途写入与停用竞态须单独验证，不追溯撤销已经完成的业务事实。
- `AC-10（FR-09）`：服务端确认撤销后客户端退出；撤销失败或结果未知时显示重试，不显示“已安全退出”。
- `AC-11（FR-10）`：集成测试证明两租户互不可见、伪造 tenant header 无效、连接归还池后不串租户。
- `AC-12（FR-11）`：登录、退出、租户切换、授权变更和所有者转移审计均包含可确认的操作者与目标租户（未知时为空）、关联号、动作、结果和时间，且不包含密码或完整敏感 token。

## 10. 度量与护栏

发布前需补齐现网基线；在基线缺失前，以下为建议目标而非已承诺 SLA：

| 指标                          | 建议目标 | 观察窗口  | 数据来源              |
| ----------------------------- | -------- | --------- | --------------------- |
| 登录成功率（排除错误凭据）    | ≥ 99.5%  | 滚动 7 天 | identity 认证结果指标 |
| 租户切换成功率                | ≥ 99.9%  | 滚动 7 天 | 切换结果事件          |
| 跨租户数据泄露                | 0        | 持续      | 安全事件 + 隔离测试   |
| 组织管理请求对 catalog 的依赖 | 0 次     | 每次回归  | 浏览器网络测试        |
| 关键 IAM 审计完整率           | 100%     | 每日抽检  | 审计事件对账          |

护栏：不得通过延长会话有效期掩盖登录失败；不得降低后端鉴权或 RLS 来提高操作成功率。

## 11. 依赖与风险

| 风险/依赖                              | 影响                                  | 缓解措施                                                |
| -------------------------------------- | ------------------------------------- | ------------------------------------------------------- |
| ADR-0005 仍为 Proposed                 | 父级访问与商品共享策略可能变化        | 本 PRD 只依赖“父子默认隔离、显式授权”；变更先更新 ADR   |
| 多标签页状态不同步                     | 一个标签退出/切换后另一个仍显示旧租户 | 标签页收到认证变化后重新读取服务端身份并卸载旧工作区    |
| 服务端撤销结果未知                     | 用户误以为已退出                      | 保留明确重试状态，不以本地清理代替撤销确认              |
| 本地账号开通依赖管理员安全传递初始凭据 | 凭据泄露或长期不更换                  | 后续凭据生命周期 PRD 必须覆盖首次改密、过期和防暴力破解 |

## 12. 发布与回滚

- 保留旧商品管理地址的只读重定向，确认无流量后再单独移除。
- 发布门槛为 §9 全部 AC 通过，尤其是三项 RLS 隔离断言与无 catalog 依赖断言。
- 若登录边界或租户切换出现跨租户残留，立即停止发布并回滚应用版本；不得通过关闭后端鉴权临时恢复。
- 数据层成员、角色和审计记录不因前端回滚而删除或回写。
