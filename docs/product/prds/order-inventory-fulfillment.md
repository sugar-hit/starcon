## 1. 摘要

让订单运营和仓库人员完成“手工录单 → 预占 → 分批出库 → 取消剩余数量或实物退货”的可追溯闭环。任何并发、重试或通信中断都不得导致超占、超发或重复入库。本稿把蓝图拆成可验收的增量，不表示相关服务已经交付。

## 2. 背景与问题

现有蓝图描述了功能入口，V2 数据设计规定了事务与恢复边界，但缺少一份把用户操作、数量守恒、失败恢复和验收串联起来的 PRD。原“未发货可直接取消”无法处理拣货中、出库确认中及丢响应；原可售公式也可能对已排除的不可售库存再次扣减。

本稿以单租户、单法人、自营仓的手工订单为范围假设。首次采用何种仓型仍是 V2 设计中的开放问题，须在批准前确认；不可把此假设扩展成平台仓或供应商直发承诺。

## 3. 目标与非目标

- 同一来源操作只产生一次业务事实，重试可查到原结果。
- 库存占用、实发、取消和退货数量可逐行核对，无隐含负库存。
- 响应未知或进程重启后，业务人员能看到进度、责任方及恢复入口。
- 每个写操作在目标租户和适用数据范围内授权并可审计。

本期不含平台接单/回写、自动分仓优化、跨法人调拨、组合商品拆件、供应商直发、收付款、退款支付及会计过账。D4 的实物售后在本稿内；资金售后需另立 PRD，不将“退货已收”显示为“已退款”。

## 4. 用户与权限

| 用户         | 动作                                               | 范围与限制                                               |
| ------------ | -------------------------------------------------- | -------------------------------------------------------- |
| 订单运营     | 创建、提交、查询订单，申请取消                     | 目标租户内授权法人及相关业务资源；提交后不能覆盖数量快照 |
| 仓库人员     | 收货、承诺分配、拣货、确认实发、停止作业、退货质检 | 目标仓库；不能改订单金额或确认退款                       |
| 售后人员     | 对已发货行授权退货、查询处置                       | 原订单范围；不能直接增加可售余额                         |
| 异常处理人员 | 核验、重试、记录处置                               | 原业务动作及范围的授权；不得手改余额或把未知结果标为成功 |

动作与数据范围必须在同一角色分配内满足；查看权限不隐含发货、取消、调整权限。异步任务保留原租户与授权来源，不能使用无边界的后台身份。父子租户关系不扩大访问范围。

## 5. 交付范围与业务事实归属

| 增量 | 范围                                                   | 完成门槛                                           |
| ---- | ------------------------------------------------------ | -------------------------------------------------- |
| D3   | 经授权的入库确认、余额与流水、预占/释放、库存核对      | AC-01、03、04、08–10 库存侧场景通过；不依赖订单 UI |
| D4   | 手工订单、持久化履约进度、分批实发、取消协调、实物退货 | 全部 AC 通过且 D3 已验收                           |

商品标识与单位来自 catalog；订单、履约需求和售后授权由 trade 拥有；库存、分配和实发事实由 warehouse 拥有；finance 以后消费事实形成价值账。订单页面显示的出库状态是仓库事实的投影，不能代替仓库确认。所有跨服务关系通过授权接口或事件传递。

## 6. 关键流程

1. 仓库先按来源单据确认实收；待检货进入不可售状态，合格且满足上架条件后进入可售范围。重复确认不重复入账。
2. 运营选有效 SKU，录入数量、单位、收货信息和订单金额。提交时冻结快照；不完整或无授权的订单不能提交。
3. 提交后产生履约需求。一次预占请求的所有行全部成功或全部不生效；同一库存池重复行先合并数量再检查；不足显示缺货及原因，用户补货后可发起新尝试。通信未知时先核验旧尝试，不并行新增占用。
4. 仓库接受作业时把相应分配从 held 转为 committed；随后可分批拣货和确认实际发出数量。面单生成、拣货完成均不等于已发货。
5. 取消时先停止未发货部分的仓库作业，再确认释放占用。处理期间阻断相冲突的新履约；已实发部分保留并进入售后路径。
6. 退货基于原实发行授权，仓库按实际收到数量逐次登记到待检库存。质检后转可售、残次或报废，资金状态保持独立。
7. 任一步结果未知时展示“核验中”、最近尝试时间、关联单号和责任方；重试入口先查询原结果。持续无法核验转人工处置，禁止直接再次发货或强制取消。

## 7. 业务规则与状态

### 数量口径

- 同一订单行：订购数量 = 已取消数量 + 累计实发数量 + 未履约数量，各项非负。退货另记，不减少历史实发量，也不自动恢复原履约需求。
- 有效占用数量不得超过未履约数量；分批出库只消费对应分配，未发部分保留。库存余额、实发流水和预占消费同时成功或同时失败。
- bucket 内可用量 = 在手 − 有效预占；可售量 = 满足质量/上架/货权条件的 bucket 可用量之和，再扣一次策略缓冲。汇总可售量下限为 0，缓冲大于可用时显示 0 并解释计算依据。禁止重复扣待检/残次。自营模式下在手与可用均不得为负。
- 预占、承诺、释放改变占用，不改变在手；实际出库同时减少在手和占用；退货实收只增加待检在手。数量账与预占流水分别核对。
- 一次入库来源行、一次出库确认、一次退货实收都有独立稳定业务标识。同一租户和动作内，同一标识、同一内容重试返回原结果；内容不同则拒绝并提示冲突。
- 本期一次原实发行的累计已收退货 + 未完成有效授权数量不得超过实发数量。取消未收授权释放授权额度；多收、错 SKU 转异常隔离，不自动形成可售入库。

### 状态与竞态

| 对象     | 转换                                                                   | 限制                                                           |
| -------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| 分配     | held → committed / released / expired；committed → consumed / released | committed 不自动过期；部分消费以分配数量明细记录，终态不可复活 |
| 取消请求 | 待处理 → 停止作业中 → 已确认 / 部分确认 / 拒绝                         | 未知结果为核验中；出库与取消竞争由仓库事实裁决，已发量不能释放 |
| 履约进度 | 待预占 → 已预占 → 作业中 → 部分发货 / 已发货                           | 缺货、核验中、待人工处理保留原进度及原因，不伪装成功           |
| 退货     | 已授权 → 部分实收 / 已实收 → 已处置                                    | 每次实收与处置独立追踪，不等待整单齐货才允许质检               |

取消先到而预占后到时，迟到请求不能复活已取消需求；取消与出库均已提交时，以仓库原子处理结果确定取消量和实发量。状态旧消息不能覆盖新快照，库存增量消息不能因版本小而直接丢弃。

held 到期与 committed 竞争由仓库原子裁决；到期只释放仍为 held 的剩余量，重复处理不重复释放。

### 金额与时间

手工单使用单一订单币种；本期不换汇。金额最多 4 位小数，单价最多 8 位，数量最多 6 位；三者总有效位数最多 19 位，乘积或合计溢出整单拒绝；数量须大于 0、单价非负；业务输入超精度时拒绝，不静默截断。币种须为系统支持的三位代码，订单行冻结库存基础单位，本期不做自由单位换算。每行金额由订单侧按数量 × 单价计算并以 HALF_UP 舍入至 4 位，总额为行金额合计；折扣税费扩展另行评审，不推导未提供的税额。以上为待确认的内部记录口径，支付币种精度不在本期承诺。

保存绝对时间和仓库业务时区，按仓库 IANA 时区解释业务日期；过期基于服务端绝对时间。预占有效时长须在批准前确定，committed 不适用此时长。

## 8. 功能需求

| 编号  | 触发、行为与结果                                                     |
| ----- | -------------------------------------------------------------------- |
| FR-01 | 确认入库时，校验来源和数量，生成可追踪流水；重复请求返回原结果       |
| FR-02 | 查询库存时，展示在手、占用、可售、待检及计算依据，按授权范围筛选     |
| FR-03 | 提交订单时冻结商品、单位、金额与地址快照；无效输入不进入履约         |
| FR-04 | 发起预占时检查全部行的可用量，整体成功或失败；不足可恢复，未知先核验 |
| FR-05 | 仓库接受并执行作业时承诺分配，按实际发出数量分批消费，逐行反馈订单   |
| FR-06 | 申请取消时协调停止作业和释放；保留已发货数量及核验中的未决结果       |
| FR-07 | 授权并收到退货时，校验原实发与剩余额度，待检入库后按质检处置         |
| FR-08 | 超时、重启或重复事件到达时，恢复同一业务操作并显示真实进度和人工入口 |
| FR-09 | 所有查询、写入及恢复动作均执行租户隔离、角色范围校验和脱敏审计       |
| FR-10 | 发起核对时，比较同一截止点的余额、库存流水与预占流水，输出可追踪差异 |

## 9. 验收标准

| 编号  | 对应需求    | 可观察结果                                                                                                                                        |
| ----- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-01 | FR-01/FR-02 | 入库 10 件可售、3 件待检，预占可售 4 件后，在手 13、占用 4、可售 6、待检 3；重复入库结果不变                                                      |
| AC-02 | FR-03       | 数量为零/负数、超精度或无权使用的 SKU 提交被拒；成功提交后修改商品名称不会改变原单快照                                                            |
| AC-03 | FR-04       | 两请求同时各预占同一池 7 件（可售 10），最多一笔成功；多行中一行不足时其他行无残留占用；同请求同池两行各 6 件、可用 10 件时整体失败               |
| AC-04 | FR-05       | 订单 10 件全部 committed 后实发 4 件，在手和占用各减少 4，剩余 6 不因 TTL 释放；重复发货确认不再扣减                                              |
| AC-05 | FR-06/FR-08 | 上例取消剩余 6 件，确认停止作业后释放 6；订单为实发 4、取消 6。并发发货抢先成功的数量不得被取消或再次释放                                         |
| AC-06 | FR-06/FR-08 | 取消早于预占到达时，迟到预占不生效；响应丢失显示核验中，查得原结果后收敛，不新增第二份占用                                                        |
| AC-07 | FR-07       | 实发 4 件授权退 2 件，分两次各收 1 件；重复实收不重复入账。质检前可售量不增加，超授权实收记录异常实物去向，不消耗原授权、不增加可售，退款状态不变 |
| AC-08 | FR-08       | 在预占或出库已提交、响应未送达时重启，恢复后仍只有一份事实；重复消息无副作用，乱序增量补齐后数量一致                                              |
| AC-09 | FR-09       | 两租户互不可见、伪造 tenant header 无效、连接池复用不串租户；跨角色拼接动作/范围被拒；审计无完整地址或凭据                                        |
| AC-10 | FR-10       | 在同一核对截止点，期初 + 入出库/调整流水 = 在手，有效分配未消费未释放量 = 占用；注入漏记投影可检出，不能静默改账                                  |

## 10. 度量与护栏

当前无本闭环运行基线。发布前由产品与运维确认吞吐、延迟、恢复时限及观察窗口；未确认不声称 SLA。

验收环境对全部并发/故障场景要求超占、超发、重复事实和跨租户泄露均为 0，差异可检出率 100%；来源为测试结果、事实核对与审计。试点每日观察核验中数量、最长滞留时间、人工处理量和账差；出现安全或数量不变量破坏即停止新履约。

## 12. 发布与回滚

先验收 D3，再在明确的试点租户/仓库开启 D4。发布前 AC 全通过，异常队列有责任人，初始余额已核对；需真实 PostgreSQL 的隔离和并发测试，不能仅靠页面演示。

发生账差或越权立即暂停新增履约，保留查询、核验和已承诺作业的受控处理。回滚应用不能删除已发生流水、释放已发货占用或重复发送指令；若旧版本不识别新状态则禁止直接回滚，先隔离新写入并采用兼容修复。恢复前由订单与仓库负责人共同确认未决请求已核对。
