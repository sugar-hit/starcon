# AI 会话上下文归档

本目录是 starcon 项目内 **AI 协作会话** 的项目级可检索日志。所有有结论的会话都必须落档。

## 为什么需要

跨境 ERP 是长周期项目，AI 协作的最大坑是：

- 上轮决定的事下轮忘了 → 反复重新设计
- 调研背景 / trade-off 讨论散落在 chat → 不可检索
- 不同 agent 接手时无从了解上下文 → 重复劳动

本目录确保任何 agent（人或 AI）都能**回溯任意时间点的项目状态和决策**。

## 收录规范

### 何时归档

满足以下任一条件**就要归档**：

- 做出 / 改变了一项架构决策（即便还没写 ADR）
- 完成了一个功能模块的设计 / 落地
- 解决了某个关键 bug 或性能问题
- 完成了跨模块的重构
- 调研了关键技术选型并给出结论
- 创建 / 修改了多个文件（≥ 3 个原子改动）

### 文件命名

```
docs/sessions/YYYY-MM/YYYY-MM-DD-<topic-slug>.md
```

- `YYYY-MM-DD`: 会话日期（同一日多个会话用 `-01` `-02` 后缀）
- `topic-slug`: kebab-case，≤ 8 个词，描述**做了什么**

示例：

- `2026-09-25-folder-structure-design.md`
- `2026-09-25-multi-tenancy-decision.md`
- `2026-10-03-amazon-sp-api-integration-design.md`

### 归档内容模板

每篇必须包含：

```md
# YYYY-MM-DD: <topic>

## 摘要

（一段话讲清楚做了什么、为什么）

## 决策 / 结论

（如果有决策，逐条列出）

## 涉及文件

（关键文件路径列表，方便回溯）

## 关键 trade-off / 讨论

（如果有争议选项，记录为什么选 A 不选 B）

## 后续待办

（衍生出的工作项，要么进 backlog 要么直接 inline TODO）

## 关联

（指向相关 ADR / 文档 / 后续会话语档）
```

### 当月归档，跨年移走

- 当月写入 `docs/sessions/YYYY-MM/`
- 跨年整理: 12 月底把去年的目录移到 `docs/sessions/archive/YYYY/`

### 不收录

- 纯闲聊 / 简单问答（无决策无代码改动）
- 一次性 debug（除非发现了通用教训）
- 跟 starcon 项目无关的话题

## 给 AI agent 的强约定

> **每次会话结束、关闭转其它工作前，主动把本轮摘要写入当月目录。**
>
> 不要等用户提醒，不要只在 chat 留一句"我做了 XX"。**chat 会清，docs 不会。**

写到 backlog 还是 sessions？

- 还没动代码、只是讨论出方向 → sessions（"会话记录"）
- 已经决定要做、但还没落地 → backlog（"待办"）
- 已经落地 → sessions 即可（backlog 不重复记录已完成项）
