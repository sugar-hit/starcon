# 2026-09-28 — 系统功能蓝图（18 系统 / 四级目录 / 430 模块）

## 用户输入

> 参考领星 ERP、Shopify 等所有网店后台和 ERP 系统的后台，以 ERP 后台为核心，再仔细参考跨境电商行业对 ERP 的需求，以及公司自研改造开发 ERP 的相关功能，完善完整设计 Starcon 应该有哪些功能，输出详细文档。需要细化到最多四级目录（系统-功能-子功能-孙功能-模块），并说清楚最小层级下该目录应该完成什么功能、接受什么输入、提供什么输出、与其他系统/功能/页面的关系。

## 产出

`docs/product/capability-blueprint/` — 1 份总纲 + 18 份分卷。

规模：**18 系统 / 100 个 L2 功能 / 430 个 L4 模块**，每个 L4 必写四项（职责 / 输入 / 输出 / 关系）。

## 关键决策

### 1. 四级目录约定被冻结为写作规范

- L1 系统 = 业务归属（有独立目标与数据主责方）
- L2 功能 = 导航单元
- L3 子功能 = **权限单元**（对应 ADR-0005 的一张 `page_resource`）
- L4 模块 = **最小设计单元**（一个页面或一项能力，有确定输入输出）

四个层级各司其职不混用：`L4 是设计单元，L3 是权限单元，L2 是导航单元，L1 是归属单元`。

### 2. L4 的「四问」是验收标准，不允许放宽

职责（写到可判断做完没有）/ 输入 / 输出 / 关系，缺一不可。反例清单写进了 README §3，防止退化成功能清单。

关系用统一记法便于交叉检索：`上游 X → 本模块 → 下游 Y` + `共享数据` + `触发`。

### 3. 三类来源交叉验证，而非单一竞品照抄

- **来源 A 网店后台**（Amazon/Shopify Admin…）：定义商品与订单在平台侧的字段与状态机
- **来源 B ERP 后台**（领星/店小秘/马帮/易仓/赛盒/通途 + 金蝶用友 SAP）：**本蓝图核心**
- **来源 C 跨境行业专属**（多平台多店铺、FBA、头程、报关、VAT/IOSS/EPR、延迟结算、平台托管模式、防关联…）

写进 README §1 的核心判断：**ERP 与网店后台的根本区别**——网店后台以"平台页面"为中心（列表页=功能），ERP 以"单据与账"为中心（单据生命周期=功能）。starcon 两者都做：**页面沿用网店后台的操作习惯，数据模型沿用 ERP 的事实纪律**。

### 4. 18 系统 vs 现有 4 导航 Tab 的关系（避免与已实现代码冲突）

现有 `nav-config.ts` 的 4 个职能 Tab（开发/运营/物流/仓储）是**角色视图**（切 Tab 换的是"我是哪种岗位"）；18 系统是**功能归属**（回答这功能归谁设计、归谁供数）。两者不是同一层。

**目标态 UI 沿用现有 Tab 结构不变**，18 系统映射进去；额外记了 6 个当前 15 个 Domain 未覆盖但需要的新增入口（`/channels` `/ads` `/crm/messages` `/logistics/customs` `/finance/costing` `/settings/approvals`）。

### 5. 「挂不上闭环就不做」作为准入判据

README §4.1 给出端到端闭环主线图，并写明：**任何功能设计如果不能挂到这张图的某条边上，它就不该做**。

## 关键 trade-off

- **选"主卷 + 18 分卷"而非单一大文件**：单文件 430 模块无法评审也无法局部更新；分卷后新增系统只动一个文件
- **L2 只给职责表不给四问**：L2 是导航层不是设计单元，四问的强制对象是 L4（用户原话"最小层级下"）。二轮补写 L2 职责表后层级才可读
- **实体名只引用不重复定义**：表结构归 `db/schemas/v2/`，蓝图只出现实体名，避免两处定义漂移

### 复审发现（不是确认，是真的找问题）

**A. 结构性缺陷**
1. 18 系统平铺，把"门户(01) / 业务域(02-16) / 横向治理(17) / 技术平台(18) / 平台运营(17.7)"混在同一维度 → 已加「层级归类」列
2. **"利润"三处口径未收敛**（05 测算 / 12 结转 / 13 报表），是财务与运营对不上账的根因 → 新增 §6.1 明确三者分工与权威性
3. 17.6 订阅与计费越界：这是 starcon 自身 SaaS 运营，非租户 ERP 功能 → 拆为 17.7 平台运营并标注"不对租户开放"
4. 法人单账簿假设不成立：跨境常见一个主体多币种多账簿 → 17.6 账簿与多主体
5. 12.5 总账对多数跨境卖家过度设计，且无分级 → 新增 P0-P3 能力分级
