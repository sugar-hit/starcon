## 这个模块做什么

蓝图 12-finance.md 12.7.2.1 原文：「资金分析：现金流入流出趋势、各币种资金分布与汇率敞口、
资金周转天数、付款集中度与流动性预警。」输入：「资金流水；应收应付账期；汇率数据。」
输出：「资金报表 + 汇率敞口测算 + 流动性预警。」关系：上游 = 12.7.1、12.1.2.2；下游 = 1 工作台。

本车道交付**六项能力全部真算**（jOOQ 显式 SQL + 真实聚合，无常量、无 mock、无占位页）。

## 关键决策

### 1. 上游缺口如实标注，**不降级也不造数**

**12.7.1.1 账户管理 / 12.7.1.2 银行对账均未开发** —— 已 grep 取证：
`backend/services/finance/src/main/resources/db/migration/` 下**没有任何资金账户表 / 银行流水表**
（`fund_account` / `bank_statement` 零命中），且 V341 的 `finance_receipt.fund_account_ref`
由 CHECK 钉死**恒为 NULL**。

处置方式（照抄 12.1.1.3 / 12.3.1.1 的先例）：

- **能力声明** `available=false` + `ownerModule` 写明 `12.7.1.1` / `12.7.1.2`；
- **DB 层把归属钉在数据上**：`finance_fund_exposure_snapshot.fund_account_ref` /
  `bank_statement_ref` 由 CHECK 钉死**恒为 NULL**，`fund_account_owner_module` 恒为 `'12.7.1.1'`、
  `bank_statement_owner_module` 恒为 `'12.7.1.2'`、`account_level_available` 恒为 `false`；
- **绝不用硬编码数组 / 常量冒充账户余额**。

**因此哪些指标不完整**（响应里逐处标注，不让人误读）：

| 本来想要 | 现状 | 归谁 |
| --- | --- | --- |
| 账户级资金分布 / 在手余额 | **只有币种级**；「累计已到账现金」是历史累计数，**不等于**在手余额 | 12.7.1.1 |
| 银行流水 / 对账差异 / 未达账项 | **不产出**；实际流入取自 12.2.1.1 的**收款单**，不是银行流水 | 12.7.1.2 |
| 实际流出的时间序列 | **没有**：12.2.2.1 未交付 ⇒ `paid_amount` 恒为 0，且付款行上**没有付款时刻字段** | 12.2.2.1 |
| 存货周转天数（CCC 的存货段） | `dioDays` **恒为 null**（不用 0 冒充） | 13.1.1.1 |

### 2. 「实际 ≠ 计划」的口径纪律

12.1.2.2 的 `finance_payment_plan.execution_available` 被**表级 CHECK 钉死为 false**
⇒ **计划表里写不出「已付款」**。所以：

- 流出侧只有**计划口径**（按计划付款日）与**累计已付口径**（无日期）；
- 趋势报表**不给「实际净额」** —— 实际流出没有日期维度，硬凑一个「实际流入 − 0」叫净额，
  那是**把缺失当零**。只给「预期流入 − 计划流出」这一种**同口径**预测净额；
- 集中度报表的 basis 字段里明写「口径 = 计划付款」。

### 3. 汇率敞口的定义（本模块自己的口径）

资产端 = 未核销应收（`amount − settled_amount`），负债端 = 未付应付（`unpaid_amount`），
净敞口 = 资产端 − 负债端。

- **已到账现金不计入敞口净额**：一笔收款与它对应的那笔应收**可能是同一笔钱**
  （12.2.1.2 核销后收款 `unsettled_amount` 归零、应收 `settled_amount` 同步上升），
  两个口径并起来会**重复计算同一笔钱**。已到账现金单列在币种分布里。
- **存货不算进敞口**：蓝图举的例子是「大量外币存货 + 本币负债」，但存货不在本服务
  （07 / 08 / 13）。缺的那一半如实标注归属，**不用 0 冒充**。
- 汇率经 **catalog 5.2.2.1 的授权 HTTP API** 读（`CatalogExchangeRatePort`，转发调用方自己的
  bearer），**不跨库 SQL / 不建跨库 FK 或视图**。**取不到一律 503 显式失败**，
  绝不返回空集合冒充「没有汇率」。
- 本位币取自**本租户单据上的 `base_currency`**（真实数据）；取不到或不唯一 ⇒ 显式失败
  （默默挑一个会产出「看着像真的」的敞口数字）。

### 4. 权限码沿用既有词表

沿用 12.1.1.2 应收账龄的 `finance.receivable.read` / `.update`。**刻意不新造权限词表** ——
权限码在 identity 的 `permission(code)` 目录里，新造一档要改另一个服务的迁移（它的写入所有权，
且迁移版本号由调度者统一分配）。本模块是应收 / 应付 / 收付款 / 汇率的**读侧投影**，与账龄同一性质。

### 5. 类型名全部带模块前缀

`TrendGranularity` 与 trade 的 `ReturnAnalyticsModels` 撞名，`AlertSeverity` 与 trade 的
`FulfillmentQualityModels`、warehouse 的 `SafetyStockModels` 撞名。契约 codegen 合并进扁平文件后
**同名后者覆盖前者且不报冲突** ⇒ 全部改名带前缀：
`FinanceFundTrendGranularity` / `FinanceFundAlertSeverity` / `FinanceFundLiquidityRule` /
`FinanceFundExposureDirection`，六个查询 record 也一并加 `FinanceFund` 前缀。

另有一类**契约谎报**要堵：SpringDoc 不会自动把 `BigDecimal` 标成 nullable，
所以 `exposureShare` / `share` / `topBucketShare` 必须显式加 `@Schema(nullable = true)`，
否则 TS 类型会写成 `number` 而服务端可能返回 `null`。

## 关键 trade-off

- **趋势报表不给「实际净额」**：宁可少一列，也不把「实际流出缺失」呈现成 0。
- **周转天数不给 CCC**：存货段缺失 ⇒ `dioDays` 恒 null。给一个「CCC = DSO − DPO」的近似值
  会让人以为那就是现金转换周期。
- **敞口快照只能追加**：重新测算追加新行，不改旧行 —— 快照是「当时用了哪档汇率」的举证凭据。
- **阈值配置整体替换**：规则的**组合**才是口径，逐条写会出现「只配了一半」的中间态。
- **api-proxy 纯追加**：`apps/web/src/lib/api-proxy.ts` 只新增一条独立 `services[]` 元素
  （插入锚点 `prefix: 'auth/'` 之前），diff **59 行新增、零删除**。既有条目一字未改、也不重排。
  ⚠️ 该文件在基线上**本就不是 prettier-clean**（4 处两行式 `pattern:` 会被 prettier 合并成一行），
  本车道**刻意不**顺手改它们 —— 那是别人的行。
