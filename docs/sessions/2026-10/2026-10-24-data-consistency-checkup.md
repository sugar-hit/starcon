# 2026-10-24: 1.5.1.2 数据一致性体检（卷 01 工作台与门户）

## 摘要

交付蓝图卷 01 L3「1.5 集成健康」下的 L4「1.5.1.2 数据一致性体检」。落点是**纯前端聚合层**：
**零迁移（V375 预分配但主动不占用）、零后端改动、api-proxy.ts 一字未改（k = 0）**，
页面 `/system-health/consistency`。五个分项里**三项可读**（07 库存账实核对、07 库存准确率红线判定、
02 渠道映射缺失队列），**两项如实报不可得**（12.3.2 对账差异**未交付**；订单/履约/财务三方金额差异
**本仓不可比**）—— 两项都**不显示成 0、也不显示成健康**。

## 决策 / 结论

1. **落点 = 纯前端聚合层（不是只读投影层）**。
   蓝图卷 01 卷首写死「后端归属：前端聚合层 + 各服务的只读投影（**不新增业务服务**）」
   与「不产生新的业务事实，只聚合各系统的投影」。本模块的三类可读输入分属**两个不同服务**
   （warehouse + channel），若做成后端投影层，就要为跨服务读取新增 HTTP 端口 + 转发调用方
   Authorization + 新权限码 —— 而蓝图明说**不新增业务服务**。同卷兄弟模块 1.1.3.2
   「资金与回款风险」已是同一形态（后端零改动、纯前端聚合层、跨 5 个上游端点），
   本模块照抄该形态与它的纪律（精确十进制 / 不可判定 ≠ 0 / 计数与清单同源 / 只读 + 跳转）。
   同 L3 的 1.5.1.1 是**另一形态**（只读投影层落 channel 服务），因为它的四类输入全在 channel
   自己的事实表上 —— 形态由输入的归属决定，不由偏好决定。

2. **零迁移，V375 不占用**。理由与 1.5.1.1（V338 同样主动不占用）一致：五类输入逐条落在归属服务
   既有的只读端点上，派生快照表只会比它描述的事实更早过期。**没有建空迁移占位**。

3. **不新增本模块的后端汇总端点**。体检报告由前端从四个上游投影合出来；白名单里也**刻意不放行**
   `warehouse/consistency-check` 之类的形状（放行后端不存在的映射比 404 更糟）。

4. **api-proxy.ts 一字未改**：四个上游端点 + `auth/session` **全部已在基线白名单里放行**，
   本车道用**真跑代理逐条实测命中**（不是目测、不是 `grep -c`）。既然没改 api-proxy，
   就不需要跑那条「唯一例外」的全量 allowlist 回归 —— 但还是跑了（243 文件 1372 例全绿）作为自证。

5. **「低于阈值应阻断结算与对账出结论」= 暴露判定，不执行阻断**。
   归属服务 07 库存（7.6.2.1）已经把它做成一个**可查询、带证据**的判定
   （`GET /warehouse/inventory/health/gate` → `blocked` + `blockReason` + `basis`），
   本模块原样透传并给处置入口，**不代** 12 财务结算与 7.1.2.2 对账去扣单
   （12.3.2 还没交付，本模块也没有写权限；卷 01 边界「工作台只读 + 跳转」）。
   并且**区分两种阻断**：准确率低于阈值 vs **没有证据**（无评估结论）—— 处置动作完全相反，
   沿用 16.3.1.2「把『读不到』与『没就绪』拆成两个状态」的先例。

6. **「判不了」是一档独立状态**，不是第四种颜色。`UNDETERMINED` 与绿色语义相反：
   「查出来没问题」与「没查出来」不是一回事。五种可得性严格分开：
   无权限（连请求都不发）/ 读不到（可重试）/ 上游未交付 / 不可比（本仓缺事实）/ 没有数据。
   **整体结论只要有一项判不了就不能报「通过」** —— 所以本仓今天整体结论**不可能是绿**
   （五项里两项上游不可读），单测专门锁住这条。

7. **金额差异绝不跨币种相减，也不按 1:1 兜底**。三方金额差异这一项**不产出任何金额数字**，
   取证三条（见下节）。

8. **阈值是本模块的默认政策并逐条公布**：映射缺口陈旧阈值 **7 天**（>0 条判黄、≥7 天判红），
   **不是平台下发的口径**；库存准确率阈值（默认 99%）由 07 库存持有、原样引用。
   规则表（条件 → 结论 → 事实来源）在页面上逐条公布。

## 关键 trade-off / 讨论

### 取证：为什么三方金额差异判不了（而不是「懒得做」）

三条都是**结构事实**，不是接口没调：

| 一侧 | 事实 | 结论 |
| --- | --- | --- |
| 订单（09） | `sales_order.grand_total_amount` + `currency_code` | 可读 |
| 履约（08） | `warehouse_outbound_order` / `warehouse_outbound_order_line` —— **只有数量，无金额列、无币种列** | **没有订单金额事实** |
| 财务（12） | `finance_settlement_line.amount` + `currency` | 可读，但与订单**没有外键**（只有可空的 `external_reference`） |

外加：全仓唯一的履约侧金额列 `trade_fulfillment_request.estimated_handling_amount`
是**作业估值**（币种列默认值写死 `'USD'`），不是订单金额，不能拿来比；
订单币种与结算币种之间**没有可读汇率**。

⇒ 履约侧没有可比金额 + 两侧币种没有汇率 ⇒ **本仓答不出这个差异**，
报「不可比」并把三条取证写进页面证据区。**绝不**退化成「订单总额 − 结算总额」：
那要么是跨币种相减，要么是 1:1 兜底 —— 加出来的「差异」是假的。

### 取证：12.3.2 对账差异为什么不拿 12.7.1.2 顶替

12.7.1.2 银行对账（V369，已交付）与 12.3.2 平台账单对账是**两处不同的事实**：
前者是银行流水 vs 我方账，后者是平台账单 vs 结算单。蓝图点名的输入是 12.3.2。
⇒ 本项判 `NOT_DELIVERED`，能力声明里只附一句「邻近但**不同口径**的 12.7.1.2 不替代 12.3.2」，
**不拿它冒充**，也不把它算进分项。

### trade-off：映射缺口的 7 天阈值是哪来的

蓝图没给阈值。这是本模块的**默认政策**（页面上明写），理由：待处理映射缺失数 > 0 就是黄
（缺口存在）；「压了一周还没人处理」是另一档问题 —— 缺口会让对应平台变体的订单建不出来。
另有一条诚实提示：`MappingGapSummary.orderSourceWired = false` 时，
**待处理数是下限**（09 订单的缺映射事件还没接线），这一点写进证据行。

### trade-off：为什么连差异明细表也要做

蓝图输出写的是「分项健康 + 异常清单 + 处置入口」。只给分项结论会让「异常清单」退化成
五个分项名字；真正能派工的是**差异行**（哪条余额行对不上、哪一笔流水可疑、在哪一段时间）。
所以额外读了 `/{runId}/findings`（真分页，`total` 取服务端全量合计，不拿页长当总数）
与 `/{runId}` 的可疑区间排名（按天对齐的「是哪**一段**流水可疑」）。

### 取证：allowlist 测试里两处「反直觉」的写法

1. 模板字面量里的 `${...}` 换成**真实 UUID 形状**占位符，不是 `x` ——
   白名单的 id 段是 `[0-9a-f-]+` 形状，换成 `x` 会让断言测成「代理认不认一个不存在的形状」，
   变成永假的假绿灯。
2. 「刻意不放行」清单里**不能**放 `warehouse/inventory/health/assess` 与
   `channel/mapping-gaps/{uuid}/map` —— 它们是**真实存在**的上游写端点（属于 7.6.2.1 / 2.4.2.3
   自己的页面），代理按**路径**放行、不按方法区分。写动作的归属由各归属系统自己保证，
   本模块靠「源码零写调用」那条断言保证自己只读。
