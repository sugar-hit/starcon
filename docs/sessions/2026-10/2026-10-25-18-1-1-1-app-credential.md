# 2026-10-25: 18.1.1.1 应用与凭证（platform 服务首条业务端点）

## 摘要

交付蓝图 18 卷 L3 18.1.1「API 管理」下的第一格 **18.1.1.1 应用与凭证**：管理第三方接入的应用
（应用注册、API Key/Secret 生成与轮换、授权范围、IP 白名单、调用配额）。

卷 18 的后端归属服务 `platform` 此前在本仓**不存在** —— 本车道先引导出服务骨架（端口 8089 /
库 `starcon_platform`），再在它上面落地本模块：迁移 **V377**（七张表）、**23 条端点**、
**1 个真实工作区页面**、**27 例后端集成测试 + 18 例前端测试**。

蓝图的三条硬要求逐条落成**物理形态**，不是靠约定：

| 蓝图原话 | 落成在哪 |
| --- | --- |
| **明文仅在生成时展示一次**，之后只存摘要 | `api_key_digest` / `secret_digest` = BCrypt；库里**没有任何一列**存明文；前端**没有**「再显示一次」入口 |
| **访问有审计** | `platform_app_audit_event` 只追加；两个触发器**拒绝 UPDATE / DELETE**；读到凭证元数据本身也留痕 |
| **泄露可一键吊销** | 吊销应用 ⇒ 该应用**全部**凭证同时失效（一次 UPDATE），幂等、时间戳不漂移 |
| **对外凭证与平台凭据同等对待** | 租户隔离（FORCE RLS）+ 权限校验 + 限流 + 审计，四条一起，不是只做一条 |

## 决策 / 结论

1. **🔴 Secret 侧刻意没有「可定位摘要」，API Key 侧有。**
   `api_key_lookup` = SHA-256 十六进制，**只**用于按值定位这一行 —— BCrypt 加盐且慢，
   无法按值定位，没有它网关拿到一个 API Key 根本不知道该比哪一行。API Key 是 32 字节
   CSPRNG 随机串（256 bit 熵），SHA-256 摘要不可暴力枚举，做定位索引是安全的。
   **Secret 相反**：它是**唯一真正的机密**，所以库里**只有** BCrypt 摘要，永不落任何
   可定位摘要 —— 验证时只能「拿到候选行之后逐行 BCrypt 比对」。
   （迁移注释里写明了：若将来允许运营手工指定 API Key，熵降下来，这一列必须同时改成
   HMAC-SHA256 —— 那时 SHA-256 就变成可离线枚举的口令哈希了。）

2. **🔴 审计事件 → 应用是 RESTRICT，不是 CASCADE。**
   应用一旦登记就写过一行 `APP_REGISTERED`，所以这条 FK 等价于「**应用只能吊销，不能删除**」。
   凭证 / 授权范围 / 白名单 / 配额 → 应用是 CASCADE（它们是应用的附属物）。

3. **🔴「生成」与「轮换」是两件事，不合并。**
   同一应用**已有生效中的凭证时不允许再生成** —— 那是轮换的语义；合成一件会出现
   「以为在生成、其实把旧的顶掉了」，旧摘要失效而没人知道。轮换是**追加新版本** +
   旧行收口成 `ROTATED`（旧摘要留在库里，争议时能查清「哪一版在什么时间点有效过」）。

4. **🔴「没配过配额」不是「限 0 次」。**
   窗口 SECOND/MINUTE/HOUR/DAY/MONTH 按 **UTC 截断**；未配置的窗口返回
   `decision=NOT_CONFIGURED`，**系统零预置**（不替用户默认「1000 次/天」）。
   前端**不重算**这个结论 —— 把「不限」显示成红色「已用尽」是误伤。

5. **🔴 凭证自检的四个判定分开给**（凭证 / 授权范围 / IP 白名单 / 配额）。
   「凭证对但没授权」和「凭证错」要修的地方完全不同，合成一个布尔值就没法用。

6. **🔴 用量回报是服务端到服务端，刻意不进浏览器白名单。**
   `POST /platform/app-quota-usages` 要 `X-Internal-Key`；放行它等于让任意浏览器往
   别的租户写用量。写入是 **UPSERT + 加法**（覆盖会把并发回报丢掉）。

7. **🔴 对外应用资源码与平台内部 RBAC 权限码刻意不共用命名空间。**
   两者都是「资源 × 操作」的形状，共用一套码会让「平台内部能干什么」与
   「对外应用能干什么」在审计里分不开。

8. **命名用 `Integration*` 前缀，不用 `Platform*`。**
   channel 服务那一族 `PlatformAppeal* / PlatformPriceRule*` 说的是「Amazon / eBay /
   TikTok 这些**电商平台**」，与本模块的「开放平台」是两回事；契约被 codegen 合并进
   同一个扁平命名空间，同前缀会让读代码的人以为是一件事。

9. **本模块不提供任何绕过平台官方 API 的模拟登录能力**（卷 18 卷首合规红线）。
   ⇒ V377 里**没有任何一张表**存账号 / 密码 / Cookie / 模拟登录态。

## 关键 trade-off / 讨论

- **台账只改自己那一行**：车道提交只动 18.1.1.1 的「状态」「证据」两格，总览与分阶段
  计数由调度者的 `sync.mjs` 重算（已核对：脚本重生成后本行**逐字节不变**，差异只有
  400→401 / 65→64 / 86.0%→86.2% 这些自动计数）。
- **`api-proxy.ts` 插入锚点选在数组末尾**：同批其它车道的插入点是「数组最开头」与
  「第一个 identity/ 之前」，本车道落在末尾，与它们相距 12000+ 行，并入时 git 能干净求并。
  实测既有条目对 `platform/` **零命中**（channel 那支的 `platforms` 是 `channel/` 下的
  **首 token**，两回事）⇒ 两条正则前缀天然互斥。
- **id 段用完整 UUID 形状** `[0-9a-f]{8}(?:-[0-9a-f]{4}){3}-[0-9a-f]{12}`，不是
  `[0-9a-f-]+` —— 后者会把 `revoke` / `rotate` / `verify` 这种非 UUID 形状也当成 id 放行。
- **白名单守卫从前端源码反向抽取真实调用点**，并**断言抽取条数 > 0** ——
  只认字面量会把调用点全部漏成零条，然后「一个都没断言」也算通过。
  另**正向钉住**其余 8 个服务已放行的分支不被误伤（白名单是多车道共用的累积型文件，
  取错一侧会静默删掉已交付模块的路由，表现是页面 404 而 typecheck/lint/vitest 全绿）。

🔴 **前端 typecheck 的唯一红**（**已知红，非本车道**）：

```
packages/api-contracts/src/index.ts(10,15): error TS2306:
  File '.../packages/api-contracts/src/contracts/reporting.ts' is not a module.
```

根因：本车道基线（reporting 车道的引导 commit `8c8f7c47`）往 `index.ts` 加了
`export * from './contracts/reporting';`，但同一 commit 里的 `contracts/reporting.ts`
**只有一行生成器头注释、零 export** ⇒ TypeScript 判定它「不是一个模块」。
该文件属 **13.1.1.1 reporting 车道**。

**处置**：**不**手改 `contracts/reporting.ts`（那是别的车道的文件），**不**删 `index.ts`
里那行 export（删了会让真实契约回来时又对不上）。⇒ 待 reporting 车道提交真实契约后，
在本 worktree 里做一次**向后合并**即可自然消失：

```bash
git merge --no-edit feat/13-1-1-1
```
