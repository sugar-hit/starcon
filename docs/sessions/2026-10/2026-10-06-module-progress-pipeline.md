# 2026-10-06 建立 465 模块进度台账与每小时开发流水线

> 目的：让「465 个 L4 模块还剩多少没开发」变成可计算的事实，并让无人值守的定时任务
> 能持续推进开发，而不是靠人肉回忆。

## 决策摘要

**进度必须是生成物，不能是人肉维护的清单。**

465 个模块手抄一遍必然与蓝图漂移。所以 `sync.mjs` 从 18 卷蓝图的功能树解析出全部模块，
台账只叠加一层人工维护的「状态 / 证据」两列，按模块 ID 继承。蓝图是唯一真相源。

**互斥用文件锁，不用会话列表。**

定时任务每小时触发，但单个模块开发远超一小时。没有互斥就会出现两个任务抢同一条 git 分支。
会话列表跨会话看不到「这个会话是不是在开发」，而 `.dev-agent/dev-task.json` 是落在项目里的、
跨会话一定读得到的真相。心跳 90 分钟不续即视为失联，可被下一个整点抢占 —— 子任务崩了
不会永久卡死流水线。

**阶段列按依赖就绪顺序逐模块标注，不是卷归属。**

这是本轮最实质的修正。最初按卷映射阶段，结果调度会去建 `1.1.1.1 我的待办` ——
而 01 工作台是纯投影聚合层（蓝图原文「不写业务数据，只读投影」），上游是
09 订单 / 07 库存 / 12 财务 / 15 客户 / 17 审批，这些投影一个都还不存在。
提前开工只能造假数据，正好踩中「禁止 mock」的红线。整卷因此改排 D7。

修正后交付顺序变成：**先补完 03 商品主数据的 SKU 体系（库存核算依赖它），再进 D3。**

## 关键 trade-off

**基线判定偏保守。** 33 个「已交付」每个都对应四件可查证据（迁移 + 端点 + 真实页面 + 测试），
证据不足的一律留「未开发」，让后续开发任务现场核实补齐。宁可多标未开发让任务去查，
也不乐观估计 —— 虚标「已交付」会让流水线永久跳过真实缺口。

**台账不参与 prettier 格式化。** prettier 会重排表格导致与生成器输出漂移、`--check` 失败。
已加进 `.prettierignore`（连同同为 codegen 产物的 `api-contracts` / `sdk`）。

## 顺带查出的数据模型缺陷

`product_compliance` 与 `product_asset` 都是 `product_research` 的
`LIKE ... INCLUDING ALL` 同构复制（catalog V1:77-80）。三张表列结构完全相同，
导致合规表装不了 HS 编码与认证、素材表装不了文件键 —— 蓝图 3.4 / 3.7 的需求
**物理上落不了库**。`/products/compliance` 与 `/products/assets` 页面虽然是真实工作区，
但底下撑不住。已在台账标为「未开发 + 阻塞」，要求先补迁移拆表。

这与 2026-09-28 会话里记的 D1 缺陷是同一个，尚未修复。

## 踩坑记录

| 坑                      | 结论                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 远端名不是 `origin`     | 是 **`upstream`**（`https://github.com/sugar-hit/starcon.git`）。照惯例写 `origin` 会直接失败                                                                                                                       |
| `main` 分支没有能力蓝图 | 本地 `main` 落后 `codex/workspace-account` **50+ 个提交**，整个 `docs/product/capability-blueprint/`（5121 行）只存在于后者。从 `main` 切分支会丢失蓝图与全部已实现服务 —— **基线必须用 `codex/workspace-account`** |
| GitHub 网络不可达       | `git fetch upstream` 报 `LibreSSL SSL_ERROR_SYSCALL`，只能用本地已有 ref。任务书已写明「失败就跳过」                                                                                                                |
| 统计 465 时正则误命中   | 直接 grep `X.Y.Z.W` 会把正文交叉引用（「下游 = 2.2.1.2」）也算进去，数出 557。必须只匹配功能树行 `^[│ ]*[├└]── ` 且限定在代码块内                                                                                   |
| prettier 改写生成物     | 格式化 `module-progress.md` 会重排表格，导致与生成器输出漂移、`--check` 失败。已加进 `.prettierignore`                                                                                                              |
