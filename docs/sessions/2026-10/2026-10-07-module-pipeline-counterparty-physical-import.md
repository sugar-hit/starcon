### 关键决策 1：三条车道被开在落后集成头 9 个提交的旧分支上（已修正）

`lane.mjs plan --lanes 3` 输出后，实测三条 worktree 的 HEAD：

```
020f5b6  feat/3-6-1-1
020f5b6  feat/3-7-2-1
020f5b6  feat/3-8-1-1
```

而真实集成头是 `fa8dee8`。查证：

```
git merge-base --is-ancestor 020f5b6 fa8dee8   → YES（是祖先，只是落后）
git rev-list --count 020f5b6..fa8dee8         → 9
```

落后的 9 个提交里包含 **3.5.2.2 BOM 展开的契约重生成与前端工作区**
（`4a91329` / `c550132`）与三条调度器修复（`7ef6372` / `d8a25b1` / `c0a08b1` / `2e19663`）。

**根因**：`plan` 复用了上一轮 `abandon` 时留下的同名分支（`feat/3-6-1-1`、`feat/3-6-2-1`
等在分支列表里已存在且停在 `020f5b6`），检出已有分支而不是从当前集成头新开。
这类分支**不会**因为集成头前移而自动跟随 —— 它是一个静止的指针。

处置：先确认三条分支 `git rev-list --count fa8dee8..<branch>` 均为 0（**没有独有提交，
不丢任何东西**）、worktree 均干净，然后在每个 worktree 里 `git merge --ff-only integration/module-dev`
快进到 `fa8dee8`，再派发。快进后三条车道 HEAD 与集成头一致。

> 这与「任务书里的基线分支会过期」是同一类问题的另一面：不是模板写错，而是
> **编排器复用了陈旧分支指针**。`lane.mjs plan` 缺一条「分支已存在且不是集成头后代时，
> 强制从集成头重建或快进」的规则。本轮只做了手工快进，未改 `lane.mjs`；
> 下一轮应把这条规则固化进 `plan`，否则每个整点都会复发。

### 关键决策 3：任务书里点名三个「不许偷懒」的具体陷阱

  但**不得引用 3.6.1.2**（未开发），台账 3.6.1.2 那行不许改。
- **3.7.2.1**：3.7.1.1 / 3.7.1.2 均未开发，禁止引用其表与端点；
  上游只需 grep 确认 SKU 表真实列名即可。
- **3.8.1.1**：蓝图标题写「四步引导」但正文列了五个环节

  Excel 解析若仓库无依赖必须**明说**而不是静默省略；
  「同一租户同类导入任务互斥」要求 DB 层约束 + 专项断言，不许只在前端禁用按钮。
