## 本车道补了什么

### 1. 修掉上一位留下的一处真实缺陷：`exactOptionalPropertyTypes` 违规

`ListingFilters.outOfStock?: boolean` 与 `emptyFilters` 里的 `outOfStock: undefined` 在本仓
（`exactOptionalPropertyTypes: true`）**编译不过**：

```
src/components/listings/listing-model.ts(192,14): error TS2375: Type '{ ... outOfStock: undefined; ... }'
  is not assignable to type 'ListingFilters' with 'exactOptionalPropertyTypes: true'.
src/components/listings/listing-model.test.ts(150,26): error TS2379
```

→ 改成 `outOfStock?: boolean | undefined`。**不是**去掉 `undefined`（那会毁掉三态：
不筛 / 有货 / 缺货），也不是把 `emptyFilters` 里的键删掉（那会让「清空筛选」回到有货）。
三态语义必须能区分，`undefined` 是其中一态，类型就得显式收下它。

### 2. 真实工作区替换占位页

`app/listings/page.tsx` 由 `DomainPlaceholder` 换成 `components/listings/listing-workspace.tsx`
（筛选面板 + 汇总 + 批量 + 表格 + 分页 + 批量历史）。四条纪律在 UI 上的落点：

- **价格位不画假数据**：渲染 `priceCell()` 给的「价格能力未接入（归 05 定价）」徽章，不画 0、不画 `--`。
- **映射与缺货是两个控件两列**：筛选面板里各自一个 `Select`，表头刻意分开，徽章文案不互相靠近。
- **汇总用服务端 `total`**：不用 `items.length`（后者会把「当前页 50 条」说成「共 50 条」）。
  本页统计（未映射数、缺货数）文案里标明「**本页**」—— 拿 50 条的一页去说「全店 80% 未映射」
  是本模块最典型的假事实。
- **改价/改库存按钮禁用并说明归属**，不是点了给一个「成功但什么都没做」的提示。

## 关键 trade-off

### 1. 价格 / 销量 / 内部可售量三段一律不建列，按「能力未接入」如实表达

卷 05 定价整卷 0/19 未交付，全库不存在 listing 售价事实表
（`supplier_quote_price_tier` 是 06 采购的报价、`b2b_price_book`/`b2b_price_tier` 是 trade 的 B2B 协议价，
**都不是** listing 售价）。

→ 建一个 `price numeric(19,4)` 影子列 = 制造第二个价格事实来源，05 上线后两个数字迟早对不上，
而没人说得清该信哪个。这比「没有价格」危险得多。
→ 列表行**没有 price 字段**（有字段就得填值），`capabilities` 返回 `priceAvailable=false` + 归属 + 影响。

### 2. 缺货标记**能**成立，但它是平台侧事实

平台回报的可售状态（`platform_stock_state`）是 04 自己拥有的事实，与 07 的内部可售量是**两个事实**
（蓝图 4.1.1.3「平台下架与内部下架是两个事实」是同一纪律）。所以两个维度在 capabilities 里
**分开声明**：平台侧缺货 `available=true`，07 内部可售量 `available=false`，两者不得互相推导。

### 3. 聚合口径在两处必须逐字一致

`mappingStatus` 的 UNMAPPED/PARTIAL/MAPPED 判定在 `list()` 的 SQL 筛选与 `row()` 的行组装里
各写了一遍。**这是刻意的重复**：各算各的会出现「行上写着 PARTIAL、按 PARTIAL 却筛不出来」，
而那条不一致在界面上完全看不出来。注释在两处互相点名。

### 4. 状态变更事件交给 DB 触发器，不交给服务层

`AFTER UPDATE OF status` 就地落一条 `listing_status_event`。服务层可以改状态，但**改不出
「状态变了而历史里查不到」** —— 漏记历史比多记历史更难发现（4.1.1.3 在这张表上补状态机即可，无需二次建表）。

## 踩到的坑

**api-proxy 正则里斜杠写在了错误的层级。** 首版写成：

```js
/^listings(?:\/(?:batch\-tasks|batch|capabilities|filter\-options)|[0-9a-f]{8}(?:-[0-9a-f]{4}){3}-[0-9a-f]{12})?$/
```

斜杠只属于**第一个** alternation 分支，uuid 段前面没有分隔符。症状极具误导性：
`listings/capabilities`、`listings/batch`、`listings/batch-tasks` 全部正常放行，
**只有** `listings/{id}` 静默 404 —— 「列表能看、批量能跑、点进详情就 404」。
改成共用层级 `(?:\/(?:batch|…|[0-9a-f]{8}…))` 才对。已在注释里把这条写死。
