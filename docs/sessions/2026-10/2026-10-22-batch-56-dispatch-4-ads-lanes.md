每条规则是一段超长单行正则。历史上反复出现的失败模式是：
**两条车道都往同一条 alternation 里并分支 ⇒ git 判冲突 ⇒ 车道标 `conflict` → 重派重做**
（6.3.2.1 工单管理就是这么冲突过的）。

### 🔴 决策 4：比率一律**加权**，不是平均；null 与 0 含义相反

`ad_campaign_daily_metric` 的 `ctr` / `acos` / `roas` 是**生成列**，
任务书统一要求：聚合时**分子分母各自求和后再算**（Σspend/Σsales），
**不要对生成列求平均**（平均 ACOS 是错的口径）。
分母为 0 时返回 **null（不可比）**而不是 0 —— 照抄 14.1.1.1 的 `AdRatio` 约定，
**null = 不可比，0 = 可比但真的是零，含义相反**。
金额/比率全部 `BigDecimal` + `NUMERIC`，**禁 float/double**，前端只原样展示不做算术。

### 🔴 决策 5：14.1.1.2 的「平台侧修改历史」显式标不可用

已交付上游里 `ad_campaign_operation_log` 是**本地操作审计**，不是平台侧改历史，
平台侧改历史需要平台广告 API 同步（未交付）⇒ 走能力声明口径标 `available=false`，
并在界面说明「当前只展示本地操作审计」。**不许拿本地审计冒充平台侧历史。**
