## 决策 / 结论

1. **落地服务 = identity，端点前缀 `/identity/alert-rules`**。理由：卷 01 §1.3「消息与预警」
   整域都在 identity（1.3.1.1 通知列表、1.3.1.2 通知偏好都在这里）。预警规则存的是
   **租户级共享的运营配置**，不是任何业务服务的事实 —— warehouse / trade / channel / finance
   都不拥有「本租户想按什么线预警」这个概念。

2. **🔴 命中历史 = 空集合 + 未接通声明，不伪造命中记录**。18.3.1.1 规则列表 / 18.3.1.2 规则编辑器
   都还是「未开发」，没有求值就没有命中。响应里带 `engineAvailable=false` +
   `engineOwnerModule` + `engineNote`，页面显示「规则引擎未接通 · 归 18 系统负责」而不是
   「0 次命中」—— 这两件事完全不同，混成一句话运营就会去找错方向。

3. **预置规则集写在代码里（`AlertRuleCatalog`），租户覆盖落库，生效值 = 预置默认值 ⨯ 租户覆盖**。
   预置规则没被改过时**库里根本没有行**（`customized=false` / `enabled=true`），
   「改参数」用**由规则码派生的确定性合成 id**（uuid v3 形状，跨进程恒定）定位。

4. **预置规则不允许删除（服务端 409），只能关闭或恢复默认**。删掉等于让「这条规则存在过」
   变成说不清的事；要让它别生效请用「关闭」。

5. **写权限额外要求授权范围是 `ALL`**。规则是租户级共享配置，一个「只对本部门生效」的授权
   不该能改全租户的告警线。

6. **阈值全程十进制文本**：前端字符串 → 契约字符串 → 服务端 `BigDecimal` → 库里 `NUMERIC(19,6)`。
   前端一个字符都不转（`0.1 + 0.2` 那类误差一旦漂进告警线，阈值就偏了）。
   DB 层 `CHECK threshold >= 0`：负阈值会让「低于阈值」恒真，规则一建就疯狂误报。

7. **时间窗的边界按规则自己的时区（IANA 区域 id）算，不写死 UTC**。预置默认 `Asia/Shanghai` ——
   「今天」按 UTC 算会和跨境运营看到的自然日差一天。

8. **api-proxy 新增一条独立 `services[]` 元素**，不往既有 identity 分支的超长单行正则里并分支
   （多车道同时并进去 git 必然判冲突，结构性、retry 不会自愈）。插入锚点固定在
   `prefix: 'identity/'` 那条**之后**。id 段用**完整 UUID 形状**
   `[0-9a-f]{8}(?:-[0-9a-f]{4}){3}-[0-9a-f]{12}`（不是 `[0-9a-f-]+` —— 后者会把
   `disable`/`enable`/`reset` 当成 id 吃掉，`/{uuid}/disable` 就永远匹配不上）；
   字面量子路径 `capabilities`/`hits` 排在 `{uuid}` 段**之前**判别。

9. **只做 1.3.2.1 这一格**：兄弟模块 1.3.2.2 外部渠道推送（凭据不落库、只看 secret manager 引用）
   **不实现**，也没有去建 `/notifications/rules` 的总页面「顺便」实现它；
   1.3.1.1 的 `/notifications/page.tsx` 与 1.3.1.2 的 `/notifications/preferences/` **未改动**。

10. **两个集成测试类各自起自己的 Testcontainers 容器并在 `@AfterAll` 里 `.stop()`**，
    不进 `IdentityIntegrationTestBase` 那个 43 个类共享的 static 容器历史包袱。

## 关键 trade-off / 讨论

- **🔴 阈值短语的后缀不能用服务端下发的 `unitLabel`**。`unitLabel` 是**标签**（天数 / 金额 /
  百分比），直接拼在数字后面会读成「低于 14 **天数**」「低于 20 **百分比**」—— 不通顺，
  而且**看上去像阈值单位被写错了**。前端按**单位码**取量词形态的后缀（`天` / `%`），
  金额与数量在契约里**没有具体量纲**（币种归 12 财务、计量单位归 07 库存），
  就如实写成「（金额）」「（数量）」，**不编一个单位出来**。

- **有比较基准时阈值比的是「与基期的差距」**，不是绝对值：「销售额环比低于基期 20%」=
  比上一个等长周期低了 20% 以上，也正是蓝图那句「某店铺销售额环比跌超 X%」的意思。
  短语里点明「基期」，否则「低于 20%」会被读成「低于 20% 这个数」。

- **草稿校验把「没选」与「不在受控词表里」分成两句话**（`请选择时间窗` vs
  `时间窗不在受控词表里`）。两者混成一句时，用户明明没选，却被告诫「你选的值不在词表里」，
  会去怀疑词表而不是自己的操作。

- **白名单断言走「反向抽取源码里的真实调用点」**，而不是写死一份清单：写死只验证
  「清单与白名单一致」，真正会出事的是「源码加了新形状、白名单忘了登记」。
  模板字面量里的 id 占位符必须替换成**真 UUID 形状** —— 用 `'id'` 之类会得到一个
  **本来就不该放行**的路径，断言会误判成「白名单坏了」。

- **共享白名单的并发纪律**：只增不改、只增不删、不重排既有元素。本车道与 1.1.2.1
  （reporting）两条车道都改 `api-proxy.ts`，但插入锚点相隔很远（`identity/` 之后 vs
  `reporting/` 那三条之后），并入时 git 干净求并。
