## 闸工具的假阻塞（重要，影响每一轮判断）

`node tools/module-progress/ci-gate.mjs --pr 50` 报「阻塞 —— 出现了 main 基线里没有的失败」，
列出新增失败作业 `Lint` / `Security Scan` / `Catalog Browser & Contract Tests`。

**这是错的。** 原因：该工具的 `baselineRun()` 用 `gh run list --branch main` 取「最近一次跑完的 run」，
判定条件是 `r.conclusion !== null`；而 GitHub 对**运行中**的 run 返回 `conclusion: ""`（空串，不是 null），
于是**正在运行的 run 被当成了基线**。本轮基线 run `#39835974291` 当时 `status: in_progress`，
`Lint` / `Security Scan` / `Catalog Browser` 三个作业都还没出结论 ⇒ 被读成「基线没失败」。

改用**最新已完成的 main run**（`#39813059444`，push `5b642caf`）重算：

| 作业                               | main 基线 | PR #50 |
| ---------------------------------- | --------- | ------ |
| `Lint`                             | ✗         | ✗      |
| `Security Scan`                    | ✗         | ✗      |
| `Java 21 & PostgreSQL Integration` | ✗         | ✗      |
| `Catalog Browser & Contract Tests` | ✗         | ✗      |

失败作业集合完全一致 ⇒ **没有新增失败，判据是「持平放行」**。

⇒ 教训：**闸工具的结论必须先确认基线 run 已跑完**（`conclusion` 非空且 `status` 为 completed），
否则会把「基线还在跑」误读成「新增失败」。这一轮没有改闸工具本体（超出本任务范围，且会污染同步 PR 的内容）。
