# 14.1.3.2 投放定位（阶段 D7，L3 锚点 14.1.3 广告组与投放结构）

- **日期**：2026-10-22
- **车道**：`feat/14-1-3-2`（worktree `integration/.worktrees/14.1.3.2`，基线 `integration/module-dev` = `c4f28a45`）
- **蓝图原文**（`docs/product/capability-blueprint/14-ads-and-growth.md`）：
  > ### 14.1.3.2 投放定位
  > - 职责：管理投放定位（地域、人群、设备、时段、匹配类型），支持按定位维度看效果，指导出价调整。
  > - 输入：定位设置；定位维度效果数据。
  > - 输出：定位效果对比表 + 调整建议。
  > - 关系：上游 = 14.1.2.1；下游 = 14.2.1.2 分时策略。**定位效果差异大时应收窄投放，无效定位的花费是最容易省下来的钱。**

## 决策摘要

### 1. 🔴 解读归一落**自己的表**，不改写上游 V281 的列语义

上游 V281 的 `ad_campaign_group.targeting_settings` 是**平台原文串（不拆解、不归一）**，
它的注释写明「**解读归 14.1.3.2**」⇒ 解读/归一化正是本模块的职责。
但**不改上游那一列**（改了就跨车道的隐性回归面），而是：

- 归一结果落**新表** `ad_targeting_setting`（V285）；
- 同时**保留原文**（`platform_raw_key` / `platform_raw_value`）以便回溯 ——
  归一是为了能聚合，不是为了把原文抹掉；
- 上游原文**一字不改**地继续留在 `ad_campaign_group` 里。

⇒ 事实有两份、职责不重叠：上游那一份是「平台怎么说的」，本模块那一份是「我们怎么归一的」。

### 2. 🔴 归一不出来 ⇒ **UNMAPPED（显式合法值）**，不猜、不丢弃

照抄 2.1.2.1「映射缺失必须显式报未映射，不能默认落到某个兜底状态」与 V274 的 `internal_ad_type` 口径：
平台原文里认不出来的键落 `dimension='UNMAPPED'`，**原文键保留**，界面上显式摆出来让人处理。
时段取值（DAYPART）解析不出小时窗口时，窗口三列**留白**（不编一个窗口出来），
DB 层用 CHECK 钉死「窗口三列要么全空要么全有」。

平台原文的键值串解析规则写死在服务层（`parseTargeting`）：按 `;` / 换行 / `|` 分段，
按**第一个** `=` 拆键与取值；键名小写去空白后查映射表；取值归一 = 去空白 + 空白折叠 + 大写。
时段窗口支持 `09:00-17:00` / `9am-5pm` / `9-17` / 单个小时 / 平台命名时段（ALLDAY / MORNING /
AFTERNOON / EVENING / NIGHT），跨零点窗口（22:00-02:00）自动识别。
🔴 手动新建 DAYPART 定位时，**解析不出窗口直接拒（400）**并指向解读入口 ——
落一条「没有窗口的时段定位」会让下游分时策略拿到空窗口。

### 3. 🔴 效果指标**只有一处来源**，且**跨币种不相加**

- 对比表与建议的指标**全部**来自 `ad_targeting_metric`（V285），**不拿别的口径冒充**；
- 派生比率（CTR / CPC / CVR / ACOS / ROAS）**分母为 0 时给 null（不可比）**，不是 0
  （照抄 V274 同一款纪律：销售额为 0 时 ACOS 是算不出来，不是零）；
- 对比表**按币种分行**，汇总的金额**按币种分列**（`spendByCurrency` / `salesByCurrency`），
  只有计数（展示 / 点击 / 转化，与币种无关）才相加；
- 一条定位设置的指标**只能是同一个币种**（跨币种的 ACOS 是假的）⇒ 跨币种那条**逐条被拒**。

指标行**冗余**了 `campaign_id` / `group_id` / `dimension` / `dimension_value`：
对比表要按维度聚合，每次都 join 设置表在指标量大时很贵。冗余列**由服务层按设置填**，
调用方**不能自报**（否则一条指标能挂到别的维度上）。

### 4. 🔴 调整建议必须带**依据数值**，否则就是硬编码文案

五条规则**全部现算**，每条建议都带：

- `evidence`：逐条列出的**真实数字**（花费、点击、转化、占同维度花费比重、目标 ACOS …）；
- `basis`：规则 + **用了哪些阈值**；
- `actionable`：**样本不足（花费 / 展示 / 点击未达门槛）时为 false** ——
  宁可少给一条，也不给一条基于噪音的建议；
- `bidFactor`：**出价系数**（比例 NUMERIC(19,6)），= 目标 ACOS ÷ 当前 ACOS，下限 0.1、上限 1.5。

规则：`WASTED_TARGETING`（花了钱零转化 ⇒ 收窄）、`ACOS_OVER_TARGET` / `UNDERPERFORMING`（⇒ 降价）、
`SCALE_UP`（⇒ 加价放量）、`DIMENSION_SPREAD`（**同维度内最差 ACOS ≥ 最佳 × 2 ⇒ 建议收窄到表现好的取值**，
即蓝图的加粗句）。阈值与系数上下限**公开在 `GET /options`** —— 建议引擎的阈值不公开，界面就变成黑箱。

### 5. 🔴 收窄投放是**会打断投放**的动作 ⇒ 有证据门槛

`POST /{uuid}/narrow` 要求该定位**已花了钱且零转化零销售**（花费 ≥ 门槛）才放行，
否则 **409** 并写明当前花费 / 转化 / 销售额与门槛。
人工确实要收窄时必须显式 `override=true` + 理由，**留痕里会记下这是人工决定**。
收窄只落本地并标「待回写平台」（平台回写队列未交付）。

### 6. 🔴 本模块**不执行**出价调整

改竞价是钱，走上游 14.1.1.2 的改竞价入口（带单次上限与绝对上限、逐条留审计）。
本模块只给**出价系数建议**与**系数记录**（定位设置上的 `bid_factor`）⇒ 两个端点改同一笔钱，
审计就会分叉。能力声明里 `bid_adjustment_execution` 显式 `available=false` + ownerModule=14.2.1.1。

### 7. 🔴 供下游 14.2.1.2 分时策略的数据**由本模块交出去**

下游 14.2.1.2 未交付 ⇒ 本模块**自己把「定位效果对比」做完**，并把可复用的数据暴露成
`GET /daypart-profile`（时段窗口 + 区间聚合）。
🔴 指标按**时段窗口**归集，**不是按小时**（平台回报的定位效果就是按窗口给的，硬拆成小时等于编数据）——
页面与下游都写明粒度。

## 关键 trade-off

| 选择 | 放弃了什么 | 为什么 |
| --- | --- | --- |
| 另建归一表，不改 V281 的列 | 「一份真相」的直觉 | 上游那列存的是**平台原文**，本表存的是**归一结果**，语义不同；改上游列会跨车道改别人的东西 |
| 计数用整数，**数量**用 NUMERIC(19,6) | 「所有数字统一 6 位小数」 | 计数是计数（V274 同一款纪律：不用 numeric(19,6) 冒充计数）；**时段小时数 / 出价系数**才是真数量（照抄 V228 crm 与 `db/schemas` 的「数量 → numeric(19,6)」） |
| `UNMAPPED` 显式落库 | 「只保留认识的维度」 | 认不出来的键**不丢弃**：平台给了个我们不认识的定位维度，人间蒸发比显式摆出来更糟 |
| 收窄要有证据门槛（可人工覆盖） | 「随时能暂停一条定位」 | 收窄会打断投放；没有门槛的「一键收窄」是事故制造机。人工覆盖留痕即可 |
| 台账**只改自己那一行**，不跑 `sync.mjs` | 总览计数差 1（且本来就差 3） | 集成头上 `14.1.2.1` 那行**少一根结尾竖线**（6 根），`sync.mjs` 解析失败会把它**回落成「未开发」并抹平证据**；跑 sync 会毁掉别的车道已交付的证据。自己的行写成 7 根竖线，`sync` 能正常继承（已用脚本的正则实测通过） |
