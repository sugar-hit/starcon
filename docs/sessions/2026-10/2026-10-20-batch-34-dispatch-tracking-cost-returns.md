## 三、本轮最重要的取证：四条车道全部撞上「上游真值不在本服务」

卷 10 的后端主责服务是 `channel + trade + warehouse`（取第一项 ⇒ channel），卷 05 是 `catalog`。
但蓝图里点名的上游数据**绝大多数在别的服务**。AGENTS.md 禁止跨服务 SQL / 跨库 FK / 共享视图，
所以这四条车道都必须走仓库既有的 **Port 模式**（`RestClient` + 转发调用方 `Authorization` bearer + 上游不可达显式报错）。

| 模块 | 蓝图点名的上游 | 真值实际在哪 |
| --- | --- | --- |
| 10.3.1.1 轨迹查询 | 承运商 API | channel 无承运商轨迹客户端；运单真值在 **trade**（`shipment_record` / `logistics_waybill_request` / `shipment_record_tracking_observation`），包裹在 **warehouse**（`parcel` / `parcel_item`）；承诺时效在 channel 同库 `logistics_transit_rule`（V139） |
| 10.6.1.1 成本分析 | 10.2 / 10.4 / 12 财务 | 尾程运费在 channel 同库 `freight_*`（V140）但订单级实际运费在 **trade** `logistics_waybill_freight`；头程在 **warehouse** `first_mile_shipment`；关税在 **warehouse** `duty_tax_*`；仓储费待查 |
| 10.7.1.1 退货处置 | 11.2 退货管理 / 8 仓储作业 | 退货实收、质检、入账**全部在 trade**（`return_receipt*` / `return_quality_*` / `return_inventory_posting`）；仓储在 **warehouse** |
| 5.2.1.1 成本构成 | 06 采购 / 12 财务 / 10 头程费用 | 报价在 catalog 同库 `supplier_quote` + `supplier_quote_price_tier`（V32）；头程在 **warehouse**；关税在 **warehouse** `duty_tax_*` |

已把仓库既有先例逐条写进子任务书（`PendingShipmentQueryPort` / `InventoryAvailabilityPort`），包含：
连接超时 3 秒读超时 5–10 秒**必须有上限**、**转发调用方 bearer 绝不自己传租户号**、
**绝不发明 `X-Tenant-Id` 头**、上游不可达报 503 且理由写「读不到」而不是「没有数据」、
**绝不返回空集合冒充「上游没有数据」**、catalog 侧还要有 `UnwiredXxxPort` 兜底（上游未配置时显式抛错而不是静默返回空）。

## 五、L2 本轮未跑 —— 理由（不是偷懒）

1. **无可验证内容**：`merge-ready` 返回空，本批 4 条车道**一条都没落地**，集成头相对 `969a9832` 零变更。
   L2 的定义是「对**并入之后**的集成头做全量验证」；没有并入就没有验证对象。
   集成头现有代码本身在 batch-33 已通过 L2 全绿，且**已经在 `origin/integration/module-dev` 上**。
2. **跑了反而会制造假红**：协议明确禁止「L2 与在途车道的 L1 并发跑」——
   多套 Testcontainers PG 互相抢资源，2026-10-19 20:00 那轮实测 PG 峰值 16，后端 1364 例里 3 failures + 24 errors
   **全是假红**（`seed()` 503 / 连接拒绝），机器空闲后隔离复跑全绿。
   本轮有 **4 条车道的 L1 正在跑**，此刻启动 L2 恰好命中这个已知故障形状。

⇒ L2 留到下一轮：4 条车道落地 → `merge-ready` → 静态预检（V212–V215）→ **L2 全量跑一次** → 绿了才写逐模块说明、才 push。
