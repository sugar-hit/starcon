### ⑤ 【本轮新发现】合并后的台账会**带一份陈旧汇总表**

`merge-union` 的台账求并只对**模块 ID 行**（`^\| \d+\.\d+\.\d+\.\d+ \|`）按键折叠；
而「总览 / 分阶段 / 分系统」这些汇总行不匹配该模式，**按整行文本去重** ——
两侧数值不同（359 vs 340）⇒ **两份都留下**：

```
合并后台账：
  第 13 行：| 已交付 | 359 |      ← 集成头侧
  第 543 行：| 已交付 | 340 |     ← main 侧的陈旧值（同一张表又来一遍）
  同类重复：| **D7** | ... |、| 01 | 工作台与门户系统 | ... | 各 2 份
```

**但模块行本身是对的**：合并后模块行仍是 465 行、无重复，逐行统计与 HEAD 完全一致：

|              | 已交付  | 进行中 | 未开发  |
| ------------ | ------- | ------ | ------- |
| HEAD         | 359     | 0      | 106     |
| 模拟合并结果 | **359** | **0**  | **106** |

且 `sync.mjs` 是**整份重建**台账的（`render()` 重新生成汇总/阶段/卷三张表 + 模块明细，再 `writeFileSync`），
汇总表由模块行现算 ⇒ 协议第 5 步跑一次 `sync.mjs` 就会把那张陈旧汇总表**覆盖掉**。

⇒ **结论：合并不会造成进度回退**（359 不变）。
⚠️ 但「合并完成」与「sync.mjs 跑完」之间存在一个**短暂窗口**，窗口内台账里有两份汇总表 ——
这正是第 53/54 轮说的「只有空行差异」没量到的部分。
