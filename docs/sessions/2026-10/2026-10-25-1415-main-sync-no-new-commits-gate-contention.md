## 决策 / 结论

1. **不抢闸、不清闸、不 force、不 release**：闸 `held` + `stale=false`（持闸者活着：keepalive 续期 + L2 在跑 +
   仍在提交）⇒ 按协议「等它释放」。本轮**从未 acquire 成功**，因此**没有 release** ——
   `gate release` 的实现是无条件 `rmSync(GATE_DIR)`，会把别人活着的闸删掉（= 清闸，破坏互斥）。
   闸最终状态：`held` / `ageSeconds≈545` / `stale=false` / `owner` 仍是 `12:25:29`（**不是本轮留下的**）。

2. **判定「无新提交」的方式**（未取闸 ⇒ 不 fetch）：协议第 2 步要求「取闸 → fetch → 判祖先」。
   本轮改用只读取证，结论等价且零副作用：

   | 取证 | 结果 |
   | --- | --- |
   | `git ls-remote origin main` | `6522c497` |
   | 本地 `origin/main` ref | `6522c497`（**与远端完全一致 ⇒ 本地 ref 新鲜，不是滞后值**） |
   | `git merge-base --is-ancestor 6522c497 integration/module-dev` | **成立 ⇒ NO_UPDATE** |
   | `git log integration/module-dev..origin/main \| wc -l` | **0** |
   | 更强一侧：远端集成头 tip `e0a7d966` 是否含 `6522c497` | **是** ⇒ 即便按最新集成头算，main 也无新内容 |

   ⇒ 结论**不依赖**「本地 ref 是否滞后」这一假设，也**不依赖**本轮能否取闸。

3. **不跑构建**：无并入内容 ⇒ 无需预检（`./mvnw -q compile` + `pnpm typecheck`）。
   且等闸期间跑构建会与持闸 tick 共用 `backend/**/target/` 与 PG 容器 ⇒ **必然假红**。

4. **不在脏工作区动手**：集成头 worktree 当时有持闸 tick 自己的未提交改动 ——

5. **不写协议文件**：上一轮已把「竞态写法改为单进程 5ms `mkdirSync`」列为「给人工裁决」，

## 关键 trade-off

- **等 55 分钟不抢闸**：持闸 tick 是活着的（keepalive 续期、L2 在跑、仍在提交）。
  抢闸 ⇒ 两个构建并发跑 `backend/**/target/` 与 PG 容器 ⇒ **成片假红**。
  「宁可等，不可抢」本轮再次成立；期间唯一代价是墙钟时间。
- **等闸期间只做只读取证**：未 fetch（协议明令「等闸期间连 `git fetch` 都先别跑」）、未 merge、
  未动工作区、未跑任何构建、未 push。
- **用 `ls-remote` 替代 `fetch` 做判定**：`ls-remote` 只读远端、不动本地 ref，
  等价回答「远端 main 现在是什么、集成头是否已包含它」，且在**没有闸**的前提下
  也不会给持闸 tick 制造 ref 竞态。
- **主动停掉竞态 racer**：确认 NO_UPDATE 后立刻终止竞态（避免持续抢 CPU 干扰持闸 tick 的 L2），
  并核查无残留进程。
