# 同步轮取证超闸 TTL ⇒ 闸被接管 + 基线漂移 ⇒ PRE 基线与冲突清单须当场落到 docs/

  `tools/module-progress/SYNC-MAIN.md`、`tools/module-progress/PIPELINE.md`（第 2 章 闸）

## 背景

第 52 轮同步的时间线（实测）：

```
13:23:14  取得闸（密集 acquire 竞态）
13:23–14:02  真合并 → 58 个文件冲突 → 四通道取证（耗时约 39 分钟）
14:02:56  外部 actor 执行 reset --hard ⇒ 合并冲突态被撤销、stage 2/3 夹具清零
14:33:14  闸 TTL 到期（13:23:14 + 4200s）⇒ 被流水线 tick 按 TTL 路径接管
14:38:32  流水线 L2 mvnw verify 启动
15:35:38  本轮第 2 段取闸（密集竞态第 2500 次迭代）
```

两个后果：

1. **闸 TTL（4200s = 70 分钟）盖不住「合并 + 58 文件取证」的耗时** ⇒ 同步轮会在自己还活着时
   被下一 tick 按 TTL 路径接管。**这不是异常路径，是现行 TTL 必然会发生的事**。
2. **基线漂移**：等闸期间流水线把集成头从 `aabae71e` 推进到 `cddb7f15`（5 个提交）。
   ⇒ 第 1 段的 `PRE` 基线作废，第 1 段的取证结论必须在新基线上**重做**（本轮重做了）。

现行协议（`SYNC-MAIN.md`）只在**会话上下文**里记「PRE 基线 + 冲突清单」，
一旦闸被接管 / 上下文被压缩 / 进程被杀，这两样东西就没了 ⇒ 下一轮只能从头重做 58 文件取证。
