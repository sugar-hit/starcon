# 3.6.2.1 报价并入后给导出加一个 QUOTE 数据源

- 创建: 2026-10-07
- Owner: TBD
- 优先级: **P2**
- 关联: 模块 `3.8.2.1`（已交付）、模块 `3.6.2.1`（由另一条车道开发、本轮未并入）

## 背景

蓝图 3.8.2.1 的上游写的是「3.1.1.1 / 3.1.2.1 / 3.6.2 等列表页」——一个**开集**。

本期交付时 3.6.2.1 报价列表尚未并入本分支，**本模块刻意没有 QUOTE 数据源**，
并且刻意没有写占位实现（不写 `TODO` + 抛异常、不返回空数据源假装有）。
理由与 V29 导入向导对「报价」的取舍同源：**价格的唯一写入所有者是定价服务**，
catalog 既不建报价表、也不把报价做成一份无主的副本。

## 为什么这不是「后续再补」的空话

扩展点是**已经造好的**，不是留给以后再设计：

- 数据源做成代码侧注册表（`ExportDataSource` 接口 + `ExportDataSources` 注册表），
  不是在迁移里枚举表名、也不是在服务层写一个 switch
- 加一个数据源 = 新增一个 `@Component` 实现，**迁移表结构、服务层、前端都不用改**
- 字段选择器、排序还原、条件回显、异步执行、下载有效期、PII 授权与审计
  全部由 `ExportJobService` 按注册表统一处理，新数据源自动获得这整套能力
- `export_job.source_key` 存的是注册表里的键（如 `SKU`）而不是表名

## 并入后要做的事

新增一个 `SqlExportDataSource` 子类（例如 `QuoteExportDataSource`），
声明自己的 `columns()` / `sorts()` / `filters()` / `from()` / `conditions()` /
`orderBy()`，标 `@Component` 即可。**不需要迁移、不需要改 `ExportJobService`、
不需要改前端**（前端的能力声明由 `/catalog/export-sources` 下发，会自动多出一个数据源）。

需要一并确认的两件事：

1. **价格字段的 PII 属性**：报价本身不是 PII，但若报价行带供应商对接人联系方式，
   那些列要标 `pii=true`，复用本模块已有的显式授权 + 留痕链路
2. **金额与数量用 `NUMERIC` + `BigDecimal`**（AGENTS.md 禁浮点），且报价的写入所有者
   仍是定价服务 —— 导出只是读，不构成第二个写入来源

## 不做的事

不改 `export_job` 表结构、不加新的 Flyway 版本号、不动 `import_job` 的互斥索引
（导出是只读作业，本来就不需要「同一租户只允许一个同类任务」那条约束）。
