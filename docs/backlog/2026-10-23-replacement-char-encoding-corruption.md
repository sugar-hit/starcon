## 影响面

1. **绝大多数是注释 / javadoc / SQL `--` 注释 / 测试断言的失败消息** ⇒ 不影响运行时语义。
2. **少数落在运行时字符串**上 ⇒ 会真的出现在 API 响应里。
   已确认的一例：`backend/services/channel/src/main/java/com/starcon/channel/PlatformViolationService.java`
   的 `UPSTREAM_NOTE`（batch-67 交付的 16.1.2.1），会把乱码返回给前端。
3. **已应用的 Flyway 迁移**里也有 ⇒ **不要直接改已应用迁移**（Flyway checksum 会炸），
   要么原样保留，要么用新的迁移修正数据/注释。

## 成因假设（未取证，仅供后续排查）

中文全角字符（`「」『』—…→` 等）在**某次工具写入时被截断**：
被截断的字节序列在严格 UTF-8 解码下不合法，写入时被替换成了 `U+FFFD`。
从样本看，**每处损坏正好吃掉 1 个汉字或 1 个标点的 2–3 个字节** ⇒ 与「按字节截断」一致，
而不是「编码转换错表」（后者会产出成片的 `æ–‡` 之类，而不是单个 `U+FFFD`）。

⇒ **先验证**：找出历史上批量写文件的工具/agent 写入口，检查是否有按字节截断的路径。
