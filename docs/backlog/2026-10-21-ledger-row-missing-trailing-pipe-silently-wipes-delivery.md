# 台账行缺尾随 `|` ⇒ 交付记录被 `sync.mjs` 静默抹除

发现：2026-10-21 08:19（batch-47 合并期间）。发现人：批次调度者。
影响范围：**模块 16.2.2.2 认证与资质**的「已交付」状态与 **5454 字符**的证据列。

## 现象

16.2.2.2 车道交付后，其台账行**少了行尾的 `|`**：

```
| 16.2.2.2 | 认证与资质 | — | D7 | 已交付 | 迁移 channel `V247__product_certification.sql`（……）
                                                                                                   ↑ 缺这一根
```

行尾无 `|` ⇒ 按 `|` 切分只得 **7 段**（正常行是 8 段）。

## 为什么会毁数据

`tools/module-progress/sync.mjs` 用带行尾锚点的正则解析台账行，匹配不上的行
**不会被继承**，而是按蓝图重建为默认值：

```js
// sync.mjs
status: prev?.status ?? STATUS.TODO,      // 继承不到 ⇒ 回落「未开发」
evidence: r.evidence || '—'                 // 继承不到 ⇒ 证据抹成「—」
```

⇒ **每一次 `sync.mjs` 都会把 16.2.2.2 的「已交付」翻回「未开发」，并抹掉 5454 字符证据。**
而 `sync.mjs` 是**每轮必跑**的（合并后刷新台账、`--check` 校验、三件套 commit 前各一次），
所以这个损坏是**必然发生**的，不是偶发。

本次的实际发现路径：调度者在 batch-47 合并后跑了一次 `sync.mjs`，
台账立刻从 **270 已交付** 掉到 **269 已交付**，16.2.2.2 变回 `未开发` 且证据变 `—`。

## 放大器：merge-union 驱动器不校验行结构

`tools/module-progress/merge-union.mjs` 对台账做「按模块 ID 求并」，
它**按行首模块 ID 归并，但沿用了行文本**，
所以一个**结构已坏**的行被原样保留进集成头，并继续往下游传播。

⇒ 缺陷在「车道写坏行」→「union 驱动器原样放行」→「sync 无条件重写」三处串联下才致命。
单看任一处都不致命。

## 修复

- **立即**：给 16.2.2.2 行补回行尾 `|`；补后连续两次 `sync.mjs` 均稳定保留
  「已交付」+ 5454 字符证据；全表 465 行结构审计 0 畸形。
- **本次未改脚本**（并发 agent 正持调度闸并准备 commit，改 `sync.mjs` 会与它的 L2/提交交叉）。
