## 为什么要这张清单

`merge-union` 驱动会**改写契约文件**，改写方式有两个缺陷（2026-10-22 第 27/28 轮取证）：

| 缺陷 | 位置（`tools/module-progress/merge-union.mjs`） | 现象 |
| --- | --- | --- |
| ① 横幅被挪到**末行** | 第 176 行：`writeFileSync(oursPath, \`${merged.map(([, v]) => v).join('\n')}\n${o.head.join('\n')}\`)` —— `o.head`（含 `// Generated by ... DO NOT EDIT.`）被追加在**最后** | `crm.ts` 横幅不在第 1 行 |
| ② **不做任何排序** | `.ts` 分支用 `merged.map(...)` 的 **Map 插入序**写出；`.json` 分支第 215 行 `JSON.stringify(a, null, 2)`，且 `Object.fromEntries(merged.map(...))` 保留插入序 | 类型序、json 键序都是「继承输入」的，不是字典序 |

全文件 `grep -nE 'sort|sort_keys|localeCompare'` ⇒ **零命中**。

⚠️ **根因在 `origin/main` 上原样存在**（第 176 行逐字节相同）⇒ 缺陷先于任何一方，
**不会被记成同步任务的回归**。

⚠️ **驱动注册在仓库本地 `.git/config`**（`merge.contract-union.driver = node tools/module-progress/merge-union.mjs %O %A %B`），
worktree 共享 ⇒ **module-dev→main 方向也走同一个驱动** ⇒
**排序约束：先合入驱动修复，再做 module-dev→main 的 PR。**

## 本清单要区分的两种「契约文件变化」

| 类别 | 含义 | 判定 | 标注写法 |
| --- | --- | --- | --- |
| **① 驱动改写产生的漂移** | 合并时驱动重写契约文件导致的字节漂移 | **修复后不应再发生** | 回归 ⇒ 要查 |
| **② 修复本身引入的**一次性排版变更** | `.ts` 类型序 + json 键序变为字典序 | **预期**，一次性 | 非回归 ⇒ 标注「预期的一次性排版变更（类别②）」 |

⇒ **下一轮汇报必须写明属于哪一类**，否则会被当成回归再查一遍。

## 下轮同步必须逐项校验的判据

### 判据 A —— 乱序输入必须产出与打乱前**逐字节相同**的生成物

```bash
# 生成器加 sort_keys（或至少 paths + components.schemas 两层排序）后：
# 打乱已提交 json 的 paths 键序 → 喂 --spec-dir → 生成物必须与打乱前逐字节相同
```

⇒ 证明「键序不是生成器决定的」这个前提已被修掉。

### 判据 B —— `.ts` 与 `.json` 一起为空

```bash
git diff --exit-code -- packages/api-contracts/src
```

⚠️ **只修 `.ts` 不够** —— 即使 6 个 `.ts` 修到逐字节相同，
3 份 json 的键序仍会让这条非空 ⇒ catalog-e2e 依旧红。
⇒ **`.ts` 与 `.json` 必须一起为空。**

### 判据 C —— 逐字节三项不变量（下轮同步逐个断言）

| # | 不变量 | 检查方式 | 期望 |
| --- | --- | --- | --- |
| C1 | **横幅归首行** | `head -1 packages/api-contracts/src/contracts/*.ts` | 每个文件首行 = `// Generated by tools/codegen/catalog-contracts.py from Spring OpenAPI. DO NOT EDIT.` |
| C2 | **类型按名排序** | 抽出 `export type/interface/const <Name>` 的 Name 列表与 `sort` 后逐字节比 | 完全相等 |
| C3 | **json 键序字典序** | `Object.keys(paths)` 与 `[...keys].sort()` 比；`components.schemas` 同理 | 完全相等 |

### 判据 D —— 合并后的驱动求并**幂等**

对同一对输入连续求并两次，两次产物必须逐字节相同（禁止「第一次排序、第二次又换序」）。
